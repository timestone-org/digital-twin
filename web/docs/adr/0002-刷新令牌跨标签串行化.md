# ADR-0002：刷新令牌在标签内合并，并用 Web Locks 在标签间串行化

- 状态：已采纳
- 日期：2026-08-10
- 来源：从 Claude 项目 memory `web-cross-tab-session-sync` 迁入；当前实现与 `web/CONTEXT.md` §4 已核对

## 背景

刷新令牌是一次性的：服务端成功轮换后会立即吊销旧令牌。同一浏览器的多个请求或多个标签页若同时用同一枚令牌刷新，只会有一个成功；其余请求会被当作重放，若直接清空登录态，会把合法用户静默登出。

## 决策

同一标签页内用一个共享的 `inFlightRefresh` 合并并发刷新；不同标签页之间用 Web Locks 对刷新临界区排他。进入锁后必须重新读取持久化令牌，避免继续使用等待锁期间已被其它标签换掉的旧值。

刷新请求失败后也重新读取一次持久化状态：若其它标签已写回新令牌，当前标签采用它；只有在没有可用新状态时才执行登出。登录、轮换与登出通过 `storage` 事件通知其它标签，但接收方重新读取当前存储，不把事件载荷当作权威快照。

## 理由与取舍

标签内合并解决单个 JavaScript 上下文的并发，Web Locks 解决同源标签之间的并发；少任一层都仍会产生合法刷新互相吊销。代价是认证恢复依赖浏览器的 Web Locks 能力，并需要在测试中覆盖等待锁后重读、失败后接管新令牌与跨标签登出三条路径。
