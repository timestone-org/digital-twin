# 能管指标时序预测专项方案

状态：待评审、未实现。日期：2026-10-30。

本文把“真实点位历史段 → 未来一段预测 → 指标曲线展示”作为独立交付项，提出可评审的范围、数据契约和验收方法。文中的候选字段、资源与算法不是已发布接口，不可直接调用。现有可调用契约见 [第三方接入说明](MODELING_THIRD_PARTY_API.md)；本方案不表示已训练模型、已测得预测精度或已更新客户环境。

## 1. 当前能力与缺口

当前平台已具备模板、独立实例配置、训练运行、固定模型版本、部署服务和按行 `:predict`。模型服务只对调用方提供的每行特征推理，响应 `predictions` 与输入顺序对应。它没有自动读取任意点位历史、构造未来多步输入或返回未来时间轴的承诺。

“能管取数” `bdm_source` 已按真实点位、属性、公式标识从外部能管读取有界历史；台账取数 `ledger_source` 已读取平台自己的台账。两者不应混成一个猜编码的入口。历史时间平移、重采样、时间对齐和周期特征可用于训练；其中历史平移不在现有线上推理链执行，调用方仍须提供对应历史值。

当前签名没有预测步数、步长、历史来源映射或统计区间契约，普通预测返回也没有未来时间戳及上下界。增加训练/版本管理页面不能补上这些能力。按配置百分比围绕预测值绘制的带状区域只能称“阈值带”或“配置范围”，不能标为模型统计置信区间。

## 2. 首批交付范围

建议首批限定为一个已确认指标、固定采样周期、单一预测目标和一个固定模型版本；输入可含多个经过确认的真实特征。先完成数据核对与离线回测，再提供有界的多步预测结果，最后接指标中心展示。多目标联合预测、跨设备统一模型、全自动在线学习和自动优化控制另行评审。

首批应支持：

1. 根据真实来源 ID 与明确字段映射取得历史，校验单位、采样周期、时间范围及缺数。
2. 明确预测起点、步长、步数、业务时区以及每个未来时刻。
3. 记录本次解析出的固定模型版本、特征绑定版本、历史截止时刻及数据质量摘要。
4. 返回逐时预测值和缺失/不可用状态，不以 0、常数或复制值填充缺失特征。
5. 有通过回测的区间方法时返回真实预测区间；尚未验证时不返回上下界，页面明确仅有点预测。

不承诺任意点位或任意现有回归部署都能直接用于时序预测。每个可用模型必须具有明确的预测目标、采样口径、特征构造与服务契约；能耗、瞬时功率、温度以及累计表底不能默认共用处理方式。

## 3. 开发前需要确认的业务与数据

| 待定内容 | 所需真实信息 | 对设计的影响 |
|---|---|---|
| 预测目标 | 指标 ID、物理含义、单位、数值类型、是否累计量 | 决定目标构造、差分/聚合和展示单位 |
| 历史来源 | 点位 pointId、属性 propertyId、公式 code 或平台台账及列 key | 决定授权读取路径，不能按名称匹配 |
| 时间口径 | 采样周期、记录时刻的区间含义、来源时区、业务时区 | 决定分桶、日/周周期及 UTC 转换 |
| 业务窗口 | 预测未来多久、刷新频率、容许延迟、最长历史回看范围 | 决定步数、计算预算与同步/异步边界 |
| 缺数与迟到 | 缺失比例、最长连续空窗、到达延迟、补采和修正方式 | 决定样本有效性与预检拒绝条件 |
| 外生特征 | 负荷、天气、班次、生产计划等来源和未来可得性 | 决定能否在每个预测时刻构造完整输入 |
| 精度验收 | 业务可接受误差、对照基线、关注时段和异常工况 | 决定上线门槛，不能事后按结果挑指标 |
| 区间展示 | 是否必须有统计预测区间、目标覆盖水平、允许宽度 | 决定区间方法与独立校准样本需求 |
| 权限与审计 | 谁可配置绑定、发起预测、查看输入摘要与下载结果 | 决定权限与敏感数据暴露边界 |

这些内容必须由现场目录、样本、真实数据规则与业务确认支持。配置保存不会自动上传数据；目录宣称有历史也不证明目标窗口完整。首次接入应生成有界的数据核对记录，列出真实覆盖区间、有效样本数、缺失和冲突，不以人造样本验收实际模型效果。

## 4. 数据绑定与特征契约

建议为时序服务建立显式、可修订的特征绑定配置，固定以下内容；最终资源名和字段待接口评审确定。

| 内容 | 需要记录的含义 |
|---|---|
| 服务与版本 | 部署 code、可接受的任务/输入契约、配置时核对的固定模型版本 |
| 目标来源 | 真实来源类别、来源 ID、字段 key、单位及目标采样周期 |
| 特征映射 | 每个模型入口 key 对应的真实来源与字段，不依赖展示名称 |
| 历史特征 | 滞后时长、窗口、聚合/差分方法、所需最早历史时刻 |
| 未来特征 | 来自已授权未来计划/预报的字段，或模型内可生成的时间特征 |
| 时间规则 | UTC 输出、显式业务时区、左闭右开窗口、桶时间标签与对齐规则 |
| 缺失规则 | 允许范围、拒绝条件；若批准插补，固定方法、最大连续长度和质量标记 |
| 单位变换 | 经业务确认的转换与公式版本，不根据单位字符串猜换算 |
| 配置修订 | expected revision、变更审计与签名兼容校验 |

禁止以同一个历史值填充所有多特征输入，或将未来未知负荷、天气填成任意常数。累计计量值出现回零、换表或负差时，须按确认规则处理，不可将其静默当真实负能耗。小时/分钟公式样本时刻的区间起点含义须与训练一致。

推理开始时应解析并固定部署对应的模型版本与绑定修订，整个预测使用同一版本，不在多步循环中反复解析“当前版本”。部署随后切换不改变已开始预测的版本归属；下一次预测另取当前版本，或调用者显式指定允许的固定版本。版本不兼容时失败并提示重新核对绑定，不自动重映射。

## 5. 时间与预测输入语义

候选时间定义：`forecast_start` 是第一个待预测时刻；`step_seconds` 是目标序列步长；`steps` 是返回点数。第 i 个结果时刻为 `forecast_start + i × step_seconds`，i 从 0 开始。最终契约须同时确认目标代表瞬时值还是以该时刻标记的业务区间，避免“预测起点”与“第一段结束时刻”相差一个步长。

历史窗口左闭右开，以明确的 `history_until` 截止，训练与回测不得使用预测目标时刻之后才会得到的数据。模型要求的滞后必须在该截止前可用；迟到样本和未来计划在回测中也按当时可获得性处理，不能拿事后补全结果代替在线可见输入。

全部传输时刻使用带 Z 的 UTC RFC3339。业务时区作为显式元数据保留，用于日历周期解释，不取服务主机时区。固定秒步长和按本地日历天预测是不同口径，首批应只选一种；若未来支持夏令时地区日历预测，需另定重复/缺失小时规则。

步数、历史跨度、来源数量、特征数、结果行数与总耗时均设硬上限，超限返回明确错误，不静默缩短预测区间。具体数值由真实数据规模和性能测试确定，不能直接沿用普通 `:predict` 的行数上限作为业务保证。

## 6. 候选接口与结果资源

建议新增独立预测执行资源，保留现有 `:predict` 语义。以下仅是待开发接口方向：

| 候选操作 | 请求/返回核心内容 | 需要先确定的保证 |
|---|---|---|
| 校验时序绑定 | 模型契约、真实来源、特征映射、采样和单位规则 | 校验无副作用、结果明确区分通过/失败/未验证 |
| 创建一次预测 | 绑定 ID、期望修订、forecast_start、step_seconds、steps、可选区间需求 | 必带幂等键、固定版本、可靠命令结果与超时恢复 |
| 查询预测执行 | 执行 UUID、排队/运行/成功/失败/取消状态、trace_id | 刷新页面后可找回，失败不能返回空成功数据 |
| 读取结果 | 逐时点预测、质量摘要、固定版本、数据截止与区间方法 | 时序结果有界；超出单页使用稳定游标 |
| 查询历史 | 按绑定、模型、时间和状态检索执行记录 | 明确可见范围、游标排序和保留期 |

考虑取数与多步计算可能超过 HTTP 预算，建议沿用 platform 的 API/worker 运行角色，创建返回 HTTP 202，再查询到终态。短小请求是否开放同步执行须经性能验证；不能以 HTTP 请求超时表示任务必定没有执行。不得在 GET 读取时隐式触发训练或预测。

拟定结果内容应至少能表达：

| 内容 | 含义 |
|---|---|
| 执行身份 | 预测执行 UUID、创建/完成 UTC 时间、trace_id |
| 模型身份 | 部署 code、解析到的 model_version_id/版本号、绑定 ID/修订 |
| 输入摘要 | 真实历史起止、observed_until、采样步长、有效/缺失/冲突数、来源是否截断 |
| 输出时间轴 | 每个结果的明确 ts，数量与请求一致或说明整次失败 |
| 点预测 | 有限数值和单位；不可计算时明确失败或逐点不可用，不以 0 顶替 |
| 区间元数据 | 可选 lower/upper、目标覆盖水平、方法标识、校准版本和评估摘要引用 |
| 质量说明 | 缺数/迟到/外推/未来特征不可得等机器可读原因 |

没有经过验证的区间方法时，结果应完全省略统计区间，或明确返回“区间不可用”的能力状态；不能填 `lower=upper=prediction` 冒充完整区间。若允许返回部分预测，必须预先定义逐点状态、区间缺失原因和整次执行的完成含义，前端不得连线跨过不可用区间。首批优先采用整段输入不满足要求即失败的简单规则。

所有新资源继续使用真实 HTTP 状态和 `{code,message,data,trace_id}`。鉴权、配额、可见范围与代理审计需明确落地；当前共享资源域不会因新增预测资源自动变成租户隔离。能管人员身份如需委托传递，应制定受信任协议，不能接受伪造平台身份头。

## 7. 候选模型与区间方法

先用时间顺序回测比较，再选模型；本节不是对算法效果或已有依赖的承诺，也不引入新的运行库。

| 层次 | 候选 | 验证重点 |
|---|---|---|
| 基线 | 上周期同刻、最近值、简单历史统计 | 作为比较基准，明确业务周期；只能作为显式算法，不能作为缺数据兜底 |
| 点预测 | 现有回归 + 显式滞后/周期特征、直接多步回归 | 特征在预测时是否可得，按步长分别评估误差 |
| 多步策略 | 每个预测步独立训练，或递归滚动 | 递归误差累积、后续步输入来源、模型数量与维护成本 |
| 区间 | 留出校准段的残差区间、分位数模型或其他经验证的区间方法 | 目标覆盖水平、按步长覆盖率、区间宽度与漂移敏感性 |

预测区间描述未来观测的不确定范围，不能与均值估计的置信区间混为同一统计量。界面应使用经评审的准确名称；若产品保留“置信带”表述，说明其具体统计含义与覆盖水平。

时间相关、异方差、季节变化和工况切换可能使简单残差区间覆盖失真，不能只对训练误差乘系数便宣称统计保证。区间需要独立校准/回测，并报告按预测距离、时段或工况的实际覆盖与宽度。候选方法选定、外部依赖引入或数据边界改变时，再按工程规范补具体设计/ADR。

## 8. 验证与上线门槛

验证必须分开说明契约正确、数据链路正确和预测效果可接受。单元测试通过或合成数据演示不代表真实点位预测已验收。

| 维度 | 必验内容 |
|---|---|
| 来源 | 不同 ID 同名不串数、模型入口映射完整、无权限来源拒绝、单位匹配 |
| 时间 | UTC/业务时区转换、步长起点、左闭右开、重复/乱序/迟到样本、跨日周月边界 |
| 质量 | 空值、断档、冲突、无穷/NaN、累计表回零、历史截断、上游超时/失败 |
| 防泄漏 | 按时间切分与滚动起点评估，仅使用当时可获得的历史与未来计划 |
| 点预测 | 与明确基线比较 MAE/RMSE；有零值时避免以未定义 MAPE 充当正常数值；按步长和关键工况报告 |
| 区间 | lower ≤ upper、时间轴与单位对齐、目标与实际覆盖率、平均宽度、不同步长与工况覆盖；点估计是否必须落在区间内由选定统计方法声明，不为画图强改边界；没有区间时明确无能力 |
| 并发 | 同命令重放/不同载荷冲突、配置修订冲突、预测中部署切换、读取稳定固定版本 |
| 韧性 | 创建后断线可找回、worker 重复领取幂等、取消与终态竞态、有限超时、无写入盲重试 |
| 展示 | 真实 ts 对齐、观测与预测明确分界、缺段不连成正常数据、阈值带与统计区间名称准确 |

数值门槛由业务确认后固定：预测目标、采样周期、步数、训练/校准/测试时间段、最少有效样本、误差阈值、区间覆盖容差和延迟预算。报告应列明最差时段和无法预测条件，不能只展示挑选出的单次曲线。若现场数据不满足最低质量，交付应说明缺口，不以开发完成宣称效果达标。

## 9. 实施顺序与回滚边界

1. **数据核对与业务定界**：选定首批真实指标与来源，验证授权、历史质量和多特征可得性，确定验收数字。
2. **离线回测样机**：固定数据截止、特征构造、模型与区间候选，输出与基线的可复核报告；此阶段不接控制下发。
3. **契约与服务实现**：确认接口、绑定版本、幂等恢复与游标结果；按 platform 现有数据属主和 worker 角色实现，更新 OpenAPI 和测试。
4. **指标展示联调**：能管后端持有平台密钥，页面只接业务网关；逐点验证时间、单位、缺失、版本归属与区间含义。
5. **受限试运行与验收**：限定指标、调用频率和窗口，观测真实性能、误差和区间覆盖，达到约定门槛后扩大范围。

新存储如有需要按扩展—收缩迁移，新增结构必须兼容旧代码；已有模型版本与普通 `:predict` 契约保持兼容。回滚优先停用新增预测入口并回到已验证的固定模型/绑定版本，不删除历史记录、不回滚数据库、不把当前观测曲线改写为预测结果。

本方案遵守 [ADR-0061](adr/0061-建模模板冻结结构而实例独立配置和训练.md) 的固定模板与独立实例、[ADR-0062](adr/0062-模型调用统一使用账号API密钥.md) 的账号权限、[平台 ADR-0005](../server/services/platform-server/docs/adr/0005-分析建模按需读取外部BDM历史接口.md) 的按需历史读取边界。空调开机达标时长仍按 [ADR-0010](adr/0010-达标时长建模走专用管线而非通用建模流水线.md) 的专用管线处理，不在本方案中自动合并。
