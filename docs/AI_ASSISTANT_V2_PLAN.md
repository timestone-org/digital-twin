# AI 助手 V2 规划：计划执行、子系统治理与跨模块工具

本文是助手第二期的总规划。第一期（[AI_ASSISTANT_DESIGN](AI_ASSISTANT_DESIGN.md)）建起了
「工具分两侧 + POST/SSE 客户端驱动 + 技能渐进披露」三条支柱；第二期在**不动这三条支柱**
的前提下，把助手从「单回合应答」升级成「先计划、后执行、边执行边核验」的 agent，
并把散在各处的提示词、上下文、工具治理收成有名字的子系统。

---

## 1. 现状盘点（三路探查的结论）

### 1.1 已经对的，不再动

- 工具按「谁攥着那份状态」分两侧（ADR-0023），草稿面直改、落库面只提议。
- POST + SSE、待续状态落库（`chat_steps.state='awaiting_client'`）、api 角色无状态。
- 技能渐进披露：常驻只有名录，正文靠 `skills.load` 按需拉；模块清单与函数目录两段式。
- 图只活在截它的那一轮：不进工具消息、不落库、只有带图那轮走视觉档。
- 身份头逐字转发，助手不是绕权限的通道。

### 1.2 查出来的缺陷（本期必须修）

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| 1 | 历史截断是裸切片 `rows[-40:]` | `advance_service.load_context` | 切点落在工具调用与其回应之间时，端点直接 400，且报错与真因无关 |
| 2 | 工具集不按工作面过滤，24 个全量下发 | `advance_service` 写死 `specs=TOOL_SPECS` | 台账工具在大屏页当噪声，模型先试错再换路，白烧往返 |
| 3 | 幽灵工具 `attachment.read_table` | `dashboard_binding` 清单与正文 | 技能正文指示模型去调一个不存在的工具 |
| 4 | 3D（孪生）模块在截图里必是空白 | `createWebGLRenderer` 没开 `preserveDrawingBuffer` | 看图技能对 3D 大屏失明；孪生编辑器干脆没有截图工具 |
| 5 | 面板重开不回放历史 | `useAiPanel` 从不调 `readSession` | 会话还在库里，屏上时间线是空的 |
| 6 | 服务端工具产出不设上限、不落库 | `turn.py`、`ChatStep.output_json` 从不写 | 一次大结果可以挤掉整个上下文；事后查不到工具当时回了什么 |

### 1.3 刻意不做（与一期同口径）

- 无人值守长任务：每个回合都需要开着的浏览器跑客户端工具，这是 ADR-0023 的有意边界。
- 向量检索/知识库：没有第一个真实需求前不建空表。
- 报告模板模块：**本仓尚无报告功能**，助手无从配起；等功能建了再登记工作面。

## 2. 子系统划分（企业级治理）

把助手拆成七个有名字、有属主文件、可独立演进的子系统。原则：**每个子系统一个模块目录
或文件，不新建服务**——助手仍是一个代码单元。

### 2.1 Agent 编排管理（`services/turn.py` + `services/plan.py`）

一期是纯 ReAct 循环（think ↔ use_tools）。二期加**计划执行**：

- **计划即工具**：给模型一个服务端工具 `plan.write`（TodoWrite 式整份重写），
  复杂任务先列计划再动手；每完成一项立刻更新勾掉。**不另起 planner/executor 双模型**——
  单循环 + 计划纪律在业界（Claude Code 等）已被验证，且不破坏客户端驱动的回合边界。
- **计划落库**：`chat_sessions.plan_json`（JSONB，可空）。api 角色无状态，
  计划放内存的话续跑落到另一副本就丢了——与 `awaiting_client` 同一个理由。
- **计划进提示词**：每轮把当前计划渲染成一段（当前项单独点名），模型永远知道
  自己走到哪一步。这就是「一步一步生成每一步的提示词」的机制化表达。
- **前端计划面板**：新增 SSE 事件 `plan`（整份快照），面板顶部渲染 TodoList，
  逐项打勾直到全部完成。
- **自动续跑**：`turn.done` 到达而计划未完时，前端自动追加一次「按计划继续」的推进
  （有上限，默认 3 次），用户随时可停。模型主动停下问人时不续跑。
- **设计类工作截图验收**：技能纪律要求布局/外观类计划的最后一项固定是
  「截图自检」——`dashboard.capture` 看图，不满意就往计划里追加修正项，
  直到看过为止才允许勾掉收尾项。

### 2.2 提示词管理（`services/prompt.py` 为组装器，正文分文件）

- **分节组装**：常驻提示词 = 基本规矩 → 当前位置 → 工作面快照 → 当前计划 →
  技能名录 → 计划纪律。节与节之间的顺序有语义（先知道对象再选技能），
  由 `prompt.py` 唯一持有。
- **正文文件化**：技能正文已是 `skill.md`；新增的纪律段落保持短小常驻
  （计划纪律 ≈ 150 字），细则放进技能正文按需拉。
- **一轮一拼、库里不存**：不变。历史会话永远按当下的提示词口径重放。
- **每个工具的 description 就是它的微型提示词**：工具怎么用、什么坑，写在
  `tool_specs.py` 的描述里，与技能正文互为两级披露。

### 2.3 上下文管理（`services/history.py` + `services/context.py`）

- **配对安全的历史窗口**：截断点不许落在「带工具调用的助手消息」与其工具回应之间；
  窗口头部的孤儿工具消息一律丢弃。
- **工具产出钳制**：服务端工具结果落进消息前按字符上限截断并如实标注
  「……（截断，共 N 字）」——截断要说出来，不许静默。
- **快照、技能、目录的按需披露**：不变（一期已做对）。
- **预留（本期不做，落挡案）**：会话摘要压缩（把窗口外的旧回合摘成一段系统注记）、
  token 计数（`usage_json` 列已在，先把模型回的 usage 记上，再谈预算）。

### 2.4 工具注册中心（`services/tool_specs.py`）

- `ToolSpec` 仍是唯一真源；本期给它补两格治理元数据的**约定**（不改数据类）：
  服务端工具按「核心（哪都在）/ 技能声明（跟着工作面）」分档下发；
  客户端工具按**前端自报**过滤——`AdvanceIn` 新增可选 `client_tools`，
  页面把自己实现了哪些工具随每轮上报，模型看不见这一页调不动的工具。
- **跨模块只读工具**进核心档（见 §3 矩阵）：在任何工作面都能查大屏清单、台账列、
  素材、点位——这就是「跨模块配置」的读侧一半。
- 写侧分三级（沿用 ADR-0023 第四条，逐工具标注）：
  1. **草稿直改**：大屏/孪生编辑器的客户端工具（可撤销）。
  2. **提议确认**：无撤销页面的写动作做成提议卡（台账公式已有；采集、素材、
     运行参数照此扩展），保存永远由人按。
  3. **排除**：权限写操作（覆盖式清权限、删用户、发 API Key）、边缘路由规则、
     实时通道内部面——不封装，助手在这些面上只读或缺席。

### 2.5 技能管理（`skills/`）

- 清单 + 正文的形态不变。本期动作：
  - `dashboard-review` 扩到孪生编辑器（3D 截图修好后成立）。
  - 删幽灵工具引用；`dashboard-compose` 正文补「计划纪律 + 截图验收」一节。
  - 新技能随新工作面走（采集页、素材页登记 surface 时再添）。

### 2.6 会话与记忆管理（`session_service` + 前端 `useAiPanel`）

- 面板重开**回放库里的历史**（`readSession` 已有，前端接上）。
- 计划随会话存取，重开后计划面板恢复。
- 预留：标题自动摘要（一期挡案未变）。

### 2.7 可观测与评测（`chat_steps` + 既有结构化日志）

- 服务端工具产出截断后写入 `ChatStep.output_json`（列已在，从不写是浪费）——
  排障时能看到工具当时回了什么。
- 模型 usage 写入 `ChatMessage.usage_json`，为将来 token 预算与评测提供实数。
- 预留：技能级评测集（每技能一组「输入 → 期望工具序列」的回归样例）。

## 3. 跨模块工具矩阵（目标态）

按「读 / 草稿直改 / 提议确认 / 排除」四档。**粗体**为本期落地，其余分期。

| 模块 | 读（服务端，跨工作面可用） | 草稿直改（客户端） | 提议确认 | 排除 |
|---|---|---|---|---|
| 大屏 | **`dashboards.list`**、`modules.catalog`✅、`dashboard.validate`✅ | 既有 14 个✅ + 分期：联动规则、层级/显隐、批量配置 | 大屏 CRUD、发布分享、模板实例化 | — |
| 孪生 | （寄居大屏节点，读走大屏） | 绑定 3 个✅、**`dashboard.capture`**；分期：七类实体增删改、染色、漫游 | — | — |
| 采集 | `points.list_sources`✅、`points.search`✅、**`points.detail`**、分期：浏览地址空间 | — | 分期：数据源启停、点位 CRUD、在线导入 | 写值下发（`collect:operate` 危险动作，单独评审） |
| 台账 | `formula.catalog`✅、`formula.validate`✅、`formula.preview`✅、**`datasets.list_tables`**、**`datasets.read_columns`（服务端版）** | — | `dataset.propose_formula`✅、分期：建列提议、修正提议 | 回填、重算（长任务） |
| 素材 | **`assets.search`** | — | 分期：改名提议 | 删除、重压 |
| 运行参数 | 分期：`runtime_params.read`（带 tier/danger 元数据） | — | 分期：改参提议（danger≠off 必须确认） | — |
| HVAC | 分期：模型/房间只读 | — | — | 训练、下发（长任务 + 写现场） |
| 权限 | 分期：权限码目录只读 | — | — | 全部写操作 |

提议卡 UI 一起来——没有确认界面就没有写工具，这是 ADR-0023 第四条的硬约束。

## 4. 协议增量（本期）

| 变更 | 内容 | 兼容性 |
|---|---|---|
| SSE 事件 +1 | `plan`：`{"plan":{"title","state","items":[{"title","status","note"}]}}`，整份快照 | 新增事件，旧前端按未知帧跳过并计数（解帧器既有行为） |

| `AdvanceIn` +1 字段 | `client_tools?: string[]`（页面自报实现了哪些客户端工具） | 可选字段，不带时退回技能声明推导 |
| 表 +1 列 | `chat_sessions.plan_json JSONB NULL` | 扩展步，可空列 |
| 服务端工具下发 | 由「全量」改为「核心 + 技能声明 + 前端自报」过滤 | 模型可见面收窄，行为向好 |

## 5. 分期路线

- **P0（本期）**：计划执行循环全链路（后端工具/落库/事件 + 前端计划面板 + 自动续跑）；
  3D 截图修复 + 孪生编辑器截图工具 + review 技能扩面；§1.2 的 1/2/3/6 号缺陷；
  跨模块读工具第一批（dashboards.list / datasets.list_tables / datasets.read_columns /
  assets.search / points.detail）；会话历史回放。
- **P1**：采集工作面登记 + 采集读写（提议卡）；运行参数读 + 提议改参；
  大屏联动规则与层级工具；孪生实体增删改工具。
- **P2**：会话摘要压缩与 token 预算（基于 usage_json 实数）；技能评测集；
  素材/HVAC 只读工具；标题自动摘要。
- **P3**：大屏 CRUD/模板/发布的提议链路；跨模块反查（点位 ↔ 台账 ↔ 大屏绑定图谱）。

每期收口条件：契约测试两侧锁死、增量覆盖达标、`scripts/ci-local.sh --fast` 全绿。
