# 知识库对话

一个独立的对话页：对着知识库多轮提问，模型自己决定检索几次、去哪几个库找，
歧义时反问并给出选项让人选，会话可列可改可归档。默认查全部库，用户可以把这次
对话的范围收窄到几个库。

架构决策见 [ADR-0037](adr/0037-对话引擎并入domain-llmcore.md)：通用对话引擎并入
`server/domain/llmcore/`，助手与知识库各接各的工具；检索范围见
[ADR-0044](adr/0044-对话检索范围钉在会话上.md)。

## 1. 它与已有两处的分界

| | 入口 | 谁在决定检索几次 | 会话 |
|---|---|---|---|
| 知识库页的检索试验台 | `/knowledge` | 不检索编排，一次 `:search` 出块 | 无 |
| `:ask` 端点 | 程序调用 | 服务端 agentic 编排跑完（ADR-0035） | 无 |
| **知识库对话**（本文） | `/knowledge/chat` | **模型自己**，每轮可再检索 | 有 |

⚠ 对话**不调 `:ask`**。两条编排叠起来会互相抢，且用户看不出这一轮到底是谁在
决定要不要再查一次。`:ask` 保留给不要对话的调用方。

## 2. 一轮对话里发生什么

```
用户问一句
  └─ 模型看到：常驻提示词 + 这次对话的检索范围 + 历史窗口 + 工具规格
     ├─ 歧义？ → 调 user.ask，浏览器渲染选项 → 用户选 → 回同一个回合
     ├─ 调 kb.search(base_id, query)     ← 可以调多次、可以跨库
     │    └─ base_id 不在范围里 → 当场拒（不是空表）
     ├─ 觉得某块要看全文 → kb.read_chunk(chunk_id)   ← 越界的块同样拒
     └─ 够了 → 给出带角标的答复
```

**角标必须能指回三样**：哪个库 / 哪份文档 / 哪个位置。默认跨全部库是用户拍板的
口径（ADR-0037 决策三 + ADR-0044），而跨库的代价就是模型可能挑错库——不标出来
用户看不出。

**范围是硬过滤，不是提示词里的一句请求。** 提示词如实说这次能查哪几个库，但真正
拦住越界取数的是工具层每一次调用前的那一道判定（§3）。只写提示词的话，模型多数
时候听话、偶尔不听，而不听的那一次没有任何一处报错。

## 3. 工具（一期只有知识库这一路）

| 工具 | 收什么 | 给什么 | 范围怎么拦 |
|---|---|---|---|
| `kb.list_bases` | — | 有哪些库、各自的策略与索引档 | 只列范围内的 |
| `kb.search` | `base_id`、`query`、`limit` | 若干召回：库名、文档名、位置、正文、为什么命中 | 库不在范围里即抛 |
| `kb.read_chunk` | `chunk_id` | 那一块的完整原文与它前后各一块 | 块所属的库不在范围里即抛 |

加一路 = 加一个文件 + `llmcore` 注册表一行 + 一条契约测试。

⚠ 三道拦截里 **`kb.read_chunk` 那道最容易漏**：前两个拦住了，模型仍可能从更早的
历史消息里翻出一个越界的 `chunk_id`，而它换回来的是整段原文。

⚠ 越界一律**抛错**而不是回空表：空表与「这个库里确实没这句话」长得一模一样，
模型会把它读成「查过了，没有」然后接着往下答。

⚠ 一期**不给写工具**：对话面只读。让模型能改库里的东西，等于让一句话就能改掉
所有人以后检索到的内容，而这件事没有撤销栈。

## 3.1 走哪一路模型

对话档按**接入形态**查一张显式的表（`llm_adapters.KIND_BUILDERS`，
[ADR-0041](adr/0041-订阅账号凭据归平台持有.md)）：目录里给 `knowledge.chat` 分配了
哪一路就走哪一路，没分配才退 `KNOWLEDGE_MODEL_*` 那一档。两种形态各一个装配口子
——按量计费的 OpenAI 兼容端点，与 ChatGPT 订阅账号。

⚠ 接不了的形态**如实缺席**，不退回环境变量那一档：静默改走另一路的差异只出现在
账单上。

⚠ 订阅账号那一路的登录态归 platform（与那一行供应商同属主），本服务经内部面领
一份短时令牌、**只领不刷**——刷新是写操作，两个消费方各自去刷会互相把对方的令牌
作废，而现象是「用着用着就掉登录」。

⚠ 那一路的端点只认 `^[a-zA-Z0-9_-]+$` 的工具名，而上面三个工具都带点号：出去
换成 `__`、回来换回去（`llmcore.codex.wire_names`）。不换是每一次带工具的对话都
撞一条 400，而那条 400 里既不说是哪个工具、也不说问题出在点号上。

## 4. 反问用选择，不用自由文本

歧义时模型调 `user.ask`——这是 `llmcore` 的客户端工具：模型给出问题与若干选项，
浏览器渲染成按钮，用户点一个，结果回填进同一个回合继续跑。

⚠ **不许用「请补充说明」这类自由文本反问**：用户不知道该补什么，补出来的往往还是
歧义的。给选项等于把消歧的责任放回模型身上——它必须先想清楚有哪几种解释。

## 5. 会话管理

列出、改标题、归档、删除、**改检索范围**。标题由首轮摘要出来；摘不出就显示时刻。

会话表在 **`knowledge` schema 自己这一份**，不与助手共用（ADR-0037 决策二）：
跨 schema 外键是禁令，共表则把两个服务的发布周期绑死。

### 5.1 检索范围（ADR-0044）

范围钉在会话上，输入框上方的选择器改它，改了对这个会话后续每一轮都生效。

- **`null` = 全部知识库**，是新对话的缺省；**空列表非法**，当场 400。两者分不开的
  表现是「用户清空了选择，检索却悄悄扩到了全部库」。
- 出参 `base_scope` 带库名（`[{base_id, name, is_missing}]`）：只回 uuid 的话前端
  显示不出人话，而它手上那份库清单是分页的、也会过期。
- 范围里的库**被删了就标 `is_missing`，不抹掉**：抹掉等于替用户把边界改宽。同一条
  理由，那一列不建外键。
- 改范围推进 `row_version`；`expected_version` 带上就断言，对不上回 409。
- 范围**不是权限**：对话面仍然只要 `knowledge:use`（§6）。它是用户给自己划的取数
  边界，随时能改回全部。

## 6. 权限

对话面挂 `knowledge:use`——与检索同一个码：能检索就能问，问不出比检索更多的东西。

⚠ 不新造 `knowledge:chat`：它与 `knowledge:use` 之间不存在任何一种「能 A 不能 B」
的真实诉求，造出来只是角色配置界面上多一个没人分得清的勾。

## 7. 语音输入

输入框旁有一枚麦克风键：按一下、说一句、转写整体进草稿，说完再按一下。音频经
`knowledge-server` 的 `GET /api/v1/knowledge/speech/ws` 中继到现场自建的
FunASR（离线识别，不出内网），转写以「整段」回来，客户端整体替换、不自己拼。

决策与部署步骤见 [ADR-0038](adr/0038-语音输入走自建FunASR经知识库服务中继.md)；
消息契约的唯一真源是 `apps/speech/services/protocol.py`，前端逐字复述并由契约
用例钉住。接没接由 `/capabilities` 的 `is_asr_enabled` 如实回答，没接就没有
麦克风键。

⚠ **浏览器开麦要 HTTPS 或 localhost**：这是浏览器的安全上下文要求，与本设计
无关。`http://` 页面上麦克风键会报一句能定位问题的错，现场部署要给边缘配 TLS。

## 8. 一期不做

- **写工具**（见 §3）。
- **跨会话的长期记忆**：助手那套（ADR-0030）是它自己的，知识库的"记忆"就是知识库本身。
- **附件**：这一页的输入是问题，不是资料；要加资料走 `/knowledge` 的上传。
- **计划子系统**（ADR-0024）：知识问答不是多步施工，摆一个空计划栏只会占地方。
