# 页签栏模块（`nav-tabs`）— 设计

大屏上第二个**控件**类模块：一排互斥的页签，点一格高亮它并上抛一次
「选项点击」事件。切到哪张大屏、显隐哪一组节点，全由大屏级联动规则按上抛的值
分流——模块自己不认识任何一种动作，这一条与
[MODULE_ACTION_BUTTON_DESIGN](MODULE_ACTION_BUTTON_DESIGN.md) 逐字相同。

它补上了 [DASHBOARD_NAV_DESIGN](DASHBOARD_NAV_DESIGN.md) §9 第 4 条留下的
「导航菜单模块是另一次讨论」。

---

## 1. 为什么值得一个独立模块

一排按钮不是一条页签栏。差别不在好看，在于**同时只有一个是当前项**：

| 要的东西               | 页签栏               | 一排 action-button           |
| ---------------------- | -------------------- | ---------------------------- |
| 同时只有一格是当前项   | 有（本地互斥）       | 没有，每个按钮各管各的       |
| 一条轨道内的对齐与等分 | 有                   | 靠容器摆，改一格宽度要挨个调 |
| 「我现在在哪一屏」     | 一眼看得出           | 看不出                       |
| 配置成本               | 一个模块，一张行列表 | N 个模块，N 份外观各配一遍   |

`action-button` §7 那句「一块摆一排按钮是导航条/分段切换的形状，它们各自该是
自己的模块」说的就是本模块。

⚠ 类型 id 是 `nav-tabs` 而不是 `tabs`：守「运行时与编辑器里零模块类型字面量」的
两道闸按**已注册的 type** 逐个 grep 源码，而 `tabs` 是 `DtSegmented` 的一个
variant 取值——叫它会红在一堆与模块毫不相干的地方（`action-button` 的教训）。

## 2. 目录与文件

```
web/packages/modules/src/modules/nav-tabs/
├── manifest.ts       清单：35 个配置字段 + 4 套外观预设，零绑定槽
├── options.ts        取值表（风格/语义色/轮廓/指示条/排布/动效/图标），清单与渲染共用一份
├── look.ts           配置 → 形态：类名、CSS 变量、每一格的文案与联动值，纯函数
├── Component.vue     一排原生 button 的模板、本地选中态与那一次上抛
└── _variants.scss    五档风格、切角、指示条、分隔线、悬停与按下、辉光
```

分文件的理由与按钮那套相同：单文件组件 ≤500 行是闸门，三十几个旋钮摊在组件里
必然超；收成纯函数后，夹取与哨兵语义能被独立单测。

## 3. 目标大屏存在**规则**里，不在这份配置里

这是本模块最容易做错的一处，也是唯一一处结构性决定。

「每一格绑一张大屏」写进模块配置看着更省事，但节点的 `config_json` 是**逐字
透传**给公开载荷的（`share_service.to_public_dashboard_out`）。真那么存的话：

- 匿名载荷里会出现兄弟屏的**内部大屏 id**，与 ADR-0014「公开面不回任何能定位
  它在库里位置的信息」直接冲突；
- 公开态照样跳不动——公开路由要的是**令牌**，而服务端的句柄改写只认
  `chrome_json.interactions` 那一段（`public_interactions.py`）。

所以模块只管上抛值，目标由规则给：

| 用途         | 联动规则                          | 事件     |
| ------------ | --------------------------------- | -------- |
| 跨屏切换     | 按值跳转大屏（`navigateByValue`） | 选项点击 |
| 页内分区切换 | 按值互斥切换（`setActive`）       | 选项点击 |

一条规则一次配完所有页签，跨屏复制节点时规则跟着节点一起走
（`editorClipboard` 会带上选中集内部闭合的规则）。

### 3.1 只发 `select` 一档

清单声明 `interactionEvents: ['select']`。理由两条：`select` 是带值的那一档，
也是 `applyInitialSelections` 进场重放互斥组唯一认的那一档。

清单只开 `emitsInteractions`，**不开 `hostClickable`**：两个都开的话，格子之外
的空白也能点，而那一次点击**不带值**，会命中「值留空」那条路径。
模板上的 `@click.stop` 是同一条理由的第二道。

联动面新增一条规则时，触发事件取**源模块自报的第一档**而不是恒给 `click`
（`InteractionEditor.defaultEventOf`）。恒给 click 的话，给页签栏加的第一条规则
永远不触发，而面板上只在下拉里标一句「该模块不会发出此事件」——很容易漏看。
`twin-2d-view` 也只发 `select`，它一并受益。

⚠ **联动值留空的格点了不上抛任何事件**。没有 value 的事件命不中任何一条按值
分派的规则，抛出去只会误触无值那条路径。出厂三格因此都自带联动值——
带标签不带值的出厂配置会让第一次试点击静默无反应。

## 4. 选中态：三档，宿主推的那一档管跨屏

高亮取自「用户刚点的那一格 > 宿主推出来的当前屏那一格 > 配置里的默认选中」。

- **跨屏切换**：宿主（运行态页 / 公开页 / 编辑器预览）把**当前这张屏的句柄**下发
  给联动引擎（`InteractionPorts.currentHandle`），引擎在本节点的按值跳转规则里
  找出目标就是这张屏的那条路由，把它的值当作 `meta.activeValue` 交给模块。
  于是同一条页签栏原样摆到每张屏上，高亮各自都对。
  ⚠ 这一档必须赢过配置里的静态下标：那个数只对其中一张屏是对的，在别的屏上
  就成了「高亮停在别处」——用户跟着高亮去点，点的正是自己那一格，被自跳挡下，
  表面上就是「切换大屏无法生效」。
- **页内分区切换**：没有跳转规则，也就推不出当前格，仍由配置里的「默认选中」
  起步；真相在联动运行时的显隐覆盖态里，页签只负责说「我现在选的是哪一个值」。
  这与 `action-button` §3.1 拒绝「开关式按钮」并不矛盾：那里的状态没有第二个
  来源可对齐，这里的互斥语义本来就归控件。
- **刚点的那一格赢过前两档**：跨屏跳转在途时（文档还没到、上一屏还留在原地）
  得先给出反馈；宿主一说「现在是另一张屏了」，本地那一下就作废。

两处夹取：配置里的序号超出真实格数时夹到最后一格；点过之后把格删到更少时，
高亮回落。不夹的话，整条轨道上没有任何一格是亮的，看着像模块坏了。

⚠ 模块自己**仍然不认识大屏**：它只拿到一个字符串值，跟自己那几格的联动值比。
句柄的含义（登录态是大屏 id、公开态是令牌）从头到尾只有宿主知道。

## 5. 配置面

| 组   | 字段                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 内容 | 页签行列表（文案 / 联动值 / 图标 / 禁用）、默认选中第几项                                                                                                 |
| 外观 | 风格、语义色、自定义主色、未选中文字色、选中文字色、轨道底色、每格轮廓、每格圆角/切角、轨道圆角、描边粗细、分隔线、选中辉光、辉光半径、指示条、指示条粗细 |
| 文字 | 字号、字重、选中字重、字间距、图标字号                                                                                                                    |
| 排布 | 排布方向、格内对齐、尺寸、每格等分、水平位置、垂直位置、格间距、格内左右边距、格内上下边距、轨道内边距                                                    |
| 动效 | 悬停反馈、按下反馈                                                                                                                                        |

四套外观预设（一次浅合并落库、一步撤销）：**凹槽控件**（与 `DtSegmented` 的控件
档同观感）、**页签底线**（与应用壳里的 `AppTabNav` 同观感）、**科技切角**、
**实心胶囊**。预设只写观感键，`contentKeys`（页签表与默认选中）一个都不碰。

### 5.1 五档风格 × 语义色

样式表里只认 `--tab-accent` 一个变量，所有派生色走 `color-mix`——换肤与换语义色
因此都只动那一处。⚠ 预警档的文字色是深色（`--text-inverse`）而不是
`--text-on-emphasis`：黄底上的浅字读不出来。这一档与 `DtButton`、`action-button`
的口径逐字相同。

### 5.2 三个哨兵

- **图标字号 `0` = 跟着文字字号走**（1.1 倍）。
- **选中字重 `0` = 与未选中同一个字重**。⚠ 只给选中格加粗会让那一格变宽，
  「按内容」尺寸下每切一格整条轨道都要抖一下——这也是 `DtSegmented` 各档一律
  同字重的理由。
- **留空的颜色不注入变量**：`--tab-text` / `--tab-active-text` / `--tab-track`
  只有配过才写，否则各档风格自己的缺省回落不到。

### 5.3 两处互斥的组合

- **切角 + 分隔线**：切角走 `clip-path`，它会把格子外的伪元素一起削掉，
  于是那一档看不见分隔线。字段 `help` 与「科技切角」预设都按这条写。
- **竖排 + 底部横条**：一列页签里，底部横条读不出层次，竖排该用「首侧竖条」。
  竖排同时该把「格内对齐」改成靠左——等分之下内容恒居中，指示条会孤零零地留在
  左边缘、与文字隔着半格空白（这一条是截真图才看出来的）。

### 5.4 未选中的格必须自己写透明底

原生 `<button>` 的 UA 缺省底色是浅灰。宿主页面的重置样式替我们清掉了它，
所以在应用里看不出问题——但脱开那份重置单独渲染（Storybook、静态样机、
别的宿主）时，整条轨道会是一排白块。`.dt-tabs__item` 因此显式写
`background: transparent`，与 `DtSegmented` 同一处理。

### 5.5 悬停只作用在没选中的格上

选中格已经是终态，再提亮一次只会让人以为点错了。按下那几条排在悬停之后——
同特异度靠后者胜出，按住时看到的才是「按下去」。触摸屏上没有悬停，所以按下
反馈单独一档。

## 7. 这一版不做

- **页内分区的进场重放**。运行时早有 `InitialSelection`（`init` 的第三个参数），
  但眼下没有宿主下发它。页内分区的开屏状态靠**节点自己的初始显隐**就能配对：
  默认那组可见、其余初始隐藏。跨屏那一档不需要它——当前格由规则与当前句柄推
  （§4），推的过程里没有任何一个具体模块的名字。
- **键盘方向键换页签**。原生 `<button>` 已经给了 Tab 次序、Enter/Space 与焦点环；
  方向键那一套属于 `role="tablist"` + `aria-controls` 的完整页签语义，而本模块
  切的东西不一定是同屏内的一块面板（跨屏那条路根本没有 tabpanel）。
  沿用 `DtSegmented` 的 `role="group"` + `aria-pressed`，是本仓已经成立的口径。
- **溢出滚动**。格数上限 12，配满时靠等分与省略号收；真要放二十项，那是侧边
  导航的形状，不是一条页签栏。
- **按数据决定哪一格能点**。禁用是常态置灰。要按实时值挡住入口，用联动规则
  控制显隐——理由与 `action-button` §7 相同。
