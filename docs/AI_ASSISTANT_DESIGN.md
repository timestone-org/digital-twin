# AI 助手设计

助手是**技能驱动**的：常驻提示词里只有一份技能名录，正文与工具由模型按需拉取。
它站在哪一页，就装哪一套技能；改画布的活不在服务端干，下发到浏览器执行。

对应的代码单元是 `server/services/ai-assistant/`（端口 8006、schema `assistant`），
前端在 `web/app/src/features/ai/` 与各页面的 `aiSurface.ts`。

---

## 1. 三条支柱

### 1.1 改画布的工具在浏览器里执行（[ADR-0023](adr/0023-助手改画布的工具在浏览器里执行.md)）

大屏编辑器手里握着一份**本地草稿**：撤销栈、脏标记、localStorage 自动存稿都在
浏览器里。服务端若直接改库，会同时坏三件事——用户屏幕不变、保存时撞 409、
一步都撤不回来。

所以工具按「**谁攥着那份状态**」分两侧：

| | 服务端工具 | 客户端工具 |
|---|---|---|
| 在哪跑 | ai-assistant 进程内 | 用户的浏览器 |
| 干什么 | 要密钥、要 IO、要处理大数据 | 改画布、读页面此刻的样子 |
| 例子 | `points.search` `modules.catalog` `formula.validate` | `dashboard.write_binding` `dashboard.add_module` `dashboard.capture` |
| 失败意味着 | 我们这一侧坏了 | 这一页根本没实现它 |

这条决定了协议必须是**双向**的：POST + SSE，回合停在「等浏览器」时把待办交出去，
浏览器跑完再带着结果发起下一次推进。待办状态**落库**（`chat_steps.state =
'awaiting_client'`）而不是留在内存里——api 角色无状态，续跑可能落到另一个副本上。

```
START → think ─（没有工具调用）──────────────→ END
             ─（有服务端工具）→ use_tools ─（还有待办）→ END
                                         ─（没有待办）→ think
             ─（只有客户端工具）─────────────→ END
```

⚠ 服务端与客户端工具混在同一批时，**服务端那几个先就地跑完**再交出去。否则
浏览器回来时模型手上缺半批结果，它多半会把没答的重问一遍。

### 1.2 一步一步看得见

回合是流式的：每走完一步就推一个事件出去，界面上逐行显示「查了什么、绑了哪一条」。
等回合整个跑完再一次性推的话，一次批量绑点要转十几秒的圈，而助手其实一直在动。

事件集是闭合的：`step` / `client_tool.request` / `turn.done` / `error`。

⚠ 边缘那条 SSE location **不能** include `proxy-common.conf`：它的
`proxy_read_timeout 25s` 会在模型还在想的时候把连接掐掉，而现象是「转了半分钟
然后什么都没发生」。同一条 location 里还必须 `proxy_buffering off`，否则事件流
退化成「攒完再一次吐」，"一步一步看得见"这一半就没了。

### 1.3 上下文按需拉取

常驻提示词只有 **648 字**：基本规矩 + 当前工作面 + 技能名录（每个一句话）。
正文由模型自己调 `skills.load` 拉。同理，模块清单、函数目录都是两段式——
先给名片，点名了才展开。

理由是同一个：整份模块清单六万多字符、函数目录五十九个函数，原样塞进去之后
被挤出上下文的正是**技能正文与工具结果**，而表现是助手忽然「忘了」自己刚查到的东西。

## 2. 四个技能

| 技能 | 工作面 | 干什么 |
|---|---|---|
| `dashboard-binding` | 大屏编辑器 / 孪生编辑器 | 批量把数据槽绑到采集点位，可带一张点表当参考 |
| `dashboard-compose` | 大屏编辑器 | 摆模块、改配置与外观、对齐排版 |
| `dashboard-review` | 大屏编辑器 / 孪生编辑器 | 截图看版面，给改进建议 |
| `formula-author` | 台账详情 | 写台账公式，验过、试算过再交给用户 |

技能是一个目录：`manifest.py`（名字、简介、适用工作面、要哪些权限码、用哪些工具）
加一份 `skill.md`（正文）。注册走**显式元组**，不靠 import 副作用。

## 3. 点位召回

批量绑点是助手最主要的场景，而它的难点全在召回：

- 后端的 `q` 只对**名字与编码**做子串匹配，且永远顺序扫描。
- 真实现场 **77% 的节点地址是 `i=2253` 这种裸数字**，零语义。
- 真实编码形如 `K1_TMT_HOT_T_PI`，与用户说的「1 号机组热水出口温度」**一个字都不重合**。

所以召回：**一个字都不看 address**；主力信号是中文名，编码经一张工业缩写表
（TT/TMT/PT/DP/FT/LT/AT/SP/PV/…）展开后再比；单位与数据类型参与相容性打分。
按词问不到时**退回全量翻页**，由本地打分兜住。

三条刻意的克制：

1. **得分为 0 的候选一律不返回。** 硬凑几个出来的话，模型会以为「就这些了」
   然后从里面挑一个——那比返回空表难查得多。
2. **打分只排序不取舍**，并把「为什么它排在这」（`why`）一并交给模型：
   选哪一个由它定，因为只有它知道用户这句话的上下文。
3. **点表不落库、不进对象存储。** 存文件要连带一整套生命周期，而这张表的用处
   只有一次——它是这一轮对话的参考资料，不是资产。

## 4. 截图

`dashboard.capture` 是客户端工具，用 `html-to-image` 出一张 1280 宽的 PNG。

- 图**不放在工具消息里**：OpenAI 兼容口径只认用户消息里的图片块，塞进工具消息
  多半被整条丢掉，表现是模型说「我没看到图」而调用明明成功。工具消息回一句
  「图在下一条」，图另起一条用户消息。
- 图**不落库**，库里存的是一句 `[截图]`。全存下来的话，一个看过几次图的会话
  每次重放都要把它们再喂一遍，上下文与账单一起翻倍。技能正文因此明说：
  **看完当场把结论写成文字，下一轮它只看得见占位。**
- 只有带图的那一轮走**视觉档**模型。整个会话都走的话，一次截图之后每句闲聊
  都按视觉计费。
- **三维模块（孪生视图）在截图里一定是空白**：渲染器没开 `preserveDrawingBuffer`，
  每帧画完缓冲就清了。为一次截图给所有 3D 场景开着它是拿每帧性能换一次按钮，
  不换；改由技能正文交代模型别把那块空白读成「漏配了」。

## 5. 台账页与大屏页的分界

大屏编辑器改的是草稿，一次 Ctrl+Z 撤得掉，所以助手**直接改**。

台账页**每一次写入都是真实落库、没有撤销栈**，所以助手只有一个写动作，
而它写的不是库、是一张待用户确认的**提议卡**：点「填进编辑器」把表达式带进弹窗，
**保存仍由人按**。

⚠ 预填连**来源**一起切成「公式」。只填表达式的话，这一列仍是人工录入，
保存下去那条公式一次都不算，而界面上看着一切正常。

## 6. 身份与权限

三道闸之外，助手自己不额外开口子：

1. 边缘 `auth_request` 注入七个 `X-Auth-*` 签名头。
2. 助手**原样转发**这组头去打 platform。签名覆盖的是
   `user_id|role|permissions_b64|expires_at` 的拼接，不含 path 也不含目标服务，
   所以转过去就验得过；而 platform 按**用户自己的**权限码判定。
   **助手因此不是绕过权限的通道**——它读不到用户本来读不到的东西。
   ⚠ 必须逐字原样：解析成 UUID 再转回会归一化，验签当场失败。
3. 权限码只有一个：`assistant:use`。

## 7. 可卸载

某些现场根本部署不了 AI。卸载分三层，任一层成立都是**干净地不出现**，
而不是出现一个点了报错的按钮：

| 层 | 怎么关 | 效果 |
|---|---|---|
| 编译期 | `web/app/src/main.ts` 不调 `installAiAssistant()` | 适配器不注册，`aiPorts()` 恒空 |
| 部署期 | 编排里不起 `ai-assistant` | 能力探测失败 → 入口不出现 |
| 账号 | 不给 `assistant:use` | `PermGuard` 挡住入口 |

⚠ 探测失败一律读成「这套部署没有助手」，不是「暂时故障」。

模型本身也是可缺席的：`ASSISTANT_MODEL_ENABLED=false` 时服务照常起、
能力面回「没接模型」。但**开关打开却不配密钥 = 启动即失败**——密钥类绝不给默认值，
而「起来之后每次对话才报错」比起不来难查得多。

## 8. 模型接入

代码里**不认任何厂商名**：端点、模型名、超时全从配置来（`config-and-secrets §6`）。
默认指向阿里百炼的 OpenAI 兼容端点，换供应商是改一行配置。

调用外面包一层断路器。**哪一档失败该让它打开，是这一层最要紧的判断**：

- 超时、连不上、限流、5xx = 「下游此刻不行」→ **打开**，短路能省下白等的时间。
- 401 / 403 / 400 = 「我们自己配错了或发错了」→ **绝不打开**：断路器一开，
  真正的原因就被盖成「暂时不可用」，而那会让人去查网络。

⚠ 这一层**不重试**。一条链路只有一层负责重试，而那一层是编排层。
