# AI 助手设计

助手是**技能驱动**的：常驻提示词里只有一份技能名录，正文与工具由模型按需拉取。
它站在哪一页，就装哪一套技能；改画布的活不在服务端干，下发到浏览器执行。

对应的代码单元是 `server/services/ai-assistant/`（端口 8006、schema `assistant`），
前端在 `web/app/src/features/ai/` 与各页面的 `aiSurface.ts`。

第二期（计划执行循环、子系统治理、跨模块工具矩阵与分期路线）见
[AI_ASSISTANT_V2_PLAN](AI_ASSISTANT_V2_PLAN.md) 与
[ADR-0024](adr/0024-助手计划执行循环用单模型加计划工具.md)；本文补了 §1.4 与 §4.2。

---

## 1. 三条支柱

### 1.1 改画布的工具在浏览器里执行（[ADR-0023](adr/0023-助手改画布的工具在浏览器里执行.md)）

大屏编辑器手里握着一份**本地草稿**：撤销栈、脏标记、localStorage 自动存稿都在
浏览器里。服务端若直接改库，会同时坏三件事——用户屏幕不变、保存时撞 409、
一步都撤不回来。

所以工具按「**谁攥着那份状态**」分两侧：

| | 服务端工具 | 客户端工具 |
|---|---|---|
| 在哪跑 | ai-assistant 进程内 | 用户的浏览器 |
| 干什么 | 要密钥、要 IO、要处理大数据 | 改画布、读页面此刻的样子 |
| 例子 | `points.search` `modules.catalog` `formula.validate` | `dashboard.write_binding` `dashboard.add_module` `dashboard.capture` |
| 失败意味着 | 我们这一侧坏了 | 这一页根本没实现它 |

这条决定了协议必须是**双向**的：POST + SSE，回合停在「等浏览器」时把待办交出去，
浏览器跑完再带着结果发起下一次推进。待办状态**落库**（`chat_steps.state =
'awaiting_client'`）而不是留在内存里——api 角色无状态，续跑可能落到另一个副本上。

```
START → think ─（没有工具调用）──────────────→ END
             ─（有服务端工具）→ use_tools ─（还有待办）→ END
                                         ─（没有待办）→ think
             ─（只有客户端工具）─────────────→ END
```

⚠ 服务端与客户端工具混在同一批时，**服务端那几个先就地跑完**再交出去。否则
浏览器回来时模型手上缺半批结果，它多半会把没答的重问一遍。

### 1.2 一步一步看得见

回合是流式的，而且是**两个粒度**上的流式：

- **逐字**：模型说的话与它想的过程边生成边推，`message.delta` 的 `channel`
  分 `text` / `reasoning` 两路。
- **逐步**：每走完一步推一个 `step`，界面上逐行显示「查了什么、绑了哪一条」。

两路分开而不是拼成一路：思考动辄比结论长几倍，混进正文的话用户要读的那句
被埋在自言自语里。界面把思考折起来，**想完自动折**，而用户手动点开过就不再折。

⚠ 思考过程**不落库**，也不进重放。落了的话这个会话每重放一次就把它再喂一遍，
上下文与账单一起翻倍——而模型早在当时就把结论写进正文了。

⚠ 客户端工具的执行**服务端看不见**（它们在浏览器里跑，ADR-0023），所以那几步
由前端就地记进同一条时间线。不记的话，一次绑二十个点在界面上是二十秒的空白。

事件集是闭合的：`message.delta` / `step` / `client_tool.request` /
`turn.done` / `error`。两侧的一致由
`web/app/tests/contract/assistant-shapes.contract.spec.ts` 对着 `events.py` 锁死。

⚠ **`langchain-openai` 会丢掉思考过程**：它明说自己只认官方 OpenAI 规范，
第三方端点加的 `reasoning_content` 一律不提取。`llm/reasoning.py` 覆写它的一个
私有接缝把那一格捡回来——这是本服务唯一一处踩在库的私有 API 上，因为再往上一层
那一格已经没了。库升级改了它的表现是「助手不再会思考」而不是崩，所以有一条
用例直接钉那个方法的签名与行为。

⚠ 边缘那条 SSE location **不能** include `proxy-common.conf`：它的
`proxy_read_timeout 25s` 会在模型还在想的时候把连接掐掉，而现象是「转了半分钟
然后什么都没发生」。同一条 location 里还必须 `proxy_buffering off`，否则事件流
退化成「攒完再一次吐」，"一步一步看得见"这一半就没了。

### 1.3 上下文按需拉取

常驻提示词只有 **648 字**：基本规矩 + 当前工作面 + 技能名录（每个一句话）。
正文由模型自己调 `skills.load` 拉。同理，模块清单、函数目录都是两段式——
先给名片，点名了才展开。

理由是同一个：整份模块清单六万多字符、函数目录五十九个函数，原样塞进去之后
被挤出上下文的正是**技能正文与工具结果**，而表现是助手忽然「忘了」自己刚查到的东西。

唯一常驻的例外是**工作面快照**：这一屏有哪些画布节点、用户此刻选中的是哪一个。
它每一轮都重发（前端在每次推进前现读一遍），因为提示词是一轮一拼的——只在
用户发话那次带的话，助手动过两下之后读到的是一屏过期的画布。

⚠ 选中项在快照里**单拎出来说一句人话**，不是只留一格 `selected_id`。埋在几十个
节点中间的一格 id，模型十次里有三次读不出「用户说的『这个』指的是它」，
而那三次它会去改另一个。没选中时同样要明说——不说的话它会拿上一轮记得的那个当数。

### 1.4 先计划、后执行、边执行边核验（ADR-0024）

多步任务先用 `plan.write`（服务端工具，TodoWrite 式**整份重写**）列出计划再动手，
每完成一项立刻更新。计划落在 `chat_sessions.plan_json`（api 角色无状态，放内存
续跑就丢），每轮渲染进系统提示词且**当前项单独点名**——那一句就是这一步的专属
提示词。快照走第六个 SSE 事件 `plan`（整份下发），前端渲染成逐项打勾的清单。

- `turn.done` 到达而计划未完时，**前端**代用户催一句「按计划继续」，最多 3 次
  （`turnRunner.MAX_PLAN_NUDGES`）；到顶交还给人。催那句以「（自动继续）」开头
  落库为用户消息，回放时按界面说明渲染。
- 布局/外观类计划的收尾项固定是「截图自检」：`dashboard.capture` 看过图、
  不满意就把修正项补进计划，看过才许收尾（compose 技能正文）。
- 纪律管不住的靠入参校验兜底：≤30 项、状态闭合、至多一项 in_progress
  （多出的就地退回待办）。

**工具下发跟着工作面走**（`tool_select.specs_for`）：服务端工具 = 核心档
（`skills.load`、`plan.write`）+ 技能声明档 + 跨模块只读档（点位/大屏/台账/素材
的查询，任何工作面可用）；客户端工具按前端每轮自报的 `client_tools` 过滤——
这一页没实现的，模型看不见。

## 2. 四个技能

| 技能 | 工作面 | 干什么 |
|---|---|---|
| `dashboard-binding` | 大屏编辑器 / 孪生编辑器 | 批量把数据槽绑到采集点位，可带一张点表当参考 |
| `dashboard-compose` | 大屏编辑器 | 摆模块、改配置与外观、对齐排版 |
| `dashboard-review` | 大屏编辑器 / 孪生编辑器 | 截图看版面，给改进建议 |
| `formula-author` | 台账详情 | 写台账公式，验过、试算过再交给用户 |

技能是一个目录：`manifest.py`（名字、简介、适用工作面、要哪些权限码、用哪些工具）
加一份 `skill.md`（正文）。注册走**显式元组**，不靠 import 副作用。

## 3. 点位召回

批量绑点是助手最主要的场景，而它的难点全在召回：

- 后端的 `q` 只对**名字与编码**做子串匹配，且永远顺序扫描。
- 真实现场 **77% 的节点地址是 `i=2253` 这种裸数字**，零语义。
- 真实编码形如 `K1_TMT_HOT_T_PI`，与用户说的「1 号机组热水出口温度」**一个字都不重合**。

所以召回：**一个字都不看 address**；主力信号是中文名，编码经一张工业缩写表
（TT/TMT/PT/DP/FT/LT/AT/SP/PV/…）展开后再比；单位与数据类型参与相容性打分。
按词问不到时**退回全量翻页**，由本地打分兜住。

三条刻意的克制：

1. **得分为 0 的候选一律不返回。** 硬凑几个出来的话，模型会以为「就这些了」
   然后从里面挑一个——那比返回空表难查得多。
2. **打分只排序不取舍**，并把「为什么它排在这」（`why`）一并交给模型：
   选哪一个由它定，因为只有它知道用户这句话的上下文。
3. **点表不落库、不进对象存储。** 存文件要连带一整套生命周期，而这张表的用处
   只有一次——它是这一轮对话的参考资料，不是资产。

## 4. 改配置：读得到才写得对

配置是一只**自由袋子**：写一个清单里没有的键既不报错也不渲染，画面上表现为
「配了没反应」，而配置确实存下去了。所以助手动配置分三层信息，各有各的真源：

| 要知道的 | 从哪来 | 为什么只能是它 |
|---|---|---|
| 这个模块**能配什么** | `modules.catalog(module_type)`（服务端） | 清单是唯一真源，含 itemSchema 与默认值 |
| 这个画布节点**此刻配成什么样** | `dashboard.read_config`（客户端） | 草稿在浏览器里，服务端读到的是上次保存的 |
| 卡片外观**有哪些键** | `dashboard.chrome_keys`（客户端） | `CHROME_KEYS` 只在前端契约里，服务端目录没有这一段 |

⚠ 往数组字段里加一项走 `dashboard.add_config_item` 而**不是** `set_config` 整份
重写：重写会把用户已经调好的单位、阈值、小数位一次冲掉，而画面上看着像加成功了。
新项按 `itemSchema` 填默认再盖上给的那几格——只写提到的两格的话，缺的那些在
渲染侧落回 `undefined`，表现是新指标那一格什么都不显示。

⚠ **配置项与数据行一一对应**。「一块 N 个指标」的模块（实时数值卡、表格、图表）
里，配置的第 i 项喂数据槽的第 i 行。所以「加一个指标」是完整的两步：加配置项，
再给 `itemValues[i].value` 写绑定。只加不绑那一格显示的是「没配来源」而不是空白。

⚠ 删中间一项会让它之后每一行的绑定都改喂前一项——工具在返回里明说了这件事，
技能正文也要求删完重读绑定。

### 4.1 不接点位的那几种槽

`dashboard.write_binding` 的 `source_kind` 分 `opcua`（实时点位）与 `static`
（常量）。助手**只写这两种**：`archive` / `dataset` 还要跟一份取数范围
（时间窗、台账列身份），少给一格的绑定存得下去、永远取不到数——那与「台账里
这一格确实是空」长得一模一样。

⚠ 常量不许写 `null`：取数那一层把 null 读成「没配过」，画面上是「取不到」
而不是空值，而助手会以为自己配好了。`0` / `false` / `''` 都是合法常量。

⚠ 换来源时**沿用同一条绑定**（直接再写一次），不要先解绑再绑：绑定 id 是实时
推送的关联键，解了再绑会断一次。这条口径两个工作面共用一份
（`features/ai/bindingSource.ts`），各写一遍就一定会漂。

## 5. 正文渲染

助手的回答按 markdown 写，前端**自己解析**（`features/ai/markdown.ts`），
产出的是结构、由模板渲染成文本节点。

⚠ 不引渲染库、也没有一处 `v-html`：市面上的渲染器都产出 HTML 字符串，接进 Vue
就得走 `v-html`——那是本仓明令拦住的一个 XSS 落点，而助手正文里随时可能夹带
用户点位名带来的 `<`、或者模型复读回来的一段 HTML。

⚠ **没闭合的代码围栏照样成块**：流式逐字出字时，```` ```json ```` 后面那一段在
收全之前一直是没闭合的——按「不成块」处理的话，用户会看着一段 JSON 先以纯文本
刷出来、收尾时再整体跳成代码块。

⚠ 链接的协议**白名单放行**，不在名单里的降级成纯文字：`javascript:` 写进 `href`
点下去会执行，而它看起来与普通链接一模一样。

## 6. 截图

`dashboard.capture` 是客户端工具，用 `html-to-image` 出一张 1280 宽的 PNG。

- 图**不放在工具消息里**：OpenAI 兼容口径只认用户消息里的图片块，塞进工具消息
  多半被整条丢掉，表现是模型说「我没看到图」而调用明明成功。工具消息回一句
  「图在下一条」，图另起一条用户消息。
- 图**不落库**，库里存的是一句 `[截图]`。全存下来的话，一个看过几次图的会话
  每次重放都要把它们再喂一遍，上下文与账单一起翻倍。技能正文因此明说：
  **看完当场把结论写成文字，下一轮它只看得见占位。**
- 只有带图的那一轮走**视觉档**模型。整个会话都走的话，一次截图之后每句闲聊
  都按视觉计费。
- **三维模块（孪生视图）走快照替身**：渲染器不开 `preserveDrawingBuffer`——
  为一次截图给所有 3D 场景开着它是拿每帧性能换一次按钮，不换。改为每个场景
  在 `@dt/three-core` 的快照登记处登记「先画一帧、当场拷进 2D 画布」的快照
  （WebGL 的后备缓冲在下一帧就被清了，必须同一个任务里取），截图前用替身
  临时顶掉 WebGL canvas，截完恢复。某处快照失败（上下文丢了 / 画布被污染）
  就让那一块空白，不让整张截图失败；技能正文交代模型把残余空白读成
  「这一次截取失败」而不是「漏配了」。

## 7. 台账页与大屏页的分界

大屏编辑器改的是草稿，一次 Ctrl+Z 撤得掉，所以助手**直接改**。

台账页**每一次写入都是真实落库、没有撤销栈**，所以助手只有一个写动作，
而它写的不是库、是一张待用户确认的**提议卡**：点「填进编辑器」把表达式带进弹窗，
**保存仍由人按**。

⚠ 预填连**来源**一起切成「公式」。只填表达式的话，这一列仍是人工录入，
保存下去那条公式一次都不算，而界面上看着一切正常。

## 8. 身份与权限

三道闸之外，助手自己不额外开口子：

1. 边缘 `auth_request` 注入七个 `X-Auth-*` 签名头。
2. 助手**原样转发**这组头去打 platform。签名覆盖的是
   `user_id|role|permissions_b64|expires_at` 的拼接，不含 path 也不含目标服务，
   所以转过去就验得过；而 platform 按**用户自己的**权限码判定。
   **助手因此不是绕过权限的通道**——它读不到用户本来读不到的东西。
   ⚠ 必须逐字原样：解析成 UUID 再转回会归一化，验签当场失败。
3. 权限码只有一个：`assistant:use`。

## 9. 可卸载

某些现场根本部署不了 AI。卸载分三层，任一层成立都是**干净地不出现**，
而不是出现一个点了报错的按钮：

| 层 | 怎么关 | 效果 |
|---|---|---|
| 编译期 | `web/app/src/main.ts` 不调 `installAiAssistant()` | 适配器不注册，`aiPorts()` 恒空 |
| 部署期 | 编排里不起 `ai-assistant` | 能力探测失败 → 入口不出现 |
| 账号 | 不给 `assistant:use` | `PermGuard` 挡住入口 |

⚠ 探测失败一律读成「这套部署没有助手」，不是「暂时故障」。

模型本身也是可缺席的：`ASSISTANT_MODEL_ENABLED=false` 时服务照常起、
能力面回「没接模型」。但**开关打开却不配密钥 = 启动即失败**——密钥类绝不给默认值，
而「起来之后每次对话才报错」比起不来难查得多。

## 10. 模型接入

代码里**不认任何厂商名**：端点、模型名、超时全从配置来（`config-and-secrets §6`）。
默认指向阿里百炼的 OpenAI 兼容端点，换供应商是改一行配置。

思考过程一类的开关在 OpenAI 兼容口径里没有标准字段、各家用自己的键，
所以它是一格**透传的请求体**（`ASSISTANT_MODEL_EXTRA_BODY`，JSON 对象），
而不是代码里的一条分支。逐字流式由 `ASSISTANT_MODEL_STREAM` 控制——留成配置
只为一种场合：个别端点在带工具时不支持流式，那时表现是一条 400。

调用外面包一层断路器。**哪一档失败该让它打开，是这一层最要紧的判断**：

- 超时、连不上、限流、5xx = 「下游此刻不行」→ **打开**，短路能省下白等的时间。
- 401 / 403 / 400 = 「我们自己配错了或发错了」→ **绝不打开**：断路器一开，
  真正的原因就被盖成「暂时不可用」，而那会让人去查网络。

⚠ 这一层**不重试**。一条链路只有一层负责重试，而那一层是编排层。
