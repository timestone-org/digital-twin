# 按钮控件模块（`action-button`）— 设计

大屏上第一个**控件**类模块：它不显示任何数，唯一的作用是「点一下，上抛一次
联动事件」。显隐、弹窗、跨屏跳转由大屏级联动规则决定，模块本身不认识其中任何一种。

它补上了 [DASHBOARD_NAV_DESIGN](DASHBOARD_NAV_DESIGN.md) §8 留下的那句话——
在此之前，想要一个「看起来就是按钮」的入口只能拿 `text-block` 加卡片外观凑。

---

## 1. 为什么值得一个独立模块

一个能点的东西必须**长得像能点**：底色或描边、圆角、悬停与按下反馈、禁用态，
是一整套而不是把一段文字框起来。文本块能做到的只有"框起来"，剩下的每一样都缺。

更要紧的是这些是白拿的，只要渲染的是原生 `<button>`：

| 要的东西                     | 原生 button | 文本块 + 整块可点                         |
| ---------------------------- | ----------- | ----------------------------------------- |
| Enter / Space 触发           | 有          | 宿主自己补（`ModuleRenderer` 的 keydown） |
| 焦点环与 Tab 次序            | 有          | 要自己写 `tabindex`                       |
| 读屏读成「按钮」             | 有          | 要自己写 `role`                           |
| 禁用语义（不可聚焦、不触发） | 有          | 没有                                      |

⚠ 类型 id 是 `action-button` 而不是 `button`。守「运行时与编辑器里零模块类型
字面量」的两道闸按**已注册的 type** 逐个 grep 源码，而模板里到处是
`type="button"` / `role="button"`：叫 `button` 会让闸门红在十几处无关的属性上，
消掉它们只能给闸门开豁免——而那正是闸门守着的东西。

## 2. 目录与文件

```
web/packages/modules/src/modules/action-button/
├── manifest.ts       清单：30 个配置字段 + 3 套外观预设，零绑定槽
├── options.ts        取值表（风格/语义色/轮廓/图标/排布/动效），清单与渲染共用一份
├── look.ts           配置 → 形态：类名、CSS 变量、外层排布，纯函数
├── Component.vue     原生 button 的模板与一次上抛
└── _variants.scss    五档风格、切角、悬停与按下、辉光与呼吸
```

`look.ts` 与 `_variants.scss` 不是洁癖：单文件组件 ≤500 行是闸门
（[code-style-typescript](agents/code-style-typescript.md) §3），三十个旋钮摊在
组件里必然超。收成纯函数还有一个实际好处——夹取与哨兵语义能被独立单测，
挂载组件去断言 `--btn-font-size` 既慢又看不清断的是哪一条。

## 3. 联动：模块只上抛，不解释

```ts
// 配了联动值就带上，没配就抛一个不带值的点击
emit(
  "interaction",
  value === "" ? { event: "click" } : { event: "click", value },
);
```

| 联动动作                                           | 要不要联动值 |
| -------------------------------------------------- | ------------ |
| 显示 / 隐藏 / 切换显隐、弹窗、关闭弹窗、跳转到大屏 | 不要         |
| 按值跳转大屏、按值互斥切换                         | 要           |

清单只开 `emitsInteractions`，**不开 `hostClickable`**。两个都开的话，按钮周围
的空白也能点，而且同一次点击会上抛两遍——`toggle` 类动作当场自我抵消
（这正是 `metric-card` 要有条件吞冒泡的原因，按钮压根不进那条路）。

按钮**不显示** `meta.interactive`：展示类模块要靠它决定"配了规则才像能点"，
而按钮的可点是它的本性，没配规则时点了没反应属于配置没写完，
在编辑器右栏的联动页当场就能看见。

### 3.1 这一版没有「开关式按钮」

一个记着自己是开是关的按钮，状态只存在它自己身上：另一条规则（或另一个按钮）
改了同一批目标的显隐，按钮的亮/灭就与屏上实际情况对不上了，而且**不报错**。
互斥选择那件事有它自己的形状——分段切换控件配 `setActive`，
进场还能靠 `InitialSelection` 重放一次，让开屏状态就成立。按钮不做这件事。

要「点一下显示、再点一下隐藏」，用动作 `toggle`：真相在运行时的显隐覆盖态里，
按钮不需要记住任何东西。

## 4. 配置面

| 组   | 字段                                                                        |
| ---- | --------------------------------------------------------------------------- |
| 内容 | 文案、副文案、图标、图标位置、悬停提示                                      |
| 行为 | 联动值、禁用                                                                |
| 外观 | 风格、语义色、自定义主色、文字色、轮廓、圆角/切角、描边粗细、辉光、辉光半径 |
| 文字 | 字号、字重、字间距、图标字号                                                |
| 排布 | 尺寸、水平位置、垂直位置、左右内边距、上下内边距、图标间距                  |
| 动效 | 悬停反馈、按下反馈、呼吸提示、呼吸周期                                      |

三套外观预设（一次浅合并落库、一步撤销）：**主行动**（实心主色+辉光）、
**科技切角**（斜面+切角+扫光）、**次要描边**（中性胶囊）。
预设存在的理由与页头那套相同：有些观感是十几个字段的组合，逐个照抄必漏。

### 4.1 五档风格 × 语义色

风格是底色与描边的组合（实心 / 柔和 / 描边 / 幽灵 / 科技），语义色是**一个**
主题变量（`--accent-primary` / `--state-success` / …）。样式表里只认
`--btn-accent` 一个变量，所有派生色走 `color-mix`——换肤与换语义色因此都只动那一处。

⚠ 预警档的文字色是深色（`--text-inverse`）而不是 `--text-on-emphasis`：
黄底上的浅字读不出来。这一档与 `DtButton` 的口径逐字相同。
⚠ 自定义主色推不出对比色，实心档默认压深色字；配浅色主色时用「文字色」显式覆盖。

### 4.2 两个哨兵

- **图标字号 `0` = 跟着文字字号走**（1.2 倍）。配一次字号图标就跟着缩放，
  而不是每次都要记得同时改两处。
- **留空的颜色不注入变量**：`--btn-text` 只有配过才写，否则各档风格自己的
  缺省（实心压深色字、其余取主色）才回落得到。

### 4.3 尺寸：充满模块 vs 按内容

出厂是**充满模块**——拖节点矩形就是改按钮大小，所见即所得。
「按内容」那一档由字号与内边距撑开，再用水平/垂直位置摆进矩形里，
用于在一块空白上放一个不占满的入口。

⚠ 只摆图标（文案与副文案都空）时四边一律取上下内边距：不收横向内边距的话，
一枚图标会被撑成扁矩形。

### 4.4 切角与四角刻线

切角走 `clip-path`，削掉**左上与右下**两个角；科技风的四角刻线因此画在
**右上与左下**——画在被削掉的那两个角上会被一起削掉，只剩两截莫名其妙的短线。

⚠ `clip-path` 会把描边一起裁掉，所以切角档的斜边上没有描边线。那是这一档
本来的样子（HUD 风格的常见做法），不是缺陷。

### 4.5 动效：悬停与按下是两件事

触摸屏上没有悬停。只配悬停反馈的大屏，在触摸屏上按下去是**没有任何反馈**的，
所以按下反馈单独一档、出厂就开（下沉 1px）。

⚠ 两者会同时命中同一个 `transform`。按下那几条排在悬停之后——同特异度靠后者胜出，
按住时看到的才是"按下去"而不是"浮起来"。

「呼吸提示」走一层独立的环（`::after`），不占 `box-shadow`——那是"辉光"的位置，
两者要能同时开。`prefers-reduced-motion: reduce` 下扫光与呼吸都停。

## 5. 为什么退出平台卡片外观

清单里 `chrome: 'bare'` + `chromeConfigurable: false`：按钮自己画完整外观，
再套一层平台卡片框就是两层边框，而且卡片的圆角与按钮的胶囊/切角对不齐。
`NodeCommonPanel` 早就按这个标记决定要不要摆外观表单——按钮是它的第一个使用者。

## 7. 这一版不做

- **二次确认**。联动动作眼下全是显隐与跳转，撤销成本约等于零；等按钮能下发写值
  的那天，确认框与幂等键要一起进来，那是另一件事。
- **开关式（记住自己开/关）**。理由见 §3.1：状态会与屏上实际情况静默对不上。
- **按数据决定能不能点**。禁用是常态置灰。要按实时值挡住入口，用联动规则控制显隐——
  一个"看得见但点不动且不说为什么"的按钮比不显示更糟。
- **一块摆一排按钮**。按钮组是导航条/分段切换的形状，它们各自该是自己的模块；
  眼下一块一个、用容器排布，够用且不引入新的对齐语义。
