# 注释规范：Python

适用于本仓所有 Python 服务。TypeScript / Vue 见 [`comment-style-typescript.md`](comment-style-typescript.md)，两份文档的原则一致，只是落到各自语言的写法。

## 这份文档要解决的问题

注释有两种坏法，方向相反：

- **臃肿**：注释在源文件里堆成小作文——架构理由、迁移记录、"改造前 / 改造后"的叙事——读代码得先分辨哪几段说的是现状。
- **过简**：只剩一行 `# 处理数据`，等于没写；真正会绊倒人的隐式契约反倒没人记。

修法不是删掉知识，而是**把每一条知识放到它唯一该在的地方**，代码里只留一个指针。下面的规则都服务于这一条。

## 唯一的判定规则：注释只做四件事

要写的注释若不属于以下四类，就别写——那说明代码本身该讲清楚。

| # | 类别 | 篇幅上限 |
|---|---|---|
| 1 | 模块 docstring——这个文件是什么 | 1–3 行 |
| 2 | 函数/方法 docstring——一句话 + 参数名 | 一句话 |
| 3 | 常量与行内——一个名字，不是一句解释 | 半行 |
| 4 | 反直觉的坑——用到的那一行上方 | 1 行 |

超过上限的内容，一律进 `docs/*.md` / `<service>/docs/adr/` / `CONTEXT.md`，代码里留一行指针。

## 怎么算"适量"

不要背比例，用信号判断。

**注释不足的信号**（该写而没写）：

- 要跳到别的文件才知道某个参数装的是什么
- 出现了没有名字的魔数
- 存在隐式契约（调用必须有先后、缓存必须由某个特定调用方失效、字段登记了但还没接线），漏掉会**静默失效**而不是报错
- 写法反直觉：看着该用 A 却用了 B，且理由不在函数体里

**注释过量的信号**（该删）：

- 注释与紧邻的下一行同义
- 某个函数头上的注释比函数体还长
- 连续三行以上的散文段落
- 同一件事在设计文档和代码里各写了一遍
- 类型标注已经说清楚的，又用文字复述一遍

**量化参考**（只作嗅探，不是指标）：单文件注释行占比通常落在 5%–15%。逼近 0 一般是缺了模块 docstring 和坑位注释；超过 25% 一般是把设计文档抄进了代码。

## 1. 模块 docstring

说清这个模块做什么。真正的设计理由（为什么是这个形状、维持了什么不变量）不要内联，指向已有或应有的文档。

```python
"""数据台账 ORM 模型 —— 从点位历史按周期聚合出来的业务派生层。

设计与不变量见 docs/DATASET_DESIGN.md。alembic env.py 通过 import * 收集
本文件元数据，故须维护 __all__。
"""
```

第二段那句是**当前约束**（不维护 `__all__` 会导致迁移漏表），不是历史叙述，所以它该留。

手工维护的 `Author` / `Email` / `LastUpdate` 头块一律不写——`git log` 与 `git blame` 已经准确回答了，而且不会过期。

## 2. 函数与方法

一句话说清做什么，再按名字列出参数，这样读的人不必回头看签名就知道作用域里有什么。只有当名字本身讲不清它装了什么时，才在名字后面补一个短句。

不要写 `Returns:` / `Raises:` 段，不要写用法示例，不要写成段落。

```python
def resolve_effective(table_id: uuid.UUID, key: str) -> float | None:
    """取一个台账格的生效值：overrides 优先，否则落回 values。

    Args: table_id, key。
    """
```

名字不自明时才补短句：

```python
def rebuild_window(anchor: datetime, span: str, *, strict: bool) -> list[Sample]:
    """重建一个聚合窗口的样本序列。

    Args: anchor（窗口右端，闭区间）, span, strict（缺样时抛错而非补零）。
    """
```

**类型标注已经说过的，不要再用文字说一遍**。这是 Python 侧最常见的臃肿来源：

```python
# ❌ 类型已经写在签名里了
def load(path: Path) -> Config:
    """加载配置。

    Args:
        path (Path): 配置文件的路径，类型为 Path。
    Returns:
        Config: 返回一个 Config 对象。
    """
```

**平凡函数不需要注释**：无参数、或只有一个自明参数且函数体只有一行的，直接不写。`is_open()` 上面不需要挂一句"返回是否打开"。property、`__repr__`、纯转发的 `@staticmethod` 同理。

**类的 docstring** 与函数同规格：一句话说清它代表什么。字段逐个加注释是 3 类的活，不是在类 docstring 里列一遍。

## 3. 常量与行内

需要标注时给一个短名字，不是一句解释。

```python
MAX_RETRY = 3          # 最大重试次数
ARCHIVE_TICK_S = 10    # 归档心跳周期
```

行内表达式同理，只在不自明时标：

```python
cutoff = now - timedelta(days=retention_days)  # 保留期左边界
```

## 4. 反直觉的坑

能阻止一个具体且不显然的错误的警告，值得在**用到的那一行上方**占一行，沿用 `⚠` 前缀。完整解释若超过约两行，解释进文档、代码留指针。

```python
# ⚠ retention_days 仅登记不生效，清理调度器见第 6 期；见 docs/DATASET_DESIGN.md
retention_days: Mapped[Optional[int]] = mapped_column(...)
```

```python
# ⚠ 必须在 client_pool 建好之后调用：seed 会按池内已连接的会话分片
await seed_points(session)
```

要写的是**当前约束及其后果**，不是它的来历。跨文件、跨包的隐式契约属于这一类，必须写清楚漏掉会怎样——这类是功能注释，不是过程注释。

## 直接删掉，不要搬家

- 复述下一行的注释（`# 计数器加一` 配 `count += 1`）
- 注释掉的死代码
- **变更史叙事**——"改造前是 X，现在是 Y""原先 / 曾经 / 本轮新增 / 旧实现"。git 已经记着了，而且下一次提交落地时这句话就是错的。
  - ✅ `# 不能复用外层 session：归档批次要独立事务，失败不能回滚采集写入`
  - ❌ `# 之前这里复用了外层 session，后来发现会连带回滚，改成新建`
- 设计文档已经写过的内容，只要 §1/§4 的指针在位就删

**测试名同理**：写这条用例断言的是什么契约，不写"回归自某次修复"。

```python
# ✅
def test_effective_prefers_override_over_value(): ...
# ❌
def test_fix_issue_42_regression(): ...
```

## 绝对不动——这些不是散文，是给工具的指令

- 静态检查指令：`# noqa`、`# type: ignore`、`# pragma: no cover`
- shebang、编码声明、许可证/版权头
- `TODO` / `FIXME`——它们跟踪的是待办，不是叙事，保留（最好带上 issue 编号）
- SQLAlchemy 等 ORM 的 `comment=` 参数——那是库表元数据，会进 DDL，不是源码注释

## 落笔前的自检

1. 这句话属于四类里的哪一类？都不属于就别写。
2. 它是不是在复述代码或类型标注已经说过的事？
3. 它讲的是**现状**还是**来历**？来历删掉。
4. 它超过篇幅上限了吗？超了就挪进文档、留一行指针。
