# 测试规范：Python

适用于本仓所有 Python 服务。TypeScript / Vue 见 [`testing-standard-typescript.md`](testing-standard-typescript.md)，两份的分层、覆盖率口径、闸门策略一致，只是落到各自工具链。

本规范按**公网发布的生产系统**要求编写：任何人在任何时间点从主干拉代码构建出的产物，都应当是可以直接对公网提供服务的。测试是这个承诺的唯一执行机制。

## 0. 工具链基线

| 项 | 取值 |
|---|---|
| Python | ≥ 3.12 |
| 包与环境 | `uv`（`uv.lock` 必须提交并锁定） |
| 测试框架 | `pytest` ≥ 9 |
| 异步 | `pytest-asyncio`，`asyncio_mode = "auto"`（无需给每个协程测试加装饰器） |
| 覆盖率 | `pytest-cov` ≥ 7 |
| 测试内数据库 | `aiosqlite`（仅限单元层，见 §6.3 的硬性限制） |
| 格式化 | `black`，line-length 80 |
| 类型 | `pyright` |
| 测试目录 | `testpaths = ["tests"]`，`pythonpath = ["."]` |

## 1. 测试分层

四层，职责不重叠。每一层都必须能**独立运行**，且不依赖上层。

### L1 单元测试 —— `tests/unit/`

单个函数、类、纯逻辑模块。不碰网络、不碰真实数据库、不碰文件系统（`tmp_path` 除外）、不碰时钟。

必须是**毫秒级**。整层跑完应在 30 秒内。

### L2 集成测试 —— `tests/integration/`

跨组件的真实装配：ORM 打到真实 Postgres/TimescaleDB、Redis 打到真实 Redis、FastAPI 走 `httpx.ASGITransport` 完整走一遍中间件与依赖注入。

外部**第三方**系统（OPC UA 服务端、对象存储、上游 HTTP API）用受控的假件或本地容器，不打生产、不打任何他人控制的地址。

### L3 契约测试 —— `tests/contract/`

锁定跨模块、跨服务、跨进程的隐式约定——**违反时不会报错、只会静默出错**的那些。这一层是本仓的重点，因为这类缺陷类型检查和 lint 都拦不住。

必须有契约测试的典型：

- API 响应体结构与前端消费口径（字段名、可空性、时间格式、数字精度）
- 数据库迁移前后的 schema 兼容性
- 权限码字符串、事件/消息的 topic 名与载荷形状
- 序列化/反序列化的往返（`pack(unpack(x)) == x`）
- 枚举值的持久化字面量（改一个枚举名不能悄悄改变库里已存的值）

### L4 端到端 —— `tests/e2e/`

真实进程、真实依赖、从 HTTP 入口打到数据库落库。只覆盖**关键用户路径**，数量控制在两位数以内。E2E 慢且脆，它证明的是"接起来了"，不是"逻辑对"——逻辑对是 L1 的事。

### 分层配比

参考值：L1 : L2 : L3 : L4 ≈ **70 : 20 : 7 : 3**。倒挂（E2E 比单元还多）是明确的设计问题，不是测试问题。

## 2. 布局与命名

```
<service>/
├── apps/...                       ← 被测代码
└── tests/
    ├── conftest.py                ← 全局 fixture，只放真正全局的
    ├── unit/
    │   └── dataset/
    │       └── test_evaluator.py  ← 镜像被测模块路径
    ├── integration/
    ├── contract/
    ├── e2e/
    └── factories/                 ← 测试数据构造，不放断言
```

- 文件名 `test_<被测模块>.py`，目录结构**镜像**被测代码的包路径。
- 测试函数名写**断言的契约**，不写来历：
  - ✅ `def test_effective_prefers_override_over_value()`
  - ✅ `def test_blank_condition_yields_unknown_not_false()`
  - ❌ `def test_fix_issue_42()` / `def test_bugfix_regression()`
- 一个测试**一个断言主题**。需要连写五个不相关的 assert，说明它其实是五个测试。
- 参数化优先于复制粘贴：`@pytest.mark.parametrize`，并给 `ids=` 起可读的名字，失败时能直接看出是哪一档。

## 3. 必测清单

以下情形**没有测试就不允许合并**，不接受"太简单了"或"手工验过"：

1. **任何 bug 修复** —— 先写一个能复现的失败测试，再修。测试必须在修复前红、修复后绿。这是回归测试的唯一来源。
2. **所有错误路径与异常分支** —— 只测 happy path 等于没测。上游超时、返回畸形数据、数据库唯一键冲突、并发写入，都要有对应用例。
3. **所有边界** —— 空集合、单元素、上限值、上限 +1、负数、零、`None`、超长字符串、非 ASCII。
4. **所有鉴权与授权判定** —— 见 §7。
5. **所有输入校验** —— 每个 Pydantic 模型的拒绝路径至少一条。
6. **所有数据库迁移** —— upgrade 与 downgrade 都要跑通，且 upgrade 后旧数据仍可读。
7. **所有并发与顺序约定** —— 竞态防护、幂等性、"必须先 A 后 B"的调用顺序。
8. **所有对外契约的变更** —— 改 API 字段、改枚举值、改消息载荷，先改契约测试。

### 明确**不需要**测的

`__repr__`、纯转发的一行包装、纯配置常量、自动生成的迁移文件骨架、第三方库本身的行为。为凑覆盖率给这些写测试是负资产。

## 4. 覆盖率要求

### 4.1 分级阈值

覆盖率**必须开分支覆盖**（`branch = true`）。只看行覆盖会把未测的 `if` 分支算成已覆盖。

| 层级 | 行覆盖 | 分支覆盖 |
|---|---|---|
| 核心域逻辑（求值器、权限判定、聚合、协议编解码） | ≥ 95% | ≥ 90% |
| 应用服务与 API 路由 | ≥ 85% | ≥ 80% |
| 适配器（DB、OPC UA、对象存储、HTTP 客户端） | ≥ 70% | ≥ 60% |
| **仓库整体闸门** | **≥ 80%** | **≥ 75%** |
| **本次改动的增量覆盖** | **≥ 90%** | **≥ 85%** |

**增量覆盖是最硬的一条**。整体数字有历史包袱、变化迟钝；新写的代码没有任何借口。用 `diff-cover` 对着 merge-base 算。

### 4.2 棘轮：只许上不许下

整体覆盖率**不允许下降**。CI 比对目标分支的基线，低于基线即失败——哪怕仍在 80% 阈值之上。这条防的是"大量新代码稀释旧的高覆盖"。

### 4.3 ⚠ `--cov=` 必须用点号模块名

这个坑会**静默**给出偏高且无人察觉的覆盖率：

```bash
# ✅ 点号模块名
uv run pytest tests/ -q --cov=apps.dataset.formula --cov-report=term-missing

# ❌ 路径形式：coverage 静默跳过，报 module-not-imported，数字虚高
uv run pytest tests/ -q --cov=apps/dataset/api/formula.py
```

CI 里必须校验 coverage 输出中不含 `module-not-imported` 警告，否则闸门形同虚设。

### 4.4 配置

写进 `pyproject.toml`，让本地与 CI 口径一致——阈值不写在命令行里，避免两处漂移：

```toml
[tool.coverage.run]
branch = true
source = ["apps"]
omit = [
    "*/migrations/*",
    "*/alembic/*",
    "*/__main__.py",
    "*/conftest.py",
]

[tool.coverage.report]
fail_under = 80
show_missing = true
skip_covered = false
exclude_also = [
    "if TYPE_CHECKING:",
    "raise NotImplementedError",
    "@overload",
    "\\.\\.\\.",
]

[tool.coverage.xml]
output = "coverage.xml"
```

### 4.5 豁免

单行豁免用 `# pragma: no cover`，且**必须在同一行或上一行写明理由**。整文件豁免必须走 `omit` 配置并在 PR 描述里说明。无理由的 `pragma` 在评审中直接打回。

## 5. 覆盖率不等于测试质量

覆盖率只证明代码**被执行过**，不证明它**被验证过**。一个没有 assert 的测试可以拿到 100%。以下是覆盖率之外的硬要求。

### 5.1 禁止的写法

- **无断言测试** —— 只调用不检查。
- **同义反复** —— `assert result == compute(x)`，用被测逻辑本身算期望值。期望值必须是**手写的字面量**。
- **过度 mock** —— 把被测对象的协作方全 mock 掉，测的就只剩 mock 的配置。mock 只用于**进程外**依赖。
- **断言实现细节** —— 断言私有方法被调用了几次。重构一改就红，属于噪音。
- **互相依赖的测试** —— 依赖执行顺序或共享可变状态。必须能 `-p no:randomly` 之外任意乱序执行。
- **条件跳过掩盖失败** —— `pytest.skip` 只用于环境能力缺失（如"本机无 Postgres"），不用于"这条一直失败"。

### 5.2 变异测试

核心域逻辑（§4.1 第一档）**每季度或每次重大改动后**跑一轮变异测试，验证测试是否真的能抓住错误。存活的变异体要么补测试，要么书面说明为何不值得（如：无公开入口、加锁需为测试改公开接口）。

> ⚠ **安全铁律**：本仓工作区常年有大量未提交改动。变异流程**绝对不允许**用
> `git checkout` / `restore` / `stash` / `reset` 还原变异体——会直接抹掉未提交的工作。
> 正确做法：`cp` 到临时目录备份 → 施加变异 → 跑测试 → `cp` 回来 → **立刻复跑确认全绿**。
> 事后独立核验还原结果（如 `inspect.getsource` 逐个断言变异点形态），不采信过程自述。

### 5.3 测试即文档

测试文件头按 [`comment-style-python.md`](comment-style-python.md) 的模块 docstring 规格，一到三行**锁定这个文件在守什么契约**。

## 6. 确定性与隔离

不稳定的测试比没有测试更糟——它训练所有人忽略红灯。

### 6.1 禁止不确定输入

- **时间**：不允许 `datetime.now()` / `time.time()` 直接进被测路径。时钟通过依赖注入传入，测试里给固定值。涉及时区的必须显式带 tz，不依赖运行机器的本地时区。
- **随机**：随机源注入，或固定 seed。
- **UUID**：内容寻址用 `uuid5`（确定性）；`uuid4` 必须可注入。
- **并发调度**：不用 `sleep` 等待异步完成，用显式的事件/条件变量或 `asyncio` 的同步原语。

### 6.2 禁止外网

测试进程**不允许发起任何真实外网请求**。CI 中应主动阻断，让越界的测试直接失败而不是偶发超时。

### 6.3 数据库：SQLite 只够 L1

`aiosqlite` 在 dev 依赖里，可用于 L1 的快速验证。但**L2/L3/L4 必须打真实 Postgres + TimescaleDB**。

理由是硬的：归档层用 TimescaleDB 超表与宽表，还用到 JSONB、窗口函数、`ON CONFLICT`、时区语义。这些在 SQLite 上要么不存在、要么行为不同。**在 SQLite 上全绿的迁移和查询，可以在生产上直接失败**——这类"测试通过但线上炸"是公网发布最不可接受的失败模式。

每个测试用例必须自带隔离：事务回滚或独立 schema，用例之间不共享残留数据。

### 6.4 零容忍 flaky

测试偶发失败一律按 **P1 缺陷**处理：当天定位根因，修不了就**删掉或标记 `xfail(strict=True)` 并挂 issue**，不允许留在主干靠重跑通过。CI 不配置自动重试——重试会把不确定性藏起来。

## 7. 安全相关必测（公网发布前提）

本仓服务面向公网，以下每一条都必须有**自动化**测试，不接受人工核对。

### 7.1 认证与授权

- 无 token、过期 token、伪造签名、算法混淆（`alg: none`）——每种都要有拒绝用例。
- **越权访问**：A 用户的 token 去读写 B 用户的资源，必须 403/404，且**不泄漏资源是否存在**。
- **权限码判定的默认值**：⚠ 鉴权端点必须**先认证再查规则**，"查不到权限码"绝不等于"匿名放行"。这条必须有专门的测试锁死：空权限码 → 拒绝。
- WebSocket 的鉴权路径单独测：token 在子协议里传递时，普通 HTTP 头的鉴权中间件不生效。
- 提权路径（如管理员自升）的每一步都要有测试，包括中途失败不留下半升状态。

### 7.2 输入与注入

- SQL 注入：所有拼接过 SQL 的位置必须有恶意输入用例（ORM 参数化不等于全仓无裸 SQL）。
- 路径穿越：一切由用户提供的文件名/对象键，测 `../`、绝对路径、NUL 字节。
- SSRF：任何由用户提供 URL 的出站请求，测内网地址、`localhost`、云元数据地址（`169.254.169.254`）必须被拒。
- 反序列化：不允许 `pickle` 处理外部输入；有则必须有测试证明其被拒。
- XSS：返回给前端的富文本经过 `nh3` 清洗，需有测试覆盖典型 payload。

### 7.3 资源与拒绝服务

- 上传体积上限、请求体上限、分页上限、公式/表达式的递归深度与长度上限——每条都要有超限被拒的用例。
- ⚠ 递归深度尤其重要，且**上限的归属必须按调用方算**：几个入口共用一个求值函数时，把深度上限记在被共用的那一侧，会让某个入口的实际深度不受限而无限递归——`RecursionError` 直接把一个页面打成 500。这类上限必须在**每个调用方**的口径下各有一条用例。

### 7.4 机密

- 测试中**不允许出现真实凭据**。CI 跑机密扫描（`gitleaks` 或等价物），命中即失败。
- 日志与错误响应不得回显密钥、token、完整连接串——需有断言。

## 8. 性能与容量

不要求做完整压测，但以下必须有自动化下限保护：

- **关键查询的复杂度回归**：核心列表/聚合接口在 N=10⁴ 量级数据下的响应时间设上限断言（宽松取值，只抓数量级劣化，如 N+1 查询）。
- **N+1 检测**：核心路径断言 SQL 执行次数不随结果集条数增长。
- 大数据量的流式/分页路径必须有测试，禁止一次性全量载入内存。

## 9. CI 闸门

> ⚠ **CI 必须在第一个服务对外提供服务之前建立。** 在那之前，上述所有阈值都只是约定——而只是约定的阈值等于没有阈值。

合并到主干前，以下检查**全部**必须通过，任一失败即阻断（不允许管理员绕过合并）：

| 闸门 | 命令 | 失败即阻断 |
|---|---|---|
| 格式 | `uv run black --check .` | ✅ |
| 类型 | `pyright` | ✅ |
| 单元 + 集成 + 契约 | `uv run pytest -q` | ✅ |
| 整体覆盖率阈值 | `--cov --cov-fail-under=80` | ✅ |
| 覆盖率棘轮（不低于基线） | 与目标分支基线比对 | ✅ |
| 增量覆盖 ≥ 90% | `diff-cover coverage.xml --compare-branch=origin/main --fail-under=90` | ✅ |
| `module-not-imported` 检查 | 扫描 coverage 输出 | ✅ |
| 依赖漏洞扫描 | `uv run pip-audit` 或等价物 | ✅ 高危 |
| 机密扫描 | `gitleaks detect` | ✅ |
| 迁移可逆性 | upgrade → downgrade → upgrade | ✅ |

E2E 与变异测试不进 PR 闸门（太慢），进**每日定时**流水线，失败开 issue。

### 本地命令速查

```bash
# 全量
uv run pytest -q

# 带覆盖率（注意点号模块名）
uv run pytest -q --cov=apps --cov-branch --cov-report=term-missing

# 只跑一层
uv run pytest tests/unit -q

# 单个文件 / 单条用例
uv run pytest tests/unit/dataset/test_evaluator.py -q
uv run pytest tests/unit/dataset/test_evaluator.py::test_blank_is_unknown -q

# 乱序验证测试间无耦合
uv run pytest -q -p no:cacheprovider --random-order
```

## 10. 定义完成（DoD）

一处改动算完成，当且仅当：

1. 新增/修改的行为都有对应层级的测试，且测试名说明的是契约。
2. 若为缺陷修复，存在一条修复前必红的用例。
3. 增量覆盖 ≥ 90%，整体覆盖率未下降。
4. 错误路径、边界、鉴权分支均已覆盖。
5. 无新增 `skip` / 非 strict 的 `xfail` / 无理由的 `pragma: no cover`。
6. 全部 CI 闸门绿灯，且**未使用重试**。
7. 若改动触及跨模块契约，契约测试已同步更新，且更新在实现之前。
