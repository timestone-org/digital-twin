# 阜阳空压系统大屏与推荐发布

「空压系统」大屏沿用同一项目「光伏 · 智慧运维」的主题、页头、页脚和数字读数样式。顶部显示当前估算总产气量、储气母管压力、主机总功率和冷却辅机功率。下方通栏逐台对照当前开机和 OPC UA 推荐状态。现场核验母管需气量点位后，可作为独立的总览指标接入。系统气电比需四台机组流量、主机功率和两路冷却辅机功率均具备计量。

## 点位与历史

KEPServer 的 `DL.KY` 提供空压站压力、部分实际转速和冷却读数，`DL.PD` 提供主辅机有功功率。按真实 NodeId 读取并确认类型和质量后，在采集页面复用已有点位或新增点位，启用归档。输出使用 `juanbaochucheng` 实例中已有的 `RECOMMEND_KYJ1` 至 `RECOMMEND_KYJ4`，读侧单独通过 OPC UA 数据源采集这四个节点。

1#、2#、3# 的开机反馈读取 `ns=2;s=DL.KY.KY_DI_KYJ1_RUN` 至 `ns=2;s=DL.KY.KY_DI_KYJ3_RUN`。4# 本地大屏根据实测有功功率 `DA111_4_P` 判定开机状态，功率达到 2.0 kW 判为运行，低于 2.0 kW 判为停机。状态未知时显示空心圆。

4# 阈值以历史实际转速大于零作为运行参照。在 2026 年 8–9 月的 87,039 条稳态分钟记录上比较 1–9 kW 的整数阈值。1 kW 与 2 kW 的不一致记录同为 22 条，采用 2 kW 留出更大的零点裕量。在 10 月全部 44,609 条记录上独立核对，其中 44,522 条一致（99.80%）。阈值配置在 4# 状态槽，计算为 `round(max(功率, 0) × 0.25)`，零对应停机，正值对应运行。对照区用绿色实心圆表示运行或建议运行，用同样大小的红色实心圆表示停机或未推荐。

2#、3# 已归档的累计点位 `KY_CO2_KYJ2_FT_LJ` 与 `KY_CO2_KYJ3_FT_LJ` 及原差分列可用于历史核对。累计表倍率需用表计确认。1# 和 4# 的累计流量、4# 实际转速和母管需气量待核验。历史文件中的瞬时流量不应作为累计读数导入。

四台机组现场气电比分别读取 `ns=2;s=DL.KY.KY_KYJ1_QDB` 至 `ns=2;s=DL.KY.KY_KYJ4_QDB`。导入大屏组态前，须将四个点位登记在 KEPServer 数据源下并启用归档。点表未注明气电比工程单位，大屏显示点位原值，产气估算暂按 m³/kWh 换算。4# 已采集的冷却水出水温度与露点可在点位归档查阅。

历史样本用采集服务的 [`scripts/import_history.py`](../server/services/collector-server/scripts/import_history.py) 追加。CSV 使用 UTF-8，表头为 `point_code,ts,value_num`，每行一个数值点位，时刻明确带时区。阜阳历史文件的北京时间按 `Asia/Shanghai` 转为 UTC。导入程序先核对采集计划和整个文件，再逐批按归档主键幂等追加。相同时刻原有样本优先。此入口归采集服务所有，平台对 `collect` schema 继续只读。

```shell
python scripts/import_history.py /path/to/verified-history.csv --source-id <数据源UUID>
python scripts/import_history.py /path/to/verified-history.csv --source-id <数据源UUID> --apply
```

## 图表及校准

[大屏组态](../examples/fuyang-compressed-air/dashboard.json) 使用原生页签切换空压系统总览与四台机组，默认打开 2#。四个机台页签按相同顺序显示有功功率、排气压力、现场气电比与估算瞬时产气，并为四项指标各画一条趋势。估算瞬时产气由同一台机组的现场气电比乘以实时有功功率，再除以 60。当前值随实时点位推送更新，输入缺失时估算留空。

[分钟台账](../examples/fuyang-compressed-air/dataset.json) `fuyang_air_minute_live` 仅包含大屏所需的 20 列。它汇总同一分钟的气电比和功率，估算产气趋势取两个分钟均值的乘积，再除以 60。两项均有记录时才计算，曲线从气电比和功率均有归档的时段开始。功率、排气压力和现场气电比趋势也读取分钟台账，储气母管压力趋势读取点位归档。历史查阅窗口可在组态面板调整。

4# 的出口实测流量和实际转速来自 `KYFT.csv` 和 `KYZS.csv`，日期覆盖北京时间 2026 年 8 月 1 日至 10 月 31 日，可在历史台账查阅。`fuyang_air4_history_minute` 留存 132,446 条对齐的原始记录和原始时刻，`fuyang_air4_history_hourly` 留存 2,208 个小时均值，均值按实际存在的样本计算并包含有效零值。

推荐 worker 每 15 分钟用最近 120 天的实测历史拟合曲线。标定台账各有 `flow_1`–`flow_4`（m³/min）、`power_1`–`power_4`（kW）、`pressure_1`–`pressure_4`（MPa）和 `rpm_2`–`rpm_4`（r/min）列，使用与报告一致的实测流量、功率、排气压力及转速。程序筛掉缺测、低负荷、压力不合格和变化过快的样本。1# 取定频代表工况，2# 至 4# 按转速档取流量和功率的中位数。默认每档至少 60 个样本，且来自至少三个自然日。追加实测历史后，下一次标定会从台账读取新样本。

## OPC UA 推荐

在 `platform-worker` 通过 `PLATFORM_COMPRESSED_AIR` 配置 JSON。`estimated_flow_points` 按 1# 至 4# 排列四组 `power` 和 `site_qdb` 点位，`calibration_table_id` 指向历史标定台账，`opcua_instance_id` 与 `recommendation_node_ids` 指向同一实例内按机号排列的四个布尔输出。可选 `recommendation_status_node_id` 写到一个独立的字符串节点。将大屏顶部「当前总产气量（估算）」绑定到该字符串的采集点位，可显示本轮采用的总量及无建议时的原因。可选 `available_node_keys` 按机号指定可用状态。`calibration_days`、`minimum_samples_per_band`、`calibration_pressure_min` 和 `calibration_pressure_max` 可覆盖默认值。

程序每轮将四台机组的 `现场气电比 × 实时有功功率 ÷ 60` 相加，以当前估算总产气代表供气负荷。输入来自在线数据源，八个点位都须属于当前采集租约且数据质量良好，停机零值参与合计。程序在历史曲线支持的范围内枚举可用组合，在满足同一目标流量的情况下选择估计主机功率最低的方案。辅机功率在总览单独显示。任一输入无效或目标超出标定范围时四个输出均为 `False`。有效组合中的机组写入 `True`，批量回执逐项核对。输出仅供运行参考，启停和保护由现场控制系统负责。

兼容部署可选择 `demand_node_key` 作为单点输入，并通过 `machines` 绑定旧的累计归档标定。每台旧配置含 `volume`、`power`、`pressure`，变频机加 `speed`，累计表倍率使用 `volume_scale`。总量输入和单点输入二选一，实测台账和旧机组归档标定二选一。配置留空时停用推荐循环。

后台依赖已有采集快照、在线运行态、只读归档和 OPC UA 内部批量写接口。worker 持独立 Redis 租约，不依赖打开大屏。发生写超时只记录结果未确认，下一拍计算新建议。四个 bool 本身无法表达写入时间或通讯异常，上位机若要使用其当前有效性，需要另行结合通讯质量和业务有效性判断。

## 阜阳部署

阜阳现场部署跟踪 `codex/fuyang-compressed-air`。先把 `origin/main` 需要的修改合入该分支，将同一个提交推送到主仓库和现场 Gitea，再用现场现有更新器部署该提交。现场源目录与更新器的 `Branch` 指向同一分支。发布前保留现有应用版本、持久化存储及大屏备份。旧大屏沿用现有数据和原有 ID，新空压系统大屏作为独立组态导入。

首次接入时登记已核验的现场点位，建立 20 列分钟台账以及独立的 15 列历史标定台账 `fuyang_air_calibration_history`。旧大屏台账继续使用已有列。将新屏的点位和台账绑定重映射到现场身份，并将顶部总产气卡片绑定到推荐状态字符串的采集点位。推荐 worker 使用现有 OPC UA 实例中按机号排列的四个布尔点。验收时核对旧屏和新屏读取、两张新台账的列数及标定样本范围，并从 OPC UA 原生端点回读四个布尔值。
