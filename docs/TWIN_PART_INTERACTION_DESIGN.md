# 孪生部件交互设计

> 一切配置都收在**部件**上：远距点击切视角，近距点击弹出一个只装这个部件的弹窗。
> 原来的「层级钻取」（`hierNodes` 一棵独立的树）已整体移除，不做迁移。

## 1. 为什么去掉层级钻取

钻取是一棵与部件**平行**的树：厂区 → 车间 → 设备各是一个 `hierNode`，各自带
关联节点、取景、字段与摘要，而部件只用 `clickHierNode` 指过去一条边。它带来三份
重复与一处必然漂移：

- **两套「关联 3D 节点」**：部件有 `nodes`，钻取层也有 `nodes`（还额外发明了
  「留空 = 取子孙并集」这一档），同一块几何在两处各登记一遍。
- **两套字段与两个绑定槽**：`panelValues` 与 `hierValues` 形状完全相同，只是挂在
  不同实体上；用户要在两个地方学同一套「按扁平化后的文档序对齐」。
- **两栏大纲**：左栏为它单开一个「层级」页签，而那一栏的拖动改的是 `parent`/`order`，
  与大纲行号（= 绑定对齐位次）**不是**一回事——摆在一起必然被当成同一件事。

现场真正要的只是「点一个设备，看它的读数」。那件事部件自己就能表达。

## 2. 现在的模型

一个部件上有两档点击动作，分界是 `clickDistance.farThreshold`：

| 档 | 触发 | 可选动作 | 缺省 |
|---|---|---|---|
| 远档 | 相机距离 > 分界 | `approach` 把它框进画面 / `view` 飞到指定取景 / `none` 不响应 | `approach` |
| 近档 | 相机距离 ≤ 分界，或没配分界 | `detail` 弹出详情弹窗 / `none` 只上抛联动 | `none` |

另有两条门禁：`min` 近于它不响应、`max` 远于它不响应。**三条阈值各自带参考系**
（`orbit` / `self` / `part-center`），脱离参考系的裸数字不可类比。

- **没配分界就没有远档**：`farThreshold` 为空时每一下都算近距点击，配好的远距取景
  永远飞不到。这一条由诊断 `part-far-unreachable` 报出来。
- `far: 'view'` 的目标：`click.view`（编辑器「取当前机位」存的快照）优先，
  没有就退回 `click.cameraId` 指的预设视点；**两者都没有时退回 `approach`**——
  远距点击彻底没反应的话，用户看不出是少配了一样东西。这一条由诊断
  `part-focus-no-target` 报出来。
- 近档的联动事件**两档都照发**：弹详情是附加动作，不是替代，否则给部件配上详情
  会把同屏别的模块的联动静默掐掉。

## 3. 详情弹窗

近距点击弹出的是一个 **Modal**（`DtModal`，Teleport 到 body），里面两块：

```
┌──────────────────────────────────────────────┐
│ 1# 冷水机组                              ✕   │
│ 地下二层                                     │
├──────────────────────┬───────────────────────┤
│                      │  出水温度   7.2 ℃     │
│    ▨ 只有这一个部件   │  负荷      ▇▇▇ 68%    │
│      （可转可缩放）   │  状态      ● 运行     │
│                      │  趋势      ▁▂▃▅▇      │
└──────────────────────┴───────────────────────┘
```

**左边那块 3D 是另一套场景**，不是把主画布挪过来：它自己起渲染器与相机，把这个
部件的对象克隆一份、烘进祖先变换、摆到原点再框住。所以「只看这一个」不需要去动
主场景的显隐与材质，关掉弹窗也没有任何要还原的东西。

- ⚠ 克隆件与画布上那份**共用几何与材质**。释放时只许收自己造的那几样（灯光、
  控制器、渲染器），绝不能走 `disposeSceneGraph`——那会把主场景正在用的几何与
  材质一并释放，表现是大屏上那个部件整块消失，而弹窗已经关了、没有线索指回来。
- ⚠ 克隆要把**祖先的变换烘进去**：`clone()` 只带自己那一层的 position/rotation，
  挂在别处的部件会以模型原点为准摆放，看着像「模型跑到画面外去了」。
- ⚠ WebGL 上下文有硬上限：开一次弹窗多一个，关掉必须 `forceContextLoss`，
  否则来回点几次部件之后最早的那个会被浏览器静默回收，主画布毫无征兆地黑掉。
- ⚠ 换配置时主场景会重建部件材质，弹窗里克隆的那份随之作废——所以宿主在
  `refreshLayers()` **之后**立刻按新配置对账（`detail.sync`），弹窗按新的部件引用
  整份重来。顺序反了就是接着画一块黑。

右边是数据卡片：字段复用信息牌那一套 `TwinPanelField`（八种画法、阈值档、量程），
换形在 `detailPanelOf`（`@dt/twin-config`），运行态卡片与编辑器字段列表共用它。
标题与副标题**不进卡片**——它们已经写在弹窗自己的头上。

可配置的有：标题 / 副标题、画不画模型、模型自转、模型区高度、弹窗宽度、
卡片风格变体、主题色、字段列数，以及字段本身。

绑定走 `partFieldValues` 槽，键 `<部件 id>::<字段 key>`，与信息牌各数各的行号。
⚠ 字段一律占绑定行，与 `click.near` 配成什么**无关**：按动作过滤会让用户在下拉里
翻一下就把这个部件已经绑好的点位整片丢掉。配了字段却不弹窗由诊断
`part-detail-unreachable` 报出来。

## 4. 移除清单（没有迁移）

`TwinHierNode` / `TwinConfig.hierNodes` / `hierValues` 绑定槽 / `TwinPart.clickHierNode`
/ 钻取面板与卡片 / 左栏「层级」页签与它的树操作 / 三条钻取诊断 / 场景搜索里的
「层级」类目，以及只被钻取节点用过的图标选择件，全部删除。存量配置里的
`hierNodes` 归一化时直接丢弃，它们的 `hierValues[i]` 绑定随之作废，需要在部件
详情上重新配字段并重绑。
