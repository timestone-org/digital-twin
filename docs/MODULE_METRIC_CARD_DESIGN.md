# 实时数值模块（`metric-card`）— 设计

大屏上「看一眼现场此刻是什么数」的主力模块：一块摆 1..N 个点位读数，
带单位、四段带阈值与**逐格**状态交代。它是本仓第一个数据模块，
也是模块系统那条判据（[DASHBOARD_DESIGN](DASHBOARD_DESIGN.md) §5：
新增一个模块 = 一个目录 + 一行注册）在数据类模块上的第一次兑现。

---

## 1. 为什么是「一块 N 个指标」而不是「一块一个点位」

一屏二十个读数是常态。做成一块一个点位的话，用户要拖二十个模块、
配二十遍标题字号、单位、阈值与卡片外观，而它们本该长得一模一样；
改一次观感要改二十处，漏掉的那一处没有任何提示。

所以指标列表是**配置**，读数是**数组绑定槽**，行与指标一一对应：

```
config.items[i]        ← 这一格叫什么、什么单位、几位小数、阈值在哪
binding itemValues[i]  ← 这一格的读数从哪来
```

行数由配置决定，不由绑定条数决定（`bindingRowCounts`）。这与数字孪生的锚点
是同一套口径，所以**绑点面板与孪生完全一致**——同一个 `BindingPanel`，
同一种"第 3 行叫什么"的行标签，同一条"绑一部分实体是常态"的规矩。

⚠ 一条随之而来的规矩：**删掉中间一项指标，它之后每一行的绑定都会改喂前一个
指标**。绑定的 `fieldKey` 是按下标拼的（`itemValues[2].value`），下标是列表里的
文档序。属性面板的字段说明里写了这一条，删完请核对绑点面板。

## 2. 目录与文件

```
web/packages/modules/src/modules/metric-card/
├── manifest.ts      清单：13 个顶层配置字段 + 11 个行内字段 + 1 个数组绑定槽
├── metrics.ts       取值逻辑（纯函数）：归一化、四档状态、阈值、展示文本
├── Component.vue    壳：三种排布的容器，只管摆位置
└── MetricCell.vue   一格：名称、读数、单位、状态点、更新时刻
```

拆成四个文件不是洁癖，是闸门：单文件组件 ≤300 行
（[code-style-typescript](agents/code-style-typescript.md) §3）。
更重要的是 `metrics.ts` 里全是纯函数，能被独立单测——
四档状态与阈值边界这类逻辑，挂载组件去测既慢又看不清断的是哪一条。

## 3. 绑定槽

```ts
{
  key: 'itemValues',
  label: '指标读数',
  dataType: 'number',
  isArray: true,
  isEntityPinned: true,
  arrayFields: [{ key: 'value', label: '读数', dataType: 'number' }],
}
```

四点说明：

- **`isEntityPinned: true`**——行钉在指标上，允许索引留空。绑一部分指标是常态
  （配了 10 个指标先接 3 个），空出来的行只表示「这一格还没接数据源」。
  列表式数组槽必须索引连续，这一档不必；服务端据这个标记分流
  （DASHBOARD_DESIGN §4.2）。
- **`dataType: 'number'`** 只影响 `static` 常量那一档的输入控件长什么样，
  **不过滤可选点位**（`BindingSourceEditor.vue`）。所以开关量与文本指标照样
  绑得上 opcua 点位。
- **没有 `isRequired`**——一格都没绑时模块画的是「未绑定」的格子，
  而不是被整格浮层盖住。
- **没有 `isTimeSeries`**——这一版不画趋势。要画的时候得先补运行态的历史
  provider：`bindingReader.ts` 现在对 `archive` 一律诚实拒绝。

**将来接别的数据源，这个模块一行都不用改**：绑定层对来源无感知，模块只消费
求值后的 `values` 与 `meta.slots`。加一种来源 = 在 `BindingSourceKind` 联合里
加一个成员 + 注册一个 provider（DASHBOARD_DESIGN §5.5）。

## 4. 配置面

属性面板是 `configSchema` 泛型渲染的，本模块没有一行专属表单代码。

### 4.1 顶层字段

| 键              | 标签       | 类型       | 缺省           | 分组 | 何时露出                   |
| --------------- | ---------- | ---------- | -------------- | ---- | -------------------------- |
| `title`         | 标题       | string     | `''`           | 内容 | 留空则不画标题栏           |
| `items`         | 指标       | array      | 一项           | 内容 | 每一项在绑点面板上是一行   |
| `layout`        | 排布       | enum       | `auto`         | 排布 | `auto` / `grid` / `list`   |
| `columns`       | 列数       | range 1–6  | `2`            | 排布 | `layout=grid`              |
| `density`       | 疏密       | enum       | `normal`       | 排布 | 紧凑 / 标准 / 宽松         |
| `align`         | 格内对齐   | enum       | `left`         | 排布 | `layout∈{auto,grid}`       |
| `valueSize`     | 读数字号   | range 0–96 | `0`            | 文字 | `0` = 跟着排布走           |
| `labelSize`     | 名称字号   | range 8–32 | `12`           | 文字 |                            |
| `valueColor`    | 读数颜色   | color      | 跟随卡片正文色 | 文字 | 命中阈值的格子改用严重度色 |
| `grouping`      | 千分位     | boolean    | `false`        | 文字 |                            |
| `emptyText`     | 无数据占位 | string     | `—`            | 文字 |                            |
| `showStatusDot` | 状态点     | boolean    | `true`         | 状态 |                            |
| `showUpdatedAt` | 更新时刻   | boolean    | `false`        | 状态 |                            |

### 4.2 每一项指标（行内字段）

| 键            | 标签     | 类型      | 缺省     | 何时露出               |
| ------------- | -------- | --------- | -------- | ---------------------- |
| `label`       | 名称     | string    | `''`     | 留空显示「指标 N」     |
| `kind`        | 值的类型 | enum      | `number` | 数值 / 开关量 / 文本   |
| `unit`        | 单位     | string    | `''`     |                        |
| `precision`   | 小数位   | range 0–6 | `1`      | `kind=number`          |
| `trueText`    | 真值文案 | string    | `运行`   | `kind=boolean`         |
| `falseText`   | 假值文案 | string    | `停止`   | `kind=boolean`         |
| `dangerBelow` | 危险下限 | number    | **无**   | 留空 = 这一侧不判      |
| `warnBelow`   | 预警下限 | number    | **无**   | 同上                   |
| `warnAbove`   | 预警上限 | number    | **无**   | 同上                   |
| `dangerAbove` | 危险上限 | number    | **无**   | 同上                   |
| `key`         | 联动值   | string    | `''`     | 留空则这一格点了不上抛 |

⚠ 四条阈值边界**刻意不给缺省**：给了就等于每个新指标出厂自带一条告警线。

### 4.3 三种排布

- **`auto`**：只有一项时是单格大字居中（远远看一眼就是这个数），
  多项时按项数自动铺列（≤4 项两列、≤9 项三列、再多四列）。
- **`grid`**：列数听配置的。
- **`list`**：每项一行，名称在左、读数在右。

三种排布**都渲染每一项**。「配了却不渲染」是本仓明令要避开的那类静默失效——
所以没有「只画第一项」的档。

### 4.4 阈值：四段带

四条边界而不是一张规则表，是因为工控现场的阈值几乎总是"下下限／下限／
上限／上上限"这四条，而通用规则表（运算符下拉 + 区间上界）在每项十几个
字段的行内表单里既占地方又难填。四条边界在内部翻译成
[`shared/thresholds.ts`](../web/packages/modules/src/shared/thresholds.ts)
的规则表，引擎是同一套。

- 优先级：两条危险排在两条预警前面，同时越界时报危险。
- 每一档带一句文案（`过低` / `偏低` / `偏高` / `过高`），画在状态点旁边。
  ⚠ 只有颜色是不够的：色弱的人、以及打印出来或投到墙上的截图，
  看不出越的是哪一侧。
- **开区间**：`warnAbove: 80` 是「超过 80 才预警」，正好等于 80 不预警。
  写成闭区间会让「上限就是 80」的工况一直挂着黄灯。
- 阈值一律拿**原始数值**判，与展示档无关：所以开关量的 `0` 也能触发红灯
  （`dangerBelow: 1`）。
- **没配边界就连「正常」都不说**——我们没有判据。状态点只画给配过边界的格子。
- **没有读数时一律不着色**：凭空一个绿灯等于宣布"一切正常"，而这时候我们
  根本没有值。

## 5. 渲染行为

### 5.1 一格的四档，逐档各说各的话

| 档        | 什么意思             | 格子里画什么                                      |
| --------- | -------------------- | ------------------------------------------------- |
| `unbound` | 这一格没配数据来源   | 占位符 + 「未绑定」                               |
| `pending` | 配了，还没收到第一帧 | 占位符 + 「等待首帧」                             |
| `error`   | 配了，取不到         | 占位符 + 「取不到」（危险色），完整原因挂 `title` |
| `ok`      | 有读数               | 读数 + 单位（+ 状态点 / 更新时刻）                |

⚠ **合成一档是不行的**。这三种没有读数的处置办法完全不同：去配绑定、
再等一会儿、去查现场。合成「暂无数据」之后，三条路一条都看不出来。

⚠ **单位只在 `ok` 档画**：「— kV」看着像是有读数的。

⚠ **`0` 是读数不是空**。这条贯穿整个 `shared/format.ts`：缺值渲染「—」，
绝不伪造 0——墙上的「0」与「没数据」长得一样时，停机与归零就再也分不出来。

### 5.2 为什么运行时不能替它盖状态浮层

`ModuleStatusOverlay` 的既有口径是：非正常态**整格盖住**并说明原因。
这个假设对一格一个点位的模块成立，对多点位模块是灾难——十个指标里有一个
采集器断了，`tally.error > 0` 就会把整块盖成「取数失败」，另外九个明明有值
却一个都看不见。等首帧那一档同理。

解法不是在运行时里写 `if (type === 'metric-card')`（那是 DASHBOARD_DESIGN
§5.3 陷阱 ③ 明令禁止的，第三方的多点位模块永远得不到这条待遇），
而是**加一条清单声明**：

```ts
ownsStatusDisplay: true; // 逐格状态我自己交代，别盖我
```

运行时只读声明。`unbound` 那一档仍归浮层——必绑槽一条都没配时，
模块连布局都摆不出来，让它自己画等于画一片空白。

### 5.3 逐槽结论怎么到模块手里

模块光看 `values` 分不出上面那四档：没配来源、没首帧、取不到，在注入袋里
长得一模一样（键都不存在）。而渲染 props 是**固定三件套**，不许扩第四个。

所以走 `meta`：

```ts
ModuleMeta.slots?: Readonly<Record<string, ModuleSlotMeta>>
// ModuleSlotMeta = { state: 'ok' | 'pending' | 'error', message?, timestampMs? }
```

键是 `fieldKey`（`itemValues[0].value`）。只在模块自报 `ownsStatusDisplay`
时下发：其余模块读了也没有地方画。

`timestampMs` 逐槽各带各的，而不是共用整块那个 `meta.valueTimeMs`——
后者是这批值里**最新**的一个，多指标模块里「哪一格不动了」正是要靠各自的
时刻才看得出来。

### 5.4 更新时刻显示到秒

`HH:mm:ss`，不是到分钟。本仓的点位周期低到 10 秒，按分钟显示时
「还在动」与「一分钟前就停了」是同一个字样，而这一列存在的全部意义就是
分开这两件事。

⚠ 它只是**照实显示采样时刻**，不参与任何"多旧算旧"的判断。值有多旧不构成
一档状态：订阅只在值变化时回调，一个一天变一次的点位按年龄判会每天被误标
23 小时（DASHBOARD_DESIGN §4.3）。真读不到时快照键会到期，落进 `error` 档。

### 5.5 联动

- 每项可配一个「联动值」，点这一格上抛 `{ event: 'click', value }`。
- 清单同时开了 `hostClickable`（整块可点由宿主接管）。
- ⚠ 格内点击**有条件地**吞冒泡：配了联动值就吞（否则同一次点击会再被整块那条
  兜底抛一个没有 `value` 的 click，toggle 类动作当场自我抵消）；没配联动值就
  放它上去，那时整块那条才是这次点击唯一的落点。

## 6. 顺带修掉的一处静默失效

`ConfigField.when`（条件显示）此前**只在顶层字段生效**：`ArrayControl` 与
`ObjectControl` 都直接 `v-for` 了 `itemSchema` / `fields`，从不评估 `when`。
后果是声明写了、面板照摆——已有的 `thresholdsConfigField` 里那个「阈值上界
只在区间档露出」的声明，一直是失效的。

本次两处都改成按**本行 / 本块自己**的取值判定（铺过行内缺省之后再判，
与顶层 `formGroups` 同一条口径）。不修的话，本模块每项十一个字段无法按
`kind` 收起，开关量的真假文案会出现在数值指标上。

## 8. 这一版不做

- **趋势迷你图**。要么在浏览器里累积实时值（不落库、刷新即清空，必须标注
  「本次打开以来」），要么接 `archive` 历史链路——后者要先补运行态的异步历史
  provider、请求缓存与快切竞态防护，是模块之外的一整块工作。
- **每项独立的完整规则表**（多条规则、区间内外、自定义告警文案的组合）。
  四段带覆盖了绝大多数工况；真需要时再把 `thresholdsConfigField` 铺进行内，
  引擎不用换。
- **设计态的演示读数**。`ModulePreview.values` 在契约里有、在画布上没接
  （`CanvasNode.vue` 只注入 `preview.config`）。所以拖进画布看得到排版与
  示例指标名，读数是一片「未绑定」——诚实，但不好看。补它要给
  `ModuleRenderer` 开一个"未绑定槽注入演示值"的口子，属运行时机制。
