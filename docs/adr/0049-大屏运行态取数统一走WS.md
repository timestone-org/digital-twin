# ADR-0049：大屏实时点位走 WebSocket，历史与台账按需走 HTTP

大屏的实时点位绑定统一由 `platform-publisher` 经 `realtime-hub` 推送，冷启动首帧也走 WebSocket；客户端按稳定点位身份增量合并，不为实时点位保留“断线后偷偷改走 HTTP”的第二口径。新连接获得全量点位帧，之后按变化推送，断线时最后值必须标为陈旧。

点位当前值来自 Redis 快照。采集每次取得租约都用独立令牌，修改快照时在 Redis
原子核对租约，并把写入令牌与原始读数的 SHA-256 记录到独立的逐点位属主哈希。
发布器原子批读当前租约、三字段快照和属主，并以实际读数核对证明，批量只读采集运行态。
数据源未确认在线、当前租约或属主缺失、或属主核对失败，都在原推送主题上保留读数
并标记陈旧。

归档窗口、台账和其它按需查询仍由各自 provider 通过 HTTP 获取。编辑态预览也可走专用 HTTP。
