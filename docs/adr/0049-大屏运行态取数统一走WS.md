# ADR-0049：大屏实时点位走 WebSocket，历史与台账按需走 HTTP

大屏的实时点位绑定统一由 `platform-publisher` 经 `realtime-hub` 推送，冷启动首帧也走 WebSocket；客户端按稳定点位身份增量合并，不为实时点位保留“断线后偷偷改走 HTTP”的第二口径。新连接获得全量点位帧，之后按变化推送，断线时最后值必须标为陈旧。

归档窗口、台账和其它按需查询不属于实时快照，仍由各自 provider 通过 HTTP 获取；编辑态预览也可走专用 HTTP。该边界与当前 publisher 只读取 Redis 点位快照的实现一致，取代旧文“所有运行态绑定都走 WS”的过宽表述。
