# ADR-0031：MCP 只接无状态 HTTP 子集，并默认只读

助手只支持通过 HTTP POST 调用 `tools/list` 与 `tools/call` 的无状态 JSON-RPC 子集，不启动 stdio 子进程，也不承诺 MCP 会话或 SSE 传输。这样生命周期、超时和链路传播仍沿用现有出站 HTTP 模型。

外部工具描述视为不可信数据；工具规范名为 `mcp.<server>.<tool>`，含点号或双下划线的段拒收。只有明确带只读标记的工具默认下发；写工具必须进入本地白名单，并在执行前获得用户明确确认。每个 server 独立断路，连不上时仅该路工具缺席，密钥只走请求头且无默认值。

白名单只代表部署许可，不能替代调用者业务授权。写工具必须另有明确的业务政策和
资源校验器；未知映射及没有确认协议的旧客户端拒绝写入。管理员配置共享模型不会
共享业务用户身份。写确认复用 ADR-0023 的持久待续机制：浏览器显示服务端保存的
目标、参数和影响，通过只绑定本次调用的短期一次性票据明确决定；实际写入仍由
服务端执行。执行前复核当前签名用户、权限、目标及政策，数据库原子领取后在事务外
调用外部工具，并记录实际结果。取消、过期、重放、参数修改和并发重复失败关闭；
外部结果未知时不得自动重试。已在本地声明为写的工具不能被远端只读标记降级。

确认票据及会话回执不替代业务审计。启用涉及 observability §7 操作的写适配器之前，
部署方必须验证其真实业务服务在业务事务内记录实际操作者、时间、类型、对象、
前后值、来源 IP 和 trace_id，并确保审计不可篡改且独立保留；没有验证不得启用。
