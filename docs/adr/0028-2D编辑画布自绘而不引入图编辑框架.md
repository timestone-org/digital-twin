# ADR 0028：2D 编辑画布自绘，不引入图编辑框架

- 状态：已接受
- 日期：2026-08-27
- 影响范围：`web/app/src/pages/Twin2dEditor/`、`web/package.json`（不新增依赖）
- 相关：[MODULE_TWIN_2D_DESIGN §13.2](../MODULE_TWIN_2D_DESIGN.md)、[ADR-0027](0027-2D孪生的节点与连线样式是可配置图元文档.md)

## 背景

2D 孪生编辑器要在一块画布上做这些事：摆节点、连线、拖拐点、画标注、框选、
平移缩放、旋转节点、选中单个图元。这正是 vue-flow 这类图编辑框架的场景，
所以「要不要引入」必须先答。

答案取决于两件事：它能替我们做掉多少，以及引入它本身要付什么。

## 决策

**画布自绘，不引入 vue-flow 或同类框架。**

## 理由

### 一、它能给的与我们要的，交集只有六分之一

vue-flow 给的是：节点拖动、框选、平移缩放、连线手势、小地图、网格背景。

本次需要而它给不了的六样：

| 要的 | 为什么它给不了 |
|---|---|
| 图元树节点渲染 | 节点内部是一棵 `box`/`vec`/`ico`/`txt` 图元树（[ADR-0027](0027-2D孪生的节点与连线样式是可配置图元文档.md)），只能是自定义节点组件 |
| 连线：多遍描边 + 自定义 marker + 沿路径标签 | 它的边是一条 path 加一个可选 label 槽；多遍描边与按弧长定位的标签都要自己画 |
| 端点按周长参数落点 | 它的连接点是离散 Handle，本模型的端口是周长参数 `t` 或归一坐标，位置任取 |
| 标注双层（按 `zOrder` 压在节点上下两层） | 它只有一个节点层 |
| 图元级选中 | 它的选中粒度是节点 |
| 旋转手柄 | 没有 |

六样里五样都要写自定义组件。剩下能白拿的只有平移缩放与框选这类通用手势，
而 `DashboardEditor` 里已有同类实现可照。

### 二、引入侧的隐藏代价在框架之外

- **一个按 `flowId` 建在全局的 store**：必须 `onScopeDispose(() => vf.$destroy())`，
  漏了就是**跨导航泄漏**——子编辑器是从属性面板反复进出的一页，进出几次就攒几份。
- **三条「少了就会在拖把手时平移画布」的必需配置**：`:delete-key-code="null"`、
  `:select-nodes-on-drag="false"`、把手上的 `nodrag nopan` 类名。这三条一条不写代码
  照跑，表现是拖旋转手柄时整块画布跟着跑。
- **坐标口径不一致**：它的节点 `position` 是左上角，而本模型的几何盒以中心为参考
  （旋转、周长参数、吸附都按中心算），每一处进出都要换算一次，漏一处就是差半个节点的偏移。

### 三、决定性的那一条：`as unknown as` 在本仓是红灯

vue-flow 的自定义节点/边组件拿到的是 `NodeProps` / `EdgeProps`，与自己声明的
props 类型对不齐，社区通行解法是 `as unknown as` 断上去。而本仓 eslint 明令打回
这个写法（`web/eslint.config.js` 的 `no-restricted-syntax`：
「as unknown as 一律打回：它把两次类型检查一起关掉了」）。

于是引入侧只剩三条路：给每个自定义组件手写一层运行时校验的适配器（代价高于自绘的
那部分手势）、把断言改写成一堆同样绕过检查的写法（同一件事换个说法）、或者给这个
模块开一条 eslint 例外（为一个可以不引入的依赖破一条全仓规矩）。三条都比自绘贵。

### 四、自绘的实际代价是可数的

| 文件 | 行数 |
|---|---|
| `scripts/viewportOps.ts`（平移缩放、坐标换算、适应） | 282 |
| `scripts/editorSelection.ts`（四条选中轴） | 220 |
| `scripts/snapping.ts`（吸附与参考线） | 215 |
| `scripts/useCanvasPointer.ts`（指针手势状态机） | 199 |
| **合计** | **916** |

外加 `CanvasMarquee.vue` 192 行与 `EditorCanvas.vue` 328 行的视口壳。
按依赖判据「少于 200 行且没有隐藏复杂度就自己写」，这里超过 200 行，
但隐藏复杂度全在**引入**那一侧。

## 后果

- **手势语义由我们自己定，也由我们自己保证**：一次手势只在 `pointerup` 提交一步撤销
  （逐帧提交的话撤销键再也按不回上一步）、拖拽中卸载要补提交一次、把手与选中框按
  当前倍率反着缩回屏幕上的固定尺寸、吸附阈值进来是屏幕像素要换成设计像素。
  这四条都有用例守着——框架不会替我们守，因为框架里根本没有这些概念。
- **卸载必清理是自己的责任**：手势期间挂在 `window` 上的 `pointermove` / `pointerup`
  与视口的 `ResizeObserver` 都要在卸载时摘掉。
- ⚠ **拖节点时连线不跟着走**，松手才归位：节点草稿是节点层私有的，层间没有逐帧通道
  （连线层拿的是文档里的 `nodes`）。补它要把草稿位置提到装配层按帧下发，
  代价是每帧多一次全量连线重算。这一条记在 §3.3，以免被当成缺陷去查。
- **不欠框架的版本账**：没有第二套坐标系、没有第二套选中模型，也不会因为框架升级
  而重新校一遍手势。
- 反过来说，**小地图这类白拿的功能没有了**，要就得自己写；本期不做。

## 备选方案

| 备选 | 不选的理由 |
|---|---|
| 引入 vue-flow | 六样需求里五样要自定义组件，白拿的只有通用手势；而自定义组件 props 几乎必须 `as unknown as`，本仓 eslint 直接打回 |
| 引入并为本模块开 eslint 例外 | 为一个可以不引入的依赖破一条全仓规矩，且例外一旦开出去就会被别处援引 |
| 引入并给每个自定义组件写运行时适配层 | 适配层的量级已经超过自绘掉的那部分手势，还多背一个依赖 |
| 用 `<canvas>` 全量重绘 | 图元树要 `linear-gradient` 多层、`inset box-shadow`、`text-overflow: ellipsis` 这些 HTML 能力（§13.1），全量重绘等于自己写一个排版引擎 |
