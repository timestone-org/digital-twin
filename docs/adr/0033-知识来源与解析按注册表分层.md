# ADR 0033：最外层的扩展点是「知识从哪来」而不是「支持几种格式」；解析产出保结构

- 状态：已接受
- 日期：2026-09-01

## 背景

需求里写的是「可扩展文档解析」，但同一句话后面还有一条：「后期可能不止从文档中获取
知识，还会从其他系统中获取数据」。这两条对架构的要求完全不同：

- 只做前者，扩展点是**一张后缀表**——助手的 `perception/registry.py` 已经是这个形状。
- 加上后者，扩展点必须往外挪一层：外部系统里根本没有「文件」与「后缀」，
  有的是一个 API、一次分页拉取、一行记录。

先做成后缀表再往外扩的代价是：摄取管线已经按「一个文件」写死了（对象存储 key、
文件名、字节流），第二路来源要么复制一遍管线，要么在管线里加一个 `if`。

## 决策

**一、最外层是 `KnowledgeSource`，文件上传只是它的一路实现。**

```python
class KnowledgeSource(Protocol):
    @property
    def kind(self) -> str: ...
    def config_schema(self) -> Mapping[str, Any]: ...
    async def discover(self, config, cursor) -> DiscoveredPage: ...
    async def fetch(self, config, ref) -> RawItem: ...
```

`discover` 报「这一路现在有哪些条目」（带游标，可增量），`fetch` 取一条的原件。
上传那一路的 `discover` 报的是这个库下还没摄取的对象；外部系统那一路报的是
对方接口分页返回的记录。

**二、解析层只认 `RawItem`，不认来源。** 一份原件是「字节 + media type + 文件名」，
不管它是用户传的还是从别人接口拉的。

**三、`DocumentParser.parse()` 产出的是保结构的 `ParsedDocument`，不是一坨字符串。**
一串 `Block`，每块带 `kind` / `level` / `text` / `locator`。

⚠ `locator`（页码、工作表与行号、幻灯片序号、标题路径）**不是可选项**。
解析时丢掉它，后面任何一层都补不回来，而表现是助手答得头头是道却指不出出处。

**四、切块只吃 `Block` 序列。** 加一种格式与改一种切法彻底解耦：加 PDF 就是多一个
`PdfParser`，`HeadingChunker` 一个字都不用改。

**五、认不出的格式当场抛，不做「读得动就收」的兜底。**
兜底会把二进制与图片放进来，解出一堆乱码占满上下文；更糟的是文档状态变成 `ready`
而检索永远查不到它——那与「这份文档里确实没这句话」长得一模一样。

**六、每一层的注册都是显式元组，不靠 import 副作用。**
与 ADR-0029 决策四同一口径：隐式注册让「装了哪些实现」取决于 import 顺序，
而顺序在测试里与生产里可以不同。

## 理由

- **会变的那一维要放在最外面。** 三年后「支持几种格式」大概率还是那几种，
  而「知识从哪来」一定会长出第三路、第四路。
- **`locator` 决定引用能不能落地，而引用决定这个功能有没有用。** 一份指不出出处的
  答案，用户没法核对，也就不敢用。
- **保结构的中间形态是解耦的唯一办法。** 解析器直接产出「块」的话，每个解析器都要
  自己决定怎么切，于是「按标题切」这件事被实现四遍、漂成四种。

## 后果

- 上传那一路要绕一圈走 `discover`/`fetch`，比直接读对象存储多几十行。这是为第二路
  来源预付的成本，而第二路来源在一期就要落地（`DatasetSource`），不是画饼。
- `Block` 与 `locator` 的形状是跨层契约，要有契约测试钉住。
- 一期不认 PDF。加它的代价被这条决策压到「一个文件 + 一行 + 一条用例」。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 只做后缀 → 解析器注册表，来源以后再说 | 摄取管线会按「一个文件」写死，第二路来源要么复制管线要么加 `if`，而那个 `if` 在第三路时变成三个分支 |
| 解析器直接产出「块」 | 「按标题切」会被每个解析器各实现一遍，然后漂成几种；且换切法要改所有解析器 |
| 解析只产出纯文本 | 引用指不到页码/行号，答案没法核对；而这一格丢了之后任何一层都补不回来 |
| 认不出的格式按纯文本兜底 | 状态 ready 但检索不到，与「确实没有」无法区分——这是最难查的一类故障 |
