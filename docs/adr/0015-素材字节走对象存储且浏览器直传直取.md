# ADR 0015：素材字节走对象存储，且浏览器直传直取

- 状态：已接受
- 日期：2026-08-15

## 背景

数字孪生要挑三维模型，大屏要放图片与图标。这些字节的特征与平台里其它数据完全不同：
单个文件可到几百 MB、一次写入之后只读、且需要被现场大屏机匿名取到。

## 决策

**一、字节存 S3 兼容对象存储，不进数据库、不进容器卷。** 单机部署用 MinIO；
访问一律走标准 S3 API，故换成别的实现只改一个 endpoint。

**二、上传是浏览器直传，服务端只签一张凭证。** 服务端签发 POST policy，
把对象键、内容类型与大小区间都签进去由存储端强制；字节从不经过 API 进程。

**三、取回由边缘反代 `/oss/<对象键>`，不走签名 URL。** 三个已验证的前缀
（`models/` `images/` `icons/`）匿名可读，`staging/` 不可读。

**四、业务配置里只许存 `asset:<uuid>` 引用，不许存 URL。**

## 理由

- 字节穿过 API 进程就意味着一个 200MB 的上传要占住一个 worker 几十秒，
  而它做的事只是把字节从一个 socket 抄到另一个 socket。
- 大小闸只在前端拦是拦不住的：绕过页面直接 POST 就能传任意大的文件，
  而服务端在确认之前根本不知道有这回事。签进 policy 才是由存储端强制。
- 直传落 `staging/` 再搬进正式前缀：少了这一步，未验证的字节直接躺在匿名
  可读的前缀下——任何人都能上传任意内容并拿到一个本站域名的链接。
- 签名 URL 不可缓存、且会以字符串形式被存进用户的大屏配置，过期即 404。
- 存 URL 的话，部署地址一换、构建产物一换 hash，存量配置里那条链接就 404，
  而没有任何一处会报错——表现只是「这张大屏的模型不见了」。

## 后果

- 多一个部署单元。它与 PostgreSQL / Redis 同档——**在编排之外**起停，compose 里
  只留一个建桶脚本与边缘那条反代；地址与凭据全部走环境变量。它的数据目录必须与
  数据库同级纳入备份清单：素材没了，存量大屏里的每一个 `asset:` 引用都会变成
  「取不到」。
- 凭据一份值三处用（对象存储的 root 凭据、建桶脚本、platform-server 的签名），
  分叉的表现是凭证签得出来、浏览器一传就 403，而三处的配置单看都对。
- 连接组挂在 platform-server 共用的 `Settings` 上，故 `api` / `worker` /
  `publisher` 三个角色都要给全这四项，哪怕后两个角色一个字节都不读——启动即全量
  校验，少给一处的表现是「api 好好的，抽取与发布全不动」。
- 删素材不做引用检查：逐一扫描配置 JSON 既慢又不完整（引用可出现在任意嵌套层）。
  删掉后大屏那边显示「取不到」，这比让素材库变成只进不出的仓库好。
