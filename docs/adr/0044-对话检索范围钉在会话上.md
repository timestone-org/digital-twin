# ADR 0044：对话的检索范围钉在会话上，默认全部，由工具层硬过滤

- 状态：已接受
- 日期：2026-09-03

## 背景

[ADR-0037](0037-对话引擎并入domain-llmcore.md) 决策三定的是「知识库对话是**跨库**
的：工具带 `base_id`，模型自己挑」。跑起来之后有一类问题它答不了：

用户手上有十几个库（几套设备的手册、几年的规程、一堆台账导出），问「1 号锅炉出口
温度上限」时，模型会先 `kb.list_bases` 再挑一个看着像的库。挑对了没人夸，挑错了
——比如拿 2020 版规程回答 2026 版的问题——**用户看不出来**：答复带着出处，出处
也确实是那份文档，只是那份文档他压根不想要。

他要的是「这次只看这两本手册」。这既是准确性，也是速度：范围小一圈，模型少查
几轮。

## 决策

**一、范围钉在**会话**上，默认全部。**

开会话时不给范围就是全部知识库；输入框上方一个选择器可以改，改了对**这个会话
后续每一轮**都生效，存在会话行上（`kb_chat_sessions.base_scope_ids uuid[]`）。

否掉的两种：

- **每轮独立选**——用户要的是「这次对话谈的是这套设备」，不是逐句声明；每轮都
  摆一次选择器，等于每问一句都要重申一遍上下文。
- **会话级默认 + 本轮临时覆盖**——两个来源的规则，界面上要说清「这一轮为什么与
  上一轮不同」，而它换来的灵活性没人真的要。要换范围就改会话的，一句话的事。

**二、`NULL`（全部）与空列表（一个都没选）必须分得开，从库里一直到界面。**

`NULL` = 不限库；空列表是**非法入参**，在四处各拦一道：数据库 CHECK、入参 schema、
服务层、以及界面上「最后一个勾禁掉、不限库走『全部知识库』那一项」。

分不开的表现是：用户把选择清空了，检索**悄悄扩到了全部库**——而那正是他刚刚
明确排除掉的那些。这类缺陷没有任何一处会报错。

存量会话那一列是 `NULL`，于是天然是「全部」，与本次改造之前行为逐字一致。

**三、范围是**硬过滤**，不是提示词里的一句请求。**

三个工具各自判一次：`kb.list_bases` 只列范围内的，`kb.search` 与 `kb.read_chunk`
越界即抛一句说得清的错（**不是空表**——空表与「这个库里确实没这句话」长得一模
一样，模型会把它读成「查过了，没有」接着往下答）。

只写进提示词的话，模型多数时候听话、偶尔不听，而**不听的那一次没有任何一处
报错**：用户看到的是一条来自他明确排除掉的库的答案。

⚠ 三道里 `kb.read_chunk` 那一道最容易漏。前两个拦住了，模型仍可能拿到一个越界的
`chunk_id`——比如从这个会话更早的历史消息里翻出来的，而它换回来的是**整段原文**。

范围经 `ToolDeps` 逐次传进注册表，不放模块级状态：两个用户的两个回合在同一个进程
里并发跑，模块级的那一份会被后来的那个覆盖。

**四、范围**不是权限**。**

对话面仍然只要 `knowledge:use`（设计 §6 不变）。范围是用户**给自己划的取数边界**，
爱怎么改怎么改、随时能改回全部。写成像权限的样子（另一个权限码、管理员配置、
改不动的只读态）会让两件事都变形：权限是别人给你的，边界是你给自己的。

**五、出参带库名，不是只带一串 uuid。**

`ChatSessionOut.base_scope` 是 `[{base_id, name, is_missing}]`。只回 uuid 的话前端
要么自己再查一遍、要么显示不出人话——而它手上那份库清单是分页的、也会过期。

**六、范围里的库被删了，如实说，不抹掉。**

那一条标成 `is_missing`，界面上写「已不存在」。悄悄从范围里抹掉等于**替用户把
边界改宽了**（抹到最后一个就成了「全部」），而他从界面上看不出来。

同一条理由，那一列**不建外键**指向 `kb_bases`：级联删会把它悄悄抹掉，RESTRICT 又
会让删库失败。范围记的是「用户当时划了什么」，不是一条活引用。

**七、改范围推进 `row_version`，并支持 `expected_version` 断言。**

带了就断言、对不上回 409（`42323`）；不带就是无条件覆盖——改标题那条路本来如此，
为它强行加一格会把既有客户端一次性打断。改范围那一路一律带上：两个标签页开着
同一条会话时，后写的那次会把先写的范围悄悄顶掉。

## 后果

- ADR-0037 决策三的口径改成：**默认跨全部库，可由用户收窄**。「每条召回必须标明
  来自哪个库」那条不变，理由也不变——收窄之后仍然可能是几个库。
- 常驻提示词多了一条**会话级稳定**的注入块（范围那一句），排在常驻段之后、摘要
  之前。第一条系统消息仍逐字不变，故端点前缀缓存照命中；改范围只作废它自己往后
  的那一截（ADR-0025 的分层多了一层，层序不变）。
- 工具层的三道拦截要有用例逐条钉住，尤其 `read_chunk` 那道要在**真库**上验：假
  会话根本走不到「拿到一个越界的块」那一步。
- 一期不做：范围里带上「哪几份文档」（粒度到库就够，文档级的边界要先有文档级的
  权限，见知识库 CONTEXT §5）；也不做「按范围记住上次选了什么」的跨会话默认——
  新对话一律从全部开始，那是最不会出错的缺省。
