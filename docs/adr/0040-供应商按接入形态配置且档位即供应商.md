# ADR 0040：供应商按接入形态配置，助手的档位即目录里的一路供应商

- 状态：已接受
- 日期：2026-09-03

## 背景

[ADR-0039](0039-模型供应商目录由平台持有两端按用途取用.md) 把「按 token 计费的
OpenAI 兼容端点」收进了平台的目录，界面上配得出、两个消费方按用途取用。但订阅
账号那一路（[ADR-0026](0026-助手接订阅账号模型走上游私有面.md)）整个在目录
之外：

- 开关、模型清单、推理档位在 `ASSISTANT_CODEX_*` 环境变量里，改一次要改配置再重启；
- 登录态在助手自己的凭据表上，按写死的字面量 `codex` 认行；
- 模型管理页上它是**单独的一节**，与供应商列表并排摆着，而它其实也是一路供应商；
- 助手侧两路是两个写死的适配器，注册表是一份字面量元组。

于是「这套部署接了哪几路模型」有两个属主：目录管一路，环境变量管另一路。用户要的
是一页里配完：**选供应商类型 → 配这一类要的那几项**。

## 决策

**一、供应商行带上「接入形态」，形态是闭合集合。**

`llm_providers.kind`，两档：`openai_compat`（填端点地址与密钥，阿里云百炼就是
这一种，带一套预填）与 `codex_oauth`（不填密钥，改为在那一行上走一次设备码登录）。
形态决定：要配哪几格、登记得了哪几种模型、哪个消费方接得了它、有没有推理档位可调。
形态自己那几格配置存在 `options_json` 里，按形态校验。

**形态建了不许改。** 改形态等于换一路接法——密钥、登录态与模型清单全部作废，
那是「删了重建」而不是「改一格」。

**二、形态清单由后端下发（`GET /api/v1/platform/llm-provider-kinds`），前端按它渲染表单。**

前端另写一份「这一格该不该摆」的判断，与后端校验迟早分叉，而分叉的表现是
「表单里填了、保存时 422」，那句话指不回是哪一格多余。校验规则本身也只有一份
（`rules.py`），写入面与更新面共用。

**三、助手侧「形态 → 适配器」是一张显式的注册表，目录里开着的每一路各装一个适配器。**

档位名就是那一路供应商的 id。认不出的形态**如实缺席**——平台那边加了一档而这一侧
还没接时，正确的行为是「界面上配得出、助手说这一路我接不了」，不是拿端点那一路的
接法去打一个根本不是那么接的地方。

一路之内**逐档挑模型**：用途分配指到本路时用它指的那个，否则用本路上第一个吃得下
这一档的；挑不出接图模型的那一路如实拒。这是与 ADR-0039 的一处口径变化：看图那一档
从「可以落在另一路上」收成「留在会话选中的那一路里」——跨路的话，会话选的那一路与
真正发出去的那一路对不上，而那种差异只在账单上看得见。

**四、环境变量那两路是**按形态逐格**的永久默认值。**

目录里有了同一形态的供应商就让位，一路都没有时才轮到它。按形态逐格顶替而不是
「目录一非空就全顶掉」——配了一路订阅账号不该把好端端的按量那一路挤没。存量部署
一行配置都不用改：目录里没配任何东西时，两边与 ADR-0039 之后完全一样。

**五、凭据按「哪一路供应商」认行，登录端点的键问注册表。**

`model_credentials` 加一列 `provider_ref`（那一路的 id），`provider` 列改存**种类**。
读侧按 `coalesce(provider_ref, provider)` 认，故环境变量那一路与升级前存量那一行
照旧读得到——**升级之后不用重新登录**。登录端点收到的键认不认得出由注册表回答，
不再是一个写死的闭合集合：写死的话，目录里新配的那一路永远登录不了。

**六、没选过时仍优先包月的那一路。**

目录里给「对话」这个用途分配了就以分配为准；没分配时，可用的那几路里优先要登录的
那一路（订阅是包月的，端点那一路按 token 计费）。说不清走哪一路时挑后者，等于每条
新会话都在替部署方花钱，而那笔账要到月底才看得见。

## 后果

- 全仓多一份「跨三处的形态码契约」（平台 / 助手与 llmcore / 前端），加上迁移里
  写死的 CHECK 集合，由 `llm-shapes.contract.spec.ts` 逐字比。加一种形态要动四处，
  且**一定要有一个消费方真接得了它**——光在平台加一档只会让界面配得出、助手说不了话。
- 断路器改成按需生长：档位来自运行期可改的目录，启动时一次建完的话，之后新配的
  那一路会落到兜底那一个上，于是一路挂掉会把别的路一起短路。
- 助手的模型面在目录在时**总是**装得出来（它是启动时装一次的，而目录是运行期可改的）。
- 知识库那一侧接不了订阅型：分配时在平台侧就拦下，而不是放行之后让它静默沿用环境变量。
- 两次迁移都是纯扩展步，没有回填。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 只把 Codex 的开关与模型清单搬进供应商行，档位名仍是写死的两个 | 面板永远只有两档，配了两家按量供应商也切不了；而「哪几路」仍有两个属主 |
| 形态码直接用厂商名（`dashscope` / `codex`） | 形态决定的是**协议与认证形态**不是厂商：一个 `openai_compat` 要能装下所有兼容端点，否则每接一家都要改代码（config-and-secrets §6） |
| 订阅账号的登录态搬到平台，随目录一起下发令牌 | 令牌要在每次调用前可续期，而目录是 10 秒 TTL 的快照；平台还要另起一套设备码流程与单飞续期，而收益只是少一处跨服务的界面调用 |
| 会话行上存「供应商 id + 模型名」两格 | 面板上选的是「走哪一路」，模型由那一路的用途分配定；多存一格等于让界面上的选择与目录的配置在同一件事上打架 |
