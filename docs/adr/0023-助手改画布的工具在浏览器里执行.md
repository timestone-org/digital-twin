# ADR 0023：助手改画布的工具在浏览器里执行，服务端只跑模型循环

- 状态：已接受
- 日期：2026-08-25

## 背景

`ai-assistant` 是架构里预留已久、唯一未建的代码单元（[ARCHITECTURE §8](../ARCHITECTURE_MICROSERVICES.md#8-建设顺序)）。
它的头号场景是**批量绑点**：一屏几十个数据槽位，人工要在挑点弹窗里搜几十次，
是全系统里最繁琐、重复度最高的一段配置工作。

大屏组态的接口本来就是照着「将来由 Agent 来配」设计的
（[ADR-0012](0012-大屏组态以节点为可寻址资源而非整文档替换.md)、
[DASHBOARD_DESIGN §3.1](../DASHBOARD_DESIGN.md)）：节点与绑定各自可寻址、
id 永不改变、写错就 400 指到字段、模块清单服务端可发现。

但这些接口全部作用于**已落库的那一份**，而大屏编辑器手里握着的是**本地草稿**：
`useEditorHistory` 的撤销栈、按引用判定的脏标记、10 秒一次的 localStorage 自动
草稿，全都只存在于浏览器里。孪生子编辑器同理，且它的撤销栈是另一套实现。

## 决策

**一、工具按「谁持有那份状态」分成两类。**

- **服务端工具**在 `ai-assistant` 进程里跑：点位检索、Excel 解析、公式校验、
  模块清单查询。它们要密钥、要 IO、要处理大数据。
- **客户端工具**下发到浏览器、由编辑器执行：读画布、截图、加模块、改配置、
  改几何、写绑定、排版。它们操作的那份状态只存在于浏览器里。

客户端工具一律落到已有的 `EditorActions` → `editorDoc.ts` 纯函数 →
`editor.apply(change, mergeKey)`。

**二、协议是 POST + SSE，循环由客户端驱动。**

服务端跑模型；需要客户端工具时把调用发出去并**结束本次流**，待续状态落在
`chat_steps.state = 'awaiting_client'` 上；浏览器执行完再 POST 一次带回结果，
从库里的状态接着跑。

**三、助手不替用户保存。** 它改的是草稿，落库永远是用户自己按的那一下。

**四、按工作面分档动手边界。** 大屏与孪生这两个草稿态编辑面上助手直接改；
其余页面是即时提交（每个动作自己发一次 REST、没有可回滚的中间态），
助手在那里**只提议，写入必须由用户确认**。

## 理由

- **让后端直接改库会同时坏掉三件事**：用户屏幕上什么都不会变（草稿盖着库里的
  值）、用户保存时撞 409（`row_version` 被助手推进过）、助手的每一步无法撤销。
- **走 `EditorActions` 则三件事全是白拿的**：每一步立刻可见、一次 Ctrl+Z 撤掉
  一步、不保存就能预览。一行额外代码都不用写。
- **批量写入必须一次成型**。逐条绑定 CRUD 也会推进 `row_version`，但推送方按
  版本重读绑定计划——绑 50 个点就是 50 轮全量推送。整树替换一次搞定。
- **不复用 realtime-hub**：它按 [ADR-0007](0007-实时通道薄化与开放主题命名空间.md)
  是薄扇出通道，语义是「主题订阅 + 服务端推」。把点对点的请求—响应塞进去，
  要给它加路由能力，正面违反那条薄化决策。
- **待续状态必须落库**：`api` 角色无状态且按 QPS 扩缩，续跑那一次请求完全可能
  落到另一个副本上。放内存的话表现是「助手做到一半忘了自己在做什么」，
  且只在多副本下复现。
- **第四条不是加一层开关，是如实反映底层能力差异**。假装台账页也能撤销，
  正是本仓最忌讳的那类静默失败。

## 后果

- 前端要实现一套「工作面」注册：每一页自己声明能读什么、能执行哪些客户端工具。
  不注册 = 助手在那一页只能聊天与检索，**如实缺席**而不是假装成功。
- 客户端工具的名字成了前后端之间的一份新契约，两侧都要有测试钉住。
- 协议要开 SSE 这条本仓从未有过的先例：`server/lib` 里没有流式响应，
  前端也没有 `EventSource`。边缘那条 location 必须单独写全超时并关掉
  `proxy_buffering`——`proxy-common.conf` 的 `proxy_read_timeout 25s` 会把
  一次模型调用拦腰切断，而 nginx 不许在同一个 location 里重复声明同一指令。
- 助手因此**不能**做无人值守的长任务：每个回合都要有一个开着的浏览器来跑客户端
  工具。这是有意的边界，不是暂时的限制。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 后端直接调 platform 的节点与绑定接口改库 | 用户看不见、保存撞 409、无法撤销。三条各自都足以否决 |
| 前端把整份草稿发给后端，后端算完整棵树发回来 | 一屏最多 2000 个节点，每一步都整树往返；且「AI 做了哪一步」退化成「树变了」，用户看不出它改了什么 |
| 复用 realtime-hub 的 WebSocket 下发工具调用 | 要给薄扇出通道加点对点路由，违反 ADR-0007；凭据、重连、退订也要重写一遍 |
| 为助手单开一条 WebSocket | 凭据得走子协议票据那套（浏览器 WS 不许自定义头），而 SSE 走普通 HTTP，边缘的 `auth_request` 原样生效 |
| 用 LangGraph 官方的 Postgres checkpointer 存待续状态 | 它自己建表、绕过 alembic，与「一张表只有一个属主、只有属主管迁移」（[ADR-0003](0003-一库多schema且写独占读放行.md)）冲突；且它是 psycopg（LGPL-3.0-only）进入依赖树的唯一来源 |
| 助手配完直接保存 | 保存是用户对这一屏负责的那一下。助手可以做完所有繁琐的部分，但不替他按 |
