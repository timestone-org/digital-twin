# ADR 0051：任意业务页用 API 密钥换短期会话后嵌入

- 状态：已接受
- 日期：2026-09-07
- 影响范围：`server/services/auth-server/`、`web/`、`server/services/realtime-hub/`、`docker/nginx/`
- 相关：[ADR-0005](0005-实时通道与边缘网关的职责分界.md)、[ADR-0013](0013-第三方系统用可吊销的API密钥而非长期令牌.md)、[ADR-0014](0014-公开大屏是平台唯一的匿名可达面.md)、[ADR-0021](0021-公开大屏的匿名实时订阅与跨屏跳转.md)、[ADR-0038](0038-语音输入走自建FunASR经知识库服务中继.md)、[ADR-0047](0047-模型对外面走API密钥并由边缘免认证承载.md)、[ADR-0049](0049-大屏运行态取数统一走WS.md)

## 背景

数字孪生的业务页需要被可信内网系统以 `iframe` 嵌入。嵌入时不显示应用壳的
左侧菜单，同一个业务页可以按嵌入实例选择不同的已登记主题。调用方已经持有某个
账号的 API 密钥，希望不再出现口令登录页。

最安全的形态是「调用方后端保管 API 密钥 → 铸一次性嵌入票据 → 浏览器换限权会话」。
本次为了降低接入成本，明确选择更简单、也更高风险的形态：API 密钥由原页面 URL
的 query 进入浏览器，前端立即用它换一枚短期 access token。

## 决策

### 一、嵌入入口是原业务页 URL，不另建页面镜像

所有允许嵌入的业务页沿用已有路由，嵌入参数是：

```text
/<business-route>?token=<APIKey>&theme=<theme-id>
```

- `token` 是现有 `dtk_...` 用户 API 密钥；存在且非空时进入嵌入模式。
- `theme` 只接受前端主题清单中的 id，不接受任意 CSS 值；缺失或不合法时回落到 `dark-tech`。
- `embed=1` 是前端清掉密钥后保留的非敏感布局标记，不是凭据，不能替代 `token`。
- 嵌入模式只改应用壳与主题，业务组件、路由参数和 API 调用全部复用原页。
- 嵌入页隐藏全局左栏、`ThemeSwitcher` 与大屏运行页的返回按钮；保留页面自己的标题、
  actions 与业务交互。这些显隐不是权限边界。

「任意业务页」不包含登录、修改密码、用户/角色/路由规则、API 密钥管理等
auth-server 管理面。这些页面会被嵌入 access 的服务端门禁拒绝，不能靠隐藏菜单放开。

### 二、API 密钥只用来换 300 秒嵌入 access，不当作业务请求的长期 Bearer

前端调用：

```http
POST /api/v1/auth/sessions:from-api-key
Authorization: Bearer <dtk_...>
```

请求没有 body。响应 `data` 是不含 refresh token 的新形状：

```json
{
  "token": {
    "access_token": "<short-lived JWT>",
    "token_type": "bearer",
    "expires_in_s": 300
  },
  "user": {}
}
```

交换只接受设置了明确 `expires_at` 的 API 密钥；永不过期的密钥与伪造、
吊销、过期密钥返回同一条 401，不泄漏密钥是否存在。

该端点仍住在受保护的 `/api/v1/auth/` location，**不新增免认证 API location**：

1. 边缘先用 `/verify` 校验 Bearer API 密钥与路由规则；
2. 端点再从 `Authorization` 取同一枚 API 密钥并校验一次。

边缘为这一条精确路径单列按来源 IP 的限流区：`60r/m`、`burst=20`、超限回
429。它容纳同一内网出口后多个 iframe 每 5 分钟的续期，同时防止被盗密钥无界换票。
该精确 location 必须继续 `include auth-inject.conf`；它是受保护面的限流特例，不是
免认证特例。

第二次校验不是把边缘的结果当作不可信，而是保留 auth-server 管理面「不用边缘
注入的 `X-Auth-*` 认自己」这条边界。绕过边缘直连 auth-server 时，端点自己仍会拒绝伪造请求。

换出的令牌仍是 realtime-hub 已认识的 access JWT，但带不可伪造的嵌入会话标记。
它完全继承 API 密钥所属账号的当前权限，不按页面收窄。auth-server 管理面必须识别该标记并
一律拒绝，其它服务继续按原有权限码守闸。

前端不把 API 密钥、access token 或用户信息写入 `localStorage` / `sessionStorage` / cookie，
也不参与普通登录态的跨标签同步。它们只存在当前 iframe 的内存中。首航把
API 密钥复制进内存并启动交换后，立即返回一次清理导航：用 `history.replaceState`
移除 URL 中的 `token`、保留 `theme` 并写入 `embed=1`。第二航在挂载页面前
等待同一次交换结果；不让网络等待时间延长 API 密钥在地址栏里的停留。内存中的
API 密钥在 access 到期前重新调用上述端点。不签发 refresh token，也不调用
`/sessions:refresh`。

API 密钥被吊销或账号被停用后，下一次换票一律失败；已签发的 access 无法中途吊销，
因此最长仍可使用 300 秒。这是本简化方案明确接受的吊销窗口。

### 三、实时通道复用 `dt.auth`，不让 hub 认识 API 密钥

嵌入页用上一节的短期 access token 连接 `/api/v1/realtime/ws`，子协议仍是：

```text
Sec-WebSocket-Protocol: dt.auth, <short-lived access token>
```

realtime-hub 继续验 access JWT、回查用户当前权限、按主题声明判定订阅，不增加
`dt.embed`，也不增加 API 密钥分支。这让 ADR-0007 的通道边界与 ADR-0049 的大屏单一
取数路径都保持不变。凭据截止时钟与客户端入站帧独立：即使连接只收服务端推送，
也会在 `exp - 60s` 主动要求 reauth，到 `exp` 仍未换票则以 4001 关闭。

### 四、不为嵌入页开新的匿名业务 API

前端静态文件与 SPA 壳本来就可以匿名取得，但业务数据仍经原有受保护 API，由
`auth_request` 与服务端闸 2 判权。`sessions:from-api-key` 也经受保护 location，所以本决策
不复制 `public-dashboards` 的免认证形态，不扩张 ADR-0014 留下的匿名数据面。

同理，iframe 内的页面请求数字孪生同源 API，不需要 CORS。本决策不添加
`Access-Control-Allow-Origin: *`，也不允许外部页面直接跨域读取 API 响应。

### 五、边缘只对带 `token` 的静态入口做可验证的泄漏缩减

正常页面的静态响应下发：

```text
Content-Security-Policy: frame-ancestors 'none'
```

带非空 `token` query 或 `embed=1` 的静态入口，以及原有
`/public/<public-token>` 大屏页面，下发：

```text
Content-Security-Policy: frame-ancestors *
Cache-Control: no-store
Referrer-Policy: no-referrer
```

`frame-ancestors *` 是有意的放宽：本方案没有嵌入父页 origin 清单，边缘无从分辨「可信
内网页面」和「其它页面」。它只能用非空 `token`、`embed=1` 或原有公开大屏路径
作为嵌入意图标记。
路径判断读的必须是从原始 `$request_uri` 剥掉 query 的 `$original_path`，不是
`$uri`：SPA 的 `try_files` 回落会在内部重定向后把 `$uri` 改成 `/index.html`，否则
`/public/<public-token>` 会在响应阶段被误判为普通页。
因此 CSP 只能保护不带密钥的普通会话，不能对嵌入方做真实授权。

Linux 与 Windows 边缘的访问日志都记从原始请求剥掉 query 的稳定路径，不记
`$request_uri` / `$request`；公开大屏路径里的票据段额外记成 `<redacted>`。这不保证密钥
不会进入浏览器历史、截图、嵌入方
服务器日志、WAF/CDN 或错误日志。`no-store` / `no-referrer` 也只缩小副本数，不能把
已进入浏览器的长期密钥变安全。

## 已接受的风险与运维约束

本决策**有意违反** [`config-and-secrets.md`](../agents/config-and-secrets.md) 「密钥不进 URL」，
也放宽 ADR-0013 与 `auth-server/CONTEXT.md` 「前端不使用 API 密钥」的安全边界。
ADR-0047 的模型密钥只允许放在 `X-Api-Key` 头里，同样是更安全的先例；本决策不将
它改成通用规则，只是为用户 API 密钥的可信内网嵌入建立一个受限例外。
不得用「只在内网」把这个例外描述成无风险：内网页面的 XSS、浏览器扩展、共享终端、
截图与访问日志都能拿走它。

故上线同时必须满足：

1. **生产必须使用 HTTPS/TLS**。TLS 可由本边缘终结，也可由它前面受管的反向代理
   终结，但浏览器到第一个可信终结点之间不得是明文 HTTP。API 密钥已在 URL 中，
   明文传输会让被动抓包直接变成长期账号接管。
2. 只在可信内网与受管终端上使用，不对互联网或不受控第三方网站开放。
3. 一个嵌入方使用一个**专用账号**与一枚 API 密钥，不复用人员的日常登录账号。
4. 专用账号只给目标页面真正需要的最小权限；默认只给 `view` 档，必须单独评审
   `manage` / `operate` / `admin`。密钥自身没有 scope，给错账号就是给错全部权限。
5. API 密钥必须有明确到期日，不允许这个场景选「永不过期」；按嵌入方独立轮换。
6. 监控 API 密钥的 `last_used_at`；任何疑似泄漏立即吊销，接受已发 access 最长再生效
   300 秒的窗口。
7. 嵌入页不得将 access token 或 API 密钥通过 `postMessage` 发给父页或任何其它 window。

若任一条无法满足，不得继续扩大该例外；应切换到下文被否决的「一次性票据 +
限权嵌入会话」方案。

## 否决的替代方案

### 一、调用方后端保管 API 密钥，浏览器只拿一次性票据

这是推荐的安全形态：票据一次使用、几十秒过期，再换按页面/origin/权限收窄的会话。
它能让 API 密钥永不进浏览器，也能真正用 `frame-ancestors` 限制父页。

本次否决的原因是调用方需要一条直接可填进 `iframe src` 的 URL，不希望同时开发后端换票与
嵌入配置管理。安全性与便捷性的取舍由上一节的运维约束补偿。

### 二、让浏览器在所有业务请求上直接携带 API 密钥

这会让长期密钥持续出现在 HTTP 与 WebSocket 边界，且 realtime-hub 并不认识 API 密钥。
换为 300 秒 access 后，密钥只打 auth-server 一条路径，业务请求与 WS 都只看短票。

### 三、为每个页面新建一组匿名数据端点

这会让 ADR-0014 有意收窄的公开面按页面增长，每增一页都要重新设计凭据、撤回、
配额与字段裁剪。本决策复用账号权限与原 API，不再扩公开面。

## 上线与回滚

按向前兼容顺序拆分：

1. auth-server 先上 `sessions:from-api-key`、路由规则、短期令牌标记与管理面拒绝，
   重跑 auth 种子；旧前端不调这条，行为不变。
2. 再上前端嵌入上下文：query 取值、内存态、300 秒自动换票、左栏与指定导航件隐藏、
   主题应用、URL 清除后保留 `embed=1` 与异常空态。
3. 最后同步 Linux/Windows 边缘的静态响应头与日志格式，用真实 iframe 验证
   嵌入、同源 API 与 WS。

回滚时先让嵌入方停用带密钥 URL，再回滚前端。为避免回滚后 URL 里的密钥被普通
登录页继续带着，已发出的嵌入 API 密钥必须吊销并重发。auth-server 的新端点可以
暂时保留，它仍受两道验证，没有新的匿名数据面。

## 必须验证的契约

- 缺少、伪造、已吊销、已过期、永不过期 API 密钥与停用账号均不能换票。
- 换票端点不接受 body/query 中的密钥，不返回 refresh token，`expires_in_s` 恒为 300。
- 换票端点的精确边缘 location 仍包含 `auth-inject`，按 IP 以 `60r/m`、`burst=20`
  限流，超限回 429；它不得进入免认证 location 清单。
- 嵌入 access 能通过原业务 API 的闸 1/闸 2，但不能进 auth-server 管理面。
- 短期 access 可以通过 realtime-hub 的 `dt.auth` 真实握手；即使客户端没有入站帧，
  也会收到换票提醒并在到期后被 4001 关闭，成功 reauth 后按新截止点重排。
- 嵌入态不写任何持久化登录态，不影响同源普通登录标签。
- 普通页面静态响应不允许 frame；带非空 `token` 或 `embed=1` 的入口可被外域 frame，
  且有 `no-store` / `no-referrer`。原有 `/public/<token>` 大屏仍可被外域 frame。
- Linux/Windows 边缘 access log 都不包含 query，且保留非凭据路由而非退化成
  `/index.html`；不新增 CORS 通配、免认证 API location
  或 realtime-hub 凭据分支。
- 生产嵌入 URL、换票 HTTP 请求与 WebSocket 全程经 HTTPS/WSS。
