# ADR 0041：订阅账号的登录态归 platform 持有，两个消费方经内部面领令牌

- 状态：已接受
- 日期：2026-09-03
- 关系：取代 [ADR-0040](0040-供应商按接入形态配置且档位即供应商.md) §四关于订阅
  账号那一路的环境变量默认值与 §五「凭据按哪一路供应商认行、存在消费方」；
  对 [ADR-0026](0026-助手接订阅账号模型走上游私有面.md) 是**换了个属主**，
  接法本身照旧

## 背景

[ADR-0040](0040-供应商按接入形态配置且档位即供应商.md) 把订阅账号那一路收进了
平台的供应商目录：形态、模型清单与推理档位都配在那一行上。唯独**登录态**还留在
助手自己的 `assistant.model_credentials` 上——那一行是按供应商 id 认的，而供应商
行在平台。

于是「这一路怎么接」有两个属主：目录管一半，助手管另一半。这件事在两个地方开始
硌人：

- 知识库要接同一路订阅账号。凭据在助手那儿，而**知识库不许回调助手**
  （[ADR-0032](0032-知识库独立成代码单元且LLM客户端下沉domain.md) 决策四）——
  照现在的形状，同一个 ChatGPT 账号要在两个服务上各登一遍，以后每加一个消费方
  再登一遍。
- 目录里删掉一路供应商时，助手那边留下一行没有人认领的登录态；下一个建出来的
  供应商甚至可能撞上它。

ADR-0040 的备选表里写过「登录态搬到平台，随目录一起下发令牌」，当时不选的理由是
**「令牌要在每次调用前可续期，而目录是 10 秒 TTL 的快照」**。这条反对意见成立，
但它反对的是「随目录下发」这一种做法，不是「归平台持有」这件事本身。

## 决策

**一、登录态归 platform，与那一路供应商同属主：`platform.llm_provider_credentials`。**

`provider_id` 唯一、外键指向 `llm_providers` 并**级联删**——这一行是那一路的一
部分，供应商删了它也就没有意义了。留着的话，下一个建出来的供应商可能撞上一行
没人认领的登录态。加密复用目录那把 `PLATFORM_LLM_PROVIDER_SECRET`，不另造一把：
两把密钥意味着两次轮换、两处配漏。

设备码登录的那一整套（上游 OAuth 客户端、在途会话、令牌包与密文换算）跟着搬到
平台，对外端点落在供应商那一行之下（`…/llm-providers/{id}/credential:start-login`
等）。读要 `llm:view`、写要 `llm:manage`，与边缘那两条规则逐字同口径。

**二、令牌不随目录下发，而是**按需领**：`POST /internal/v1/platform/llm-credentials/{id}:token`。**

这是与 ADR-0040 那条备选的实质分别。目录是 10 秒 TTL 的快照，令牌塞进去必然过期；
而一条独立的内部端点在**每一次要用的时候**回答「此刻能用的那一份是什么」，快过期
就先换一份再回。消费方那一跳与目录那一跳互不相干，各有各的预算。

**三、续期只在平台这一侧做：消费方**只领不刷**。**

刷新是写操作，属主只有一个。两个消费方各自拿同一个 refresh_token 去换，每一份新
令牌都会把上一份作废——而被作废的那一份已经发出去用了。现象是「用着用着就掉
登录」，且只在两个消费方同时活跃时才出现。故 `llmcore` 那一层的端口只有
`usable(provider)` 一个动作，连 refresh_token 都拿不到。

**四、`llmcore` 收下订阅账号那一路的共用件。**

模型构造（上游 `_ChatOpenAICodex` 焊死的那几条硬约束）、令牌来源端口与它的平台
实现、适配器、工具名的线形改写，以及形态码与推理档位的闭合集合，全部下沉——
入场券是「已有 ≥ 2 个服务真实消费」，而这次正好两家。复制一份一定会漂，漂的表现
是「同一个订阅账号，助手说得了话、知识库说不了」。

**五、知识库那一侧认「对话模型适配器」协议 + 一张形态 → 装配口子的表。**

与助手侧 `KIND_BUILDERS` 同一个形状。原来它只认 `OpenAiCompatAdapter` 这个具体
类，目录里分配到订阅账号那一路时解不出端点、**静默退回环境变量那一档**——差异
只出现在账单上。现在接不了的形态如实缺席。平台侧那一档的 `consumers` 随之放宽到
两个消费方：加一个消费方的前提是**它真接得了**。

**六、订阅账号那一形态不再有环境变量档。**

`ASSISTANT_CODEX_ENABLED` / `_MODEL` / `_MODELS` 与 `ASSISTANT_CREDENTIAL_SECRET`
四格退场。理由是硬的：这一路要先登录一次，而登录态挂在**目录里那一行供应商**上
——目录之外配出来的那一路无处存登录态，装出来也说不了话。留着它等于让界面上配
得出、点下去报一条指不回任何地方的错。留下的只有
`ASSISTANT_CODEX_REASONING_EFFORT`：那一路没配推理档位时的缺省。

**七、存量令牌不搬，助手那张表按扩展—收缩两次发布退场。**

迁移里禁止回填，跨服务读别人的密文也不该做。这一次发布只**停止读写**
`assistant.model_credentials`，表与它的声明留着——代码可回滚、数据库不回滚，故
「新结构 + 旧代码」必须可用。**删表在下一次发布。**

## 后果

- **已经登录过的部署，升级后要在模型管理页重新登录一次。** 界面上那一节从
  「助手专用」改口成「助手与知识库共用」，位置不变。
- 用环境变量配订阅账号的部署，升级后那一路整个消失，要去模型管理页建一路
  「Codex 订阅」形态的供应商再登录一次。`.env` 里那四格删掉即可。
- platform-server 多一张表、一次纯扩展迁移、四条对外端点与一条内部端点，
  并多一个依赖 `langchain-openai`——只借它的**协议常量**（client_id、几个端点
  地址与 scope）。抄一份字面量进来的话，上游改地址时我们静默失效，而现象是
  「登录页转圈转到超时」。
- 每一次模型调用之前多一跳内部 HTTP。刻意**不在消费方缓存令牌**：缓存一份等于
  在「界面上退出登录了」与「那一路还在说话」之间开一个说不清多久的窗口。
- 助手的能力面问「登没登录」也变成一次跨进程调用。降级方向逐项显式：「还没登录 /
  登录已失效」如实报未连接；**「平台此刻不可达」仍报已连接**——报未连接的话，
  平台抖一下会让界面说「去登录一次」，而那一次登录同样打不通平台。
- 形态码的复述从三处变四处（平台 / llmcore / 助手 / 前端）加迁移里的 CHECK，
  由 `llm-shapes.contract.spec.ts` 逐字比。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 登录态留在助手，知识库经助手的 HTTP 面领令牌 | 知识库回调助手是双向同步 RPC（ADR-0032 决策四），且助手的定位是纯消费方 |
| 两个消费方各存一份登录态 | 同一个账号要登两遍，而且两边各自续期会互相把对方的令牌作废——现象是「用着用着就掉登录」 |
| 令牌随目录一起下发（ADR-0040 那条备选） | 目录是 10 秒 TTL 的快照，令牌塞进去必然过期；按需领的那一跳与目录那一跳互不相干 |
| 消费方缓存令牌到过期前若干秒 | 「界面上退出登录了」与「那一路还在说话」之间会开一个窗口；一次内部往返比这便宜 |
| 保留环境变量那一路的登录态（凭据表按文本键认行） | 那就是把「两个属主」这件事换个地方留下来：一个键在目录里、一个键在配置文件里，而读侧要为它写一条 coalesce |
| 助手这次就把 `model_credentials` 删掉 | 代码可回滚、数据库不回滚。删表之后一旦回滚到上一版助手，它启动即崩 |
