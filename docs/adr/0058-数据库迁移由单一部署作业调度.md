# ADR-0058：数据库迁移由单一部署作业调度

Docker Compose 用一个专用部署作业按顺序调用各服务原有的 Alembic 链，并执行
认证与平台的对应种子；应用角色等待整个作业成功后才启动。迁移链、版本表和 schema
仍归各属主，作业不共享 ORM、不合并事务，也不是新的业务服务，符合 ADR-0003。

迁移镜像只安装执行迁移与种子需要的锁定依赖，不携带业务镜像的 Node、模型工具
或 LibreOffice。应用镜像仍按服务隔离；同一服务的运行角色复用同一个镜像。
迁移账号可单独配置，作业持有 PostgreSQL 会话锁，抢不到锁、锁连接丢失、命令
超时或任一迁移失败即退出，不自动重试写操作。应用入口不执行迁移，避免扩缩和
重启触发 DDL；不挂载 Docker socket，避免部署调度获得宿主容器控制权。

代价是任一迁移失败都会阻断这次 Compose 应用启动，已成功的 schema 不回滚；
修复失败原因后重新执行，由各链版本表继续推进。需要独立发布一个服务时，部署
作业可显式选择属主，但这不能替代全栈启动所需的完整成功记录。
