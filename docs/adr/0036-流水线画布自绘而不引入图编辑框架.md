# ADR 0036：流水线画布自绘，不引入图编辑框架

- 状态：已接受
- 日期：2026-09-01
- 影响范围：`web/app/src/pages/Modeling/Canvas/`、`web/package.json`（不新增依赖）
- 相关：[MODELING_DESIGN §8.2](../MODELING_DESIGN.md)、[ADR-0028](0028-2D编辑画布自绘而不引入图编辑框架.md)

## 背景

分析建模的画布要在一块图上做这些事：摆算子节点、按**具名端口**连线、拖节点、框选、
平移缩放、连接前置校验（契约不等 / 成环即拒），再叠一层运行态四态染色与只读回看。
这正是 vue-flow 这类图编辑框架的场景，所以「要不要引入」必须先答。

[ADR-0028](0028-2D编辑画布自绘而不引入图编辑框架.md) 已经在 2D 孪生编辑器上答过一次
「自绘」。但那是另一套需求：2D 孪生要旋转手柄、图元树节点、周长参数端口、标注双层、
图元级选中，流水线一样都不要；反过来流水线要具名端口（[D4](../MODELING_DESIGN.md)：
边必须带端口）与连接前置校验，2D 孪生没有。**需求交集不同，结论不能靠援引拿来**，
理由必须在流水线 DAG 这一侧独立成立一遍。

## 决策

**流水线画布自绘，不引入 vue-flow 或同类框架。**

这是 ADR-0028 那条判据在第二个场景上的复用，不是推翻它，也不是它的推论——下面四条
理由每一条都只用流水线这一侧的事实。

## 理由

### 一、决定性的那一条是全仓级的：`as unknown as` 在本仓是红灯

`web/eslint.config.js` 的 `no-restricted-syntax` 明令打回这个写法，原话是
「as unknown as 一律打回：它把两次类型检查一起关掉了」。而 vue-flow 的自定义
节点 / 边组件拿到的是它自己的 `NodeProps` / `EdgeProps`，与组件自己声明的 props
对不齐，社区通行解法正是这个断言。

这一条在流水线上比在 2D 孪生上更硬：流水线的节点卡片**必须**是自定义组件——
左右两侧每个端口一个具名接点（`data-port` = 端口名）、待运行 / 运行中 / 成功 / 失败
四态染色、右上角按结果有无出现的抽屉按钮。默认节点渲染不出这些，拿不到自定义组件
就等于框架白引。

绕开这条 lint 只剩三条路：

| 绕法 | 代价 |
|---|---|
| 给每个自定义组件手写一层运行时校验的适配层 | 逐组件逐字段写，量级已超过它替我们做掉的那部分手势 |
| 把断言改写成别的同样绕过检查的写法 | 同一件事换个说法，规矩还在，只是骗过了扫描器 |
| 为建模模块开一条 eslint 例外 | 为一个**可以不引入**的依赖破一条全仓规矩，且例外一旦开出去就会被别处援引 |

⚠ 这是全仓 lint 规矩，不是 2D 孪生那个模块的偏好——它与本 ADR 引不引用 0028 无关。

### 二、流水线要的比 2D 孪生少，而本仓已经自绘过更难的那块

2D 孪生编辑器的视口 / 选中 / 吸附 / 指针手势共 **916 行**（`viewportOps.ts` 282 +
`editorSelection.ts` 220 + `snapping.ts` 215 + `useCanvasPointer.ts` 199），
且那块画布同样带节点与连线。流水线画布是它的真子集：

| 2D 孪生有的 | 流水线要不要 |
|---|---|
| 旋转手柄 | 不要——节点不旋转 |
| 图元树节点渲染（`box`/`vec`/`ico`/`txt`，[ADR-0027](0027-2D孪生的节点与连线样式是可配置图元文档.md)） | 不要——节点是固定版式的卡片 |
| 端点按周长参数落点 | 不要——端口是离散具名接点 |
| 标注双层（按 `zOrder` 压在节点上下） | 不要——只有节点层与连线层两层 |
| 图元级选中 | 不要——选中粒度就是节点与边 |
| 吸附与参考线（215 行） | 不要——DAG 不做像素排版 |

砍掉的这几样正是那 916 行里最贵的部分。剩下的视口换算与指针状态机在本仓已有两份
现成实现（`DashboardEditor`、`Twin2dEditor`）可照。

### 三、框架给不了流水线真正要的两样

| 要的 | 为什么框架给不了 |
|---|---|
| 每个输入 / 输出端口一个具名接点 | 端口是自定义节点组件里的 DOM，落回第一条：自定义组件 props 对不齐 |
| 连接前置校验要**给出原因** | 框架的连接校验回调只答「能不能连」，「契约不等」还是「会成环」这句人话要自己挂 |

参考仓零前置校验，所有连接错误都要等运行时才知道——长流水线里一个笔误要跑到那一步
才炸。这件事必须在画布上做，而它落在自定义组件与自己的连线层上。

### 四、不欠框架的版本账

- **没有第二套坐标系**：框架的节点 `position` 是左上角，本模块的命中与连线锚点按端口
  接点的实际盒算，每一处进出都要换算一次，漏一处就是偏半个节点；
- **没有第二套选中模型**：选中集是自己的一份 `Set`，不是框架 store 里的镜像；
- **运行态染色挡得住**：运行状态每秒换新，混进节点数组会让拖拽中的位置被重建的数组
  盖回去。自绘下它走 `provide/inject`、根本不进节点数据；框架的节点数组是它 store
  里的东西，同一件事得顺着它的生命周期做；
- 也不会因为框架升级而重新校一遍手势。

**自绘的量级**（拆成组合式函数，各自压在 200 行的闸门以内）：

| 文件 | 管什么 |
|---|---|
| `scripts/useCanvasViewport.ts` | 平移、缩放、屏幕↔画布坐标换算、适应视图 |
| `scripts/useCanvasPointer.ts` | 指针手势状态机：拖节点、框选、拖连线 |
| `scripts/useCanvasSelection.ts` | 选中集（单选 / 加选 / 框选） |
| `scripts/useCanvasWiring.ts` | 端口命中、连线预览、连接前置校验 |

按依赖判据「少于 200 行且没有隐藏复杂度就自己写」，四个加起来超过 200 行，
但隐藏复杂度全在**引入**那一侧。

## 后果

- **小地图这类白拿的功能没有了**，要就得自己写；本期不做。框架顺带给的网格背景与
  「适应视图」按钮也一样，前者是一层 CSS，后者在 `useCanvasViewport.ts` 里。
- **手势语义由我们自己定，也由我们自己保证**。四条逐条照抄 2D 孪生那块的用例：
  一次手势只在 `pointerup` 提交一步撤销（逐帧提交的话撤销键再也按不回上一步）；
  拖拽中卸载要补提交一次；把手与选中框按当前倍率**反着缩**回屏幕上的固定尺寸；
  手势期间挂在 `window` 上的 `pointermove` / `pointerup` 与视口的 `ResizeObserver`
  **卸载时必须摘掉**。框架不会替我们守这些，因为框架里根本没有这几个概念。
- **不必管框架 store 的生命周期**：ADR-0028 记过 vue-flow 按 `flowId` 建在全局的
  store 漏 `$destroy` 会跨导航泄漏；建模画布同样是反复进出的一页，自绘直接没有这个面。
- **本仓从此有三块自绘画布**（大屏组态、2D 孪生、流水线）。视口与指针手势的写法要写
  第三遍——照抄成本低（两份现成实现都在仓里），但重复是真的。第四块出现时再论抽包，
  本期不抽：三边的选中模型与命中语义各不相同，抽一层公共画布包等于给每边加一组参数。
- ⚠ **拖节点时连线跟不跟着走，是我们自己的取舍**：2D 孪生那块松手才归位，因为节点草稿
  是节点层私有的、层间没有逐帧通道。流水线的连线是一层 SVG、节点量级也小，逐帧下发草稿
  位置是可行的；这条留给实现时定，但**必须显式定**——默认行为不会替我们做选择。

## 备选方案

| 备选 | 不选的理由 |
|---|---|
| 引入 vue-flow | 节点卡片（具名接点 + 四态染色 + 抽屉按钮）必须是自定义组件，而自定义组件 props 几乎必须 `as unknown as`，本仓 eslint 直接打回；白拿的只剩视口与框选，这两样仓里已有两份现成实现 |
| 引入并为建模模块开一条 eslint 例外 | 为一个可以不引入的依赖破一条全仓规矩，且例外一旦开出去就会被别处援引 |
| 引入并给每个自定义组件写运行时适配层 | 适配层要逐组件逐字段写，量级已经超过它替我们做掉的那部分手势，还多背一个依赖与它的版本账 |
| 复用 2D 孪生那块画布的组件 | 交集只有视口与指针手势；它的选中与吸附是按图元文档（[ADR-0027](0027-2D孪生的节点与连线样式是可配置图元文档.md)）建的模型，套到 DAG 上要先把那套模型参数化，比照着重写一遍贵 |
| 用 `<canvas>` 全量重绘 | 节点卡片要 `text-overflow`、渐变、阴影这些 HTML 能力（§8.2），全量重绘等于自己写一个排版引擎 |
