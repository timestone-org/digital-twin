# ADR-0014：公开大屏是平台唯一的匿名可达面，且只读静态快照

- 状态：已采纳（§四「不提供实时数据」已由 [ADR-0021](0021-公开大屏的匿名实时订阅与跨屏跳转.md) 取代，其余照旧）
- 日期：2026-08-14
- 影响范围：`server/services/platform-server/apps/dashboard/`、`server/services/auth-server/apps/auth/catalog/`、`docker/nginx/`、`web/app/src/pages/`

## 背景

工作台要能把一张大屏「分享出去」——收到链接的人不登录就能看。这与本仓既有的一条硬规范直接冲突：**所有 `/api/v1/` 下的路径都经边缘的 `auth_request` 前置鉴权**，未通过的请求根本到不了业务服务（[ADR-0005](0005-实时通道与边缘网关的职责分界.md)）。

「分享」这件事没有可以躲开这条规范的实现：无论令牌放在 URL、请求头还是 cookie 里，**持有者都是一个未登录的访客**，闸 1 没有任何身份可判。

## 决策

**开一条、且只开一条匿名端点 `/api/v1/platform/public-dashboards/{token}`，它回的是静态快照。**

| | 取值 |
|---|---|
| 匿名端点 | `/api/v1/platform/public-dashboards/`，nginx 里 `location ^~` 单列，不挂 `auth-inject.conf` |
| 凭据 | URL 里的 `public_token`，`secrets.token_urlsafe(32)` |
| 令牌轮换 | **每次 publish 都换新的**，旧链接当场失效 |
| 撤回 | `:unpublish` 置 `is_public=false` 且 `public_token=NULL` |
| 查不到 | 一律 404，**不区分**「没这个令牌」与「已撤回」 |
| 出参 | 只有渲染要的字段：无 `id`、无 `project_id`、无 `row_version`、无创建人 |
| 实时数据 | ~~**不提供**~~ → 见 [ADR-0021](0021-公开大屏的匿名实时订阅与跨屏跳转.md)：匿名订阅走 WS，凭据是同一枚公开令牌，订的是它换来的**别名**主题（大屏 id 仍不出门）|
| 限流 | nginx 独立 `limit_req` 区，60r/m |

## 理由

### 〇、是 `public-dashboards` 这个资源，不是 `public/` 这个命名空间

一开始写的是 `/public/dashboards/{token}`，把 `public` 当成一个匿名命名空间。
放弃它的理由是：**命名空间会自动扩张**。nginx 上那条免认证 location 一旦写成
`^~ /api/v1/platform/public/`，此后任何人往 `/public/` 底下挂一个端点，
它就**自动**变成匿名可达的——不需要评审、不需要改网关、没有任何一处会亮红灯。

写成 `public-dashboards` 之后，每开一个新的公开面都必须显式再加一条 nginx
location 与一条闸 1 规则，是一次要被人看见的改动。

（顺带：`public` 也过不了对外契约那条「首段是复数资源名」的闸——那条闸本来就是
在拦这件事：`public` 不是一个资源，它是一个借口。）

### 一、只开一条，且让它在评审时显眼

匿名面的风险不在于「开了一条」，而在于**开了之后没人记得它是匿名的**。所以：

- 路由注册里它单列一行并带注释（`apps/dashboard/api/__init__.py`），不混进那串受保护路由；
- auth-server 的规则表里 `_PUBLIC_RULES` 单成一段；
- nginx 里单成一个 `location`，注释写明「这不是漏了 auth-inject」。

⚠ nginx 那条的 `^~` 不能省：少了它，更短的 `/api/v1/platform/` 前缀在存在正则 location 时会重新参与竞争，公开链接又会被要求登录——而这种回归只在加了某条正则 location 之后才出现，改的人根本不会想到自己动了公开面。

### 二、「撤回」必须是真的，所以每次发布都换令牌

如果 publish 复用已有令牌，那么「撤回 → 再发布」之后，先前发出去的链接会**重新生效**。用户以为自己收回了一份材料，实际只是让它下线了几分钟。

代价是重新点一次「发布」会废掉已经发出去的链接。这个代价必须在界面上说清楚——用户会以为再点一次是幂等的。

### 三、404 不区分两种「没有」

分开回（比如撤回的回 410）等于告诉持有旧链接的人「这张屏确实存在过」。公开面的每一个可区分的响应都是一次信息泄露。

### 四、否决了「公开面也推实时数据」

BK 有 `/public/dashboards/{token}/realtime-plan`（它那边的命名），公开页也能拿实时值。本仓**这一轮不做**，理由是它要在 `realtime-hub` 上开一条匿名订阅通道：连接层要认令牌、要按令牌限定可订阅的主题集、要防一个泄露的令牌把连接池吃满。这三件事任何一件做漏，代价都是连接层被打穿——而连接层是全站共用的（ADR-0005）。

因此公开页现在渲染**静态快照**，并在页面上显式标注「数据截止 {updated_at}」。

⚠ 这一条是刻意的、可见的降级，不是遗漏。**不许**去掉那个截止时刻标注来「让页面好看点」——一个看起来在跑、实际停在某个时刻的大屏，比一个明说自己是快照的大屏危险得多（见 `docs/agents/runtime-resilience.md`「返回陈旧数据必须标注为陈旧」）。

要补实时，走独立一轮，并单开一条 ADR 说明匿名订阅的配额与主题限定怎么做。

**（2026-08-19 更新）那一轮已经走完，见 [ADR-0021](0021-公开大屏的匿名实时订阅与跨屏跳转.md)**：连接层认的是同一枚公开令牌、可订的主题由推送方登记的授权限定、名额按票据与副本双重设限。⚠ 上面那句「必须标注陈旧」**没有**跟着作废——它现在的形态是右下角那条三档状态：通道没连上时，页面仍旧必须说自己是快照。

## 影响

- 部署时**必须重跑路由规则种子**，否则 `/api/v1/platform/public-dashboards/` 在 auth-server 的规则表里没有条目，会走「受管前缀无规则 = 拒绝」。
- nginx 配置变更要随发布一起下，只更新后端不更新网关时公开链接一律 401。
