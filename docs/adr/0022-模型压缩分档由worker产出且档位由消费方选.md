# ADR 0022：模型压缩分档由 worker 产出，且档位由消费方选

- 状态：已接受
- 日期：2026-08-20

## 背景

现场大屏要在浏览器里拉一个 109 MB 的 `.glb`，首帧要等一分多钟。同一个模型在
孪生编辑器里要看清每根管子，在值班大屏上只要认得出轮廓——画质要求差着一个数量级，
而现在只有原件一档。

[ADR-0015](0015-素材字节走对象存储且浏览器直传直取.md) 定下「字节从不经过 API 进程」，
因此「谁来压」不是一个自由选择：它要么在浏览器里，要么在一个**不是 API 角色**的进程里。

## 决策

**一、压缩跑在 `platform-worker`，不在浏览器。** 上传仍是直传三步；finalize 之后
落三行 `pending` 并投一条压缩任务，worker 从对象存储拉原件、逐档压、传回正式前缀。

**二、分三档，排的是画质不是压缩率。** `high`（不减面 + Draco）/ `medium`（50% 面数 + Draco）
/ `low`（25% 面数 + Draco）。原件永远保留且永不改写。

**三、档位存进 `TwinModelRef.variant`，不编进 `asset:<uuid>` 引用串。**

**四、给 `platform-server` 的镜像装 Node 与 `@gltf-transform`。** 这是新增的依赖类别。

## 理由

- **浏览器压不动大的那些。** 解析 + 简化 + 重编码的内存峰值按经验是文件体积的
  10–20 倍，几百 MB 的模型会直接崩掉标签页。更要命的是它把「上传成功」与「压缩成功」
  绑成一件事：用户关掉页面就前功尽弃，而这两者的失败处置完全不同——上传失败要重传，
  压缩失败只要重压，原件还好好地躺在桶里。
- **Python 侧没有可用的 glTF Draco 编码器。** 装 Node 不是偏好而是唯一解；
  否决的替代是「用 C++ 的 draco 命令行」——那样要自己处理 glTF 的容器解析与
  扩展声明，属于把 `@gltf-transform` 做的事重写一遍。
- **档位不进引用串**，因为 `asset:<uuid>` 的语法在服务端 `refs.py`、前端
  `@dt/contracts` 与删除时的按 id 反查里各有一份实现；往里塞 `#low` 要同时改三处，
  而漏掉任何一处都只表现为「取不到」。档位与 `kind` 同性质——由消费语境决定
  （ADR-0015 §4 的推论，拓扑先例见 [ADR-0022 前身 asset:引用统一](../../CONTEXT-MAP.md)）。
- **名字排画质不排压缩率**：选档的人问的是「够不够清楚」。反过来命名
  （`low` = 压得少 = 最清楚）每次读都要在脑子里翻译一次，而翻译错的那次没有任何提示。

## 后果

- **镜像变重**：`platform-server` 实测从 **817 MB 涨到 1.01 GB**（+190 MB：node 二进制
  加 47 个 npm 包，其中大半是 `sharp` 的各平台原生件，由 `ndarray-pixels` 传递引入）。
  三个角色共用一个镜像，故 `api` 与 `publisher` 也白背着 Node。拆成两个镜像是可选项，
  代价是构建与部署各多一套。
- **多一类会失败的后台活**。压缩失败**不影响素材可用**（原件已经落库），但界面必须
  把「压缩中 / 失败」如实显示——不显示的话用户看到的是「选了一档却还是那么慢」。
- **重试只有一层**：worker 不自动重试，失败即写 `failed` + 原因，由人在界面上按「重压」。
  一个压不动的模型重试一万次也压不动，而自动重试会把 worker 占满。
- **加载侧必须接 Draco 解码器**，且解码器要随构建产物自托管——现场不一定有外网，
  走 CDN 的表现是「模型永远加载中」且控制台只有一条被吞掉的跨域错误。
- **存量配置零影响**：`TwinModelRef.variant` 缺省规范化成 `original`，既有大屏的
  表现一个像素都不变。
- 选了一档但那一档还没压好时**回落原件**：不回落的话现场就是一块永远转圈的黑屏。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 浏览器端压缩 | 大模型崩标签页；把上传与压缩的失败处置绑死 |
| 上传时同步压（API 进程里压） | 直接违反 ADR-0015：一个 200 MB 的模型会把一个 worker 占住几分钟 |
| 只做 Draco 无损、不分档 | 画质不变但纹理大头压不到，且「档」无从谈起 |
| 档位编进引用串 `asset:<uuid>#low` | 引用语法有三份实现，漏一处只表现为取不到 |
| 压完删原件省空间 | 原件是压缩失败时唯一的退路，也是重压的输入 |
