# HTTP 终止先撤就绪，再按共享预算关停

每个 HTTP 角色使用共享 Uvicorn 入口。它在本进程首次收到终止信号时将现有 readiness 闸关闭，保留可探测的传播窗口，随后让 Uvicorn 按正常流程关闭监听、处理在途连接并通知 ASGI lifespan。这样负载均衡器可以先读到未就绪，liveness 仍能在监听期间响应。

传播窗口默认 2 秒。各部署按实际 readiness 轮询设置带服务前缀的 `APP_READINESS_WITHDRAW_S`。监听关闭后，HTTP 请求与资源退出钩子共用单调时钟的 `APP_DRAIN_TIMEOUT_S` 截止时刻，默认 20 秒。硬停止的宽限应大于两阶段之和。重复 SIGTERM 不延长窗口，Uvicorn 的强制中断保留原行为。

collector 的领导权、服务既有就绪依赖以及非 HTTP worker、publisher 的停机协议继续由各自生命周期负责。Docker 的存活检查仍使用 liveness。系统角色的资源清理次序见 [运行韧性规范](../agents/runtime-resilience.md)。
