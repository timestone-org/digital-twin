# ADR 0029：助手按能力分七层，每层一个显式注册表；层是能力分层不是执行流水线

- 状态：已接受
- 日期：2026-08-31

## 背景

`apps/chat/services/` 平铺了 25 个模块。功能上没问题，但**横向扩展没有落脚点**：

- 加一路模型来源要改 `llm/provider.py::build_model_source` 的函数体。
- 加一种附件格式要改 `services/tables.py` 的后缀 `if` 链。
- 加一个服务端工具要同时动三处——`tool_specs.TOOL_SPECS`（规格）、
  `server_tools._handlers()`（实现）、技能清单（声明）。漏一处不报错，
  表现是「模型看得见、调一次失败一次」，而那与「这一页没实现它」长得一模一样。

同时有一份外部提出的七层参考架构（感知输入 / 意图理解 / 规划编排 / 记忆系统 /
执行与工具 / 反思反馈 / 输出）。对着代码核过之后，七种能力**六种已经在**，
但都没有命名的接缝；其中三处还是本仓用 ADR 明确否决过的形态。

## 决策

**一、七层是能力分层，不是执行流水线。**

不做 `层1 → 层2 → … → 层7` 的物理管道。真实控制流是一个环
（`think ⇄ use_tools`），中间还跨网络挂起等浏览器（ADR-0023）；把它铺成管道，
每一次「停下来等客户端工具」都要在管道里再发明一次中断态。

**二、七层落成 `services/` 的七个子包，不与 `services/` 平级。**

结构闸 `check_feature_modules_use_public_face` 的判据是「跨功能 import 的路径
第 4 段必须是 `services`」（`_reaches_inside`）。`…apps.chat.services.memory.ports`
机械满足，与它平级的 `…apps.chat.memory.ports` 当场被拦。CLAUDE.md 又规定功能内是
`api → services → crud → models`。放里面两条都满足，放外面两条都违。

⚠ 闸只判第 4 段，**不强制经过 `services/__init__.py`**。「跨功能只认再导出面」
是本仓自己多加的一条约定，闸兜不住，靠评审守。

**三、每层同一副骨架：`ports.py` + `registry.py` + 实现目录。**

扩展一层的动作被钉死成三步：加一个实现文件、注册元组里加一行、加一条契约测试。
调用方只认 Protocol，不认实现。

**四、注册一律是显式元组，不靠 import 副作用。**

与 `skills/__init__.py` 同一口径：隐式注册让「装了哪些实现」取决于 import 顺序，
而顺序在测试里与生产里可以不同。

**五、缺席的能力装 `Null*` 实现，不装半个。**

`NullSummarizer` / `NullLongTermStore` 返回「没有」，调用方按「能力缺席」处理——
与前端那套 ports 范式、以及模型没开时不造对象同一口径。

**六、三条既有 ADR 全部保留，本期每一项改动都要证明自己不与它们抵触。**

ADR-0023（工具在浏览器里执行）、ADR-0024（不建 planner/executor）、
ADR-0025（上下文按缓存稳定性分四层）。其中 ADR-0025 有一道现成的闸
（`tests/contract/test_prompt_prefix.py`），本期新增的摘要段与长期记忆检索结果
都必须在它下面保持绿。

## 理由

- **分层的收益全在接缝上，不在目录上。** 把文件挪进七个目录而不定 Protocol，
  只是换了个地方平铺；定了 Protocol 而不建注册表，扩展仍要改调用方的函数体。
  三件一起做才有「加一个实现 = 加一个文件 + 一行」。
- **能力分层与执行顺序解耦，才装得下这个环。** 七种能力在一个回合里会被反复穿过
  （查一次点位、改一次配置、再查一次），按执行顺序分层的话，每一层都要能被重入，
  那与「分层」这件事本身矛盾。
- **`services/` 之内是唯一同时满足两条既有规范的位置。** 这不是审美选择，
  是两道闸夹出来的唯一解。
- **`Null*` 比条件分支好**：`if summarizer is not None` 会散布到每个调用点，
  而其中一处漏判的表现是「有时候摘要就没了」。

## 后果

- `services/` 下 25 个模块要搬家，import 路径大面积变。搬家单独成 PR 并用
  `check_pr_policy` 的 `[机械]` 豁免——机械移动与行为改动混在一起时，
  评审会跳过其中一半。
- 每层多两个文件（`ports.py`、`registry.py`）。七层就是 14 个，其中多数很短。
- 契约测试要跟着扩：每个注册表都要有一条「注册的实现都满足 Protocol」的用例，
  否则注册表本身就成了新的静默失效点。
- `services/__init__.py` 的再导出清单要有人维护。⚠ 漏一个的表现**不是**被闸拦下——
  闸只判第 4 段是不是 `services`，别的功能包直接 import 子包它一声不吭。这条只能靠
  评审，所以再导出面要短、要有注释说清它是唯一入口。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 七层做成物理流水线（层间单向依赖） | 与 `think ⇄ use_tools` 的环、以及跨网络挂起正面冲突；每次中断都要在管道里重造一次状态机 |
| 七层与 `services/` 平级放在 `apps/chat/` 下 | 违反 CLAUDE.md 的 `api → services → crud → models`；且路径第 4 段不再是 `services`，跨功能 import 当场被结构闸拦 |
| 只定 Protocol 不建注册表 | 扩展仍要改调用方；「加一路模型」依旧是改 `build_model_source` 的函数体 |
| 靠 `__init_subclass__` / 装饰器自动注册 | 「装了哪些实现」取决于 import 顺序，测试与生产可以不同——本仓已在技能注册上拒过一次 |
| 维持现状，只在文档里画七层 | 文档画的层挡不住下一次「顺手加个 if」，而那正是今天 25 个模块平铺的来路 |
