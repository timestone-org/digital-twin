# ADR-0021：公开大屏的匿名实时订阅由推送方登记授权，跨屏跳转的句柄改写成公开令牌

- 状态：已采纳
- 日期：2026-08-19
- 影响范围：`server/services/realtime-hub/`、`server/services/platform-server/apps/dashboard/`、`web/app/src/pages/PublicDashboard/`、`web/app/src/composables/useRealtimeChannel.ts`
- 关系：补上 [ADR-0014](0014-公开大屏是平台唯一的匿名可达面.md) §四 明确留下的那一轮；`interactions` 的下发口径取代 [DASHBOARD_NAV_DESIGN](../DASHBOARD_NAV_DESIGN.md) §6 的一期做法；对 [ADR-0007](0007-实时通道薄化与开放主题命名空间.md) 是**加一条并列的授权来源**，不是推翻它

## 背景

ADR-0014 把公开大屏定成**静态快照**，并写明否决实时的三条理由：匿名订阅要让连接层认令牌、要按令牌限定可订阅的主题集、要防一枚泄露的令牌把连接池吃满——三件事任何一件做漏，代价都是全站共用的连接层被打穿。同一条里也写了出路：「要补实时，走独立一轮，并单开一条 ADR 说明匿名订阅的配额与主题限定怎么做。」本文就是那一轮。

同时 DASHBOARD_NAV_DESIGN §6 把联动规则整段挡在公开面之外，因为规则里存的是**别的大屏的 id**：下发它既与 ADR-0014「公开面不回任何能定位它在库里位置的信息」冲突，拿着 id 在公开态也跳不动（公开路由要的是令牌）。那条也留了出路：把句柄改写成目标屏的公开令牌。

现场要的是这两件的合集：一块挂在墙上、谁都不用登录的屏，数值是活的，点一下能进明细屏。

## 决策

| | 取值 |
|---|---|
| 凭据 | **公开令牌本身**，走 WebSocket 子协议 `dt.public` + 令牌（登录态是 `dt.auth` + access token） |
| 授权来源 | hub 库里的 `realtime.public_grant`：**票据指纹 → 主题**。由 platform 的发布态对账推过去，与主题登记同一条循环（默认 5 秒一轮） |
| hub 存什么 | 只存 `sha256(令牌)` 的十六进制指纹，**不存令牌本身** |
| 客户端订什么 | 别名 `public:<令牌>`。真主题（`dashboard:{id}`）不出现在任何一帧里 |
| 名额 | 每枚票据 50 条、每副本 500 条（可配）。**在 accept 之前判**，超了关 4029 |
| 连接时效 | 匿名连接 1 小时到期（可配），到点由复核任务关 4001，客户端拿同一枚票据重连 |
| 撤回 | 对账把授权注销（≤ 一轮对账）；hub 的复核任务把已连着的匿名连接关掉（≤ 一轮复核，默认 15 秒）。关闭码 4003 |
| 跨屏跳转 | 公开载荷里的 `interactions` **照常下发**，但 `navigate` / `navigateByValue` 的句柄改写成目标屏当前的公开令牌；目标没发布 → **整条规则不下发** |
| 历史数据 | 仍然**不提供**：公开面没有历史端点，`archive` 绑定如实显示为没有数据 |
| 页面状态 | 右下角常驻一条：有实时绑定且通道连着 = 「实时数据」；收到过值但断了 = 「实时数据 · 已断开」；其余 = 「静态快照 · 数据截止 {updated_at}」 |

## 理由

### 一、授权由推送方登记，hub 不回查业务服务

ADR-0007 §决策 3 定的是「订阅授权只比一次，不回调业务服务」。最直接的实现是让 hub 拿着票据去问 platform「这枚令牌能看哪张屏」，但那会把**握手**这条全站共用的路径挂到业务服务的可用性上：platform 抖一下，所有客户端——包括登录态的那些——一起握不上。

所以匿名授权沿用主题登记那套形状：**推送方登记，hub 只比对本地那张表**。它带来的是同一条对账循环里多一支（`public_grants.py`），而对账本来就是 ADR-0007 §决策要求的东西。

代价认下来：新发布的公开链接要等一轮对账（默认 5 秒）才订得上，与「新建的大屏多久之后可被订阅」同一个上界。

### 二、hub 存指纹不存令牌

令牌是一枚**可直接使用的凭据**：拿到它的人就能看那张屏。让它落进通道服务的库里，等于给同一枚凭据多开一处可以被拖走的副本，而 hub 根本不需要原文——它只需要判「你手上这枚，是不是我登记过的那枚」。

握手时现算一次 SHA-256 再比对即可。代价是算法在两侧各写一份（platform 登记时算、hub 握手时算），漂开的表现是**所有公开链接一律订不上、两边都不报错**——所以两侧各有一条契约用例钉住同一个向量。

### 三、客户端只说得出别名，真主题一个字都不出门

ADR-0014 的核心是「公开面不回任何能定位它在库里位置的信息」。若让匿名客户端直接订 `dashboard:{id}`，那个 id 会同时出现在订阅动作与每一帧信封里，等于把这条口径推翻。

所以 hub 给匿名连接记一份「真主题 → 别名」的改名，扇出时按连接改写信封上的 `topic`。别名由票据派生（`public:<令牌>`），客户端本来就拿着它，不多泄露任何东西。

⚠ 别名比对是**逐字**的，不是「以 `public:` 开头就放行」——放松成前缀匹配，一枚票据就能去订别人的。

### 四、撤回必须对**已经连着**的那些也成立

ADR-0014 §二 把「撤回是真的」当成承诺。但一条已经握完手的连接，手里握着的是握手那一刻解出来的授权，此后没有任何一处会重判它——而公开大屏一开就是几天。

因此 hub 多一支复核任务（`services/sweeper.py`），按周期拿本副本的匿名连接去问本地那张授权表，授权没了就把连接关掉。它**只查本服务的库**，不打任何别的服务：跨服务调用会让一次业务侧抖动变成全副本的连接抖动。

登录态连接不走这一支：它们的复核挂在换票那条路上，而按码重判匿名连接会把它唯一那条订阅退掉（它一个权限码都没有）。

### 五、4003 / 4029 与 1008 分开

客户端对 1008 的处置是**停止重连**（票压根验不过，再连也是同样结果）。但匿名这条路上有两种「现在不行、待会儿行」：

- **4003**：这枚票据没有授权。它可能是撤回了，也可能是推送方还没把这枚**新**票据对账过去——后者只要等一轮。合成 1008 的话，刚发布出去的链接会在那几秒的窗口里被客户端判成永久失败，此后一次也不再连。
- **4029**：名额用尽。那是拥挤不是拒绝，照常退避重连。

⚠ 名额必须在 `accept` **之前**判：accept 之后再关，客户端的退避会在 open 那一刻归零，表现是每秒一次的空转重连——正好是名额想挡的那种压力。

### 六、跳不到的规则**整条不下发**，而不是把目标改成空串

DASHBOARD_NAV_DESIGN §6 当时的设想是「未发布的目标改写成空串，前端据此当作不可跳」。改成整条丢掉，理由是：留着规则，源控件的 `meta.interactive` 仍为真、仍摆出可点击外观，点下去什么也不发生——「点了没反应」正是这套设计一路在躲的那种表现。整条丢掉之后，那块模块在公开页上就是一块普通的展示件。

令牌是**现查**的，所以目标屏一撤回，源屏的公开载荷当场就不再带那条规则；目标屏重新发布换了新令牌，规则里跟着换成新的。

⚠ 这一条的代价必须说清楚：**一条公开链接会把它联动指向的、且同样已发布的那些屏的令牌一并交出去**。这是「联动」这件事本身的语义（作者显式配了「点这里进那张屏」，且那张屏也被显式发布过），但它确实让一条链接的影响面不止一张屏。不发布的目标一个字都不会出现。

### 七、公开面仍不接历史

历史序列要打 `/api/v1/platform/point-histories`，那是受保护面。为它再开一条匿名端点意味着匿名可达面从一条变成两条，而 ADR-0014 §一 的整个立论是「匿名面的风险不在于开了一条，而在于开了之后没人记得它是匿名的」。趋势类模块在公开页上如实显示为没有数据。

## 影响

- **realtime-hub 要跑迁移**：新增 `realtime.public_grant`，并把 `realtime.subscription.user_id` 放开可空（匿名连接不属于任何一个人）。放开可空是扩展步，「新结构 + 旧代码」照常可用。
- **撤回的真实窗口**：HTTP 快照面**立即** 404；实时值 ≤ 一轮对账（5 秒）+ 一轮复核（15 秒）。这个窗口要写进运维口径，不要对外承诺「立刻」。
- **名额按副本计**，不是全集群：它防的是一枚泄露的票据把单个副本的连接池吃满，副本之间本来就靠负载均衡分摊。
- **ADR-0014 §四 的降级到此为止**，但它那句「不许去掉截止时刻标注来让页面好看点」仍然成立——现在的形态是三档状态文案：通道没连上时，页面必须说自己是快照。
- 前端的实时通道从此有两种凭据。⚠ 公开页**必须显式接管**：沿用登录态那条的话，未登录时 `accessToken` 恒为 null，表现是一条连接都不建、页面永远是静态快照，而且没有任何报错。
