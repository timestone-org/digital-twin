# ADR 0035：检索编排是策略注册表，`agentic` 是其中一个策略；助手侧另给只读原语

- 状态：已接受
- 日期：2026-09-01

## 背景

「AgenticRAG」这个词至少指两种东西：

1. **检索侧自带一个循环**：改写查询 → 路由 → 召回 → 给结果打分 → 覆盖不足再来一轮 →
   合成带引用的答案。
2. **让 agent 自己决定怎么检索**：把检索原语交给已有的 agent，由它在自己的
   `think ⇄ use_tools` 环里决定查几次、怎么改写。

本仓已经有第 2 种的全部基础设施：助手的环、计划工具、工具注册表（ADR-0023/0024/0029）。
但知识库还要服务**非对话消费方**（将来的报表、告警说明、外部系统），那些消费方
没有 agent 可用。

## 决策

**一、`retrieval/` 层是一个 `RetrievalStrategy` 注册表，不是一条写死的管线。**

```python
class RetrievalStrategy(Protocol):
    @property
    def name(self) -> str: ...
    @property
    def needs_llm(self) -> bool: ...
    async def retrieve(self, request: RetrievalRequest) -> RetrievalResult: ...
```

一期三个实现：`naive`（单次向量召回，基线与对照组）、`hybrid`（向量 + 关键词按
名次融合，**默认**）、`agentic`（带评分与补检的循环）。

**二、`agentic` 需要 LLM；LLM 缺席时它如实不可用，不悄悄退化成 `naive`。**
悄悄退化的表现是「质量忽然变差了」，没有任何一处报错。缺席由
`/capabilities` 如实回答，选它时给一句点得出名字的错。

**三、助手侧另给三个只读原语工具**：`knowledge.search` / `knowledge.get_chunk` /
`knowledge.list_bases`，外加一份 `knowledge-qa` 技能正文。
助手的环自己决定查几次、怎么改写——它手里有整轮对话的上下文，改写查询这件事
它做得比任何服务端启发式都好。

**四、非对话消费方走 `POST /api/v1/knowledge/knowledge-bases/{id}:ask`**，
按库上配置的默认策略跑完整套编排，回「答案 + 引用」。

**五、打分只排序不取舍，并把 `why` 一并交出去；得分为 0 的候选一律不返回。**
与点位召回同一口径（AI_ASSISTANT_DESIGN §3）：硬凑几条出来的话，模型会以为
「就这些了」然后从里面挑一条，那比返回空表难查得多。

**六、`agentic` 的循环有硬上限**（轮数、召回条数、总耗时），到顶就把手上最好的
那一批连同「我没查全」一起交出去。没有上限的话，一次问不到的提问会把 worker 占住。

## 理由

- **两侧各解决一半，而那两半解决的是不同的人的问题。** 助手侧要的是「一步一步
  看得见」与带上下文的改写；非对话消费方要的是「一个接口，进去问题出来答案」。
  只做一侧，另一侧要么用不上，要么质量没法控。
- **策略做成注册表，是因为检索质量这件事一定会反复改。** 写死一条管线的话，
  每一次调整都是改调用方的函数体，而新旧两版没法同时在线做对照。
  注册表让「换一种检索」变成一格配置，A/B 才有可能。
- **`naive` 留着不是为了用，是为了对照。** 出了「召回变差」的报告时，
  没有基线就只能靠感觉。

## 后果

- 库上多一格 `retrieval_strategy`，改它要挡在 `knowledge:manage` 后面。
- `agentic` 走的是 `server/domain/llm`，于是知识库也有了模型配置与断路器，
  配置项要按 config-and-secrets 全量校验、密钥不给默认值。
- 助手侧的工具注册序要重排：`KnowledgeTools` 排在服务端工具之后、客户端工具之前，
  且要有一条闸守着原序（工具声明属于前缀缓存唯一能命中的那一段，ADR-0025 的 B 层）。
- 三个策略各要一套用例；`agentic` 的用例必须用假模型跑，不许打真端点。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 只出原语工具，agent 就是助手 | 非对话消费方用不上；且检索质量分散在技能正文里，没法做对照实验 |
| 只出 `:ask`，助手当黑盒调 | 助手看不见中间过程，「一步一步看得见」那一半没了；且改写查询失去整轮对话的上下文 |
| 写死一条 hybrid 管线，不做注册表 | 每次调整都改调用方函数体，新旧两版没法同时在线对照 |
| `agentic` 在 LLM 缺席时退化成 `naive` | 表现是「质量忽然变差了」，没有任何一处报错，于是没有人会去查 |
