# ADR 0052：嵌入允许永久 API 密钥与 HTTP 传输

- 状态：已接受
- 日期：2026-09-08
- 影响范围：`server/services/auth-server/`、`web/`、`docker/nginx/`
- 部分取代：[ADR-0051](0051-任意业务页用API密钥换短期会话后嵌入.md) 中“嵌入密钥必须有明确到期日”与“生产必须使用 HTTPS/WSS”的要求

## 背景

ADR-0051 把 API 密钥暴露在嵌入 URL 里，但只允许有明确到期日的
密钥换取嵌入会话，并把 HTTPS/WSS 作为生产前置。现场部署需要用固定的
永久 API 密钥，也需要在只有 HTTP 的内网环境直接运行，不接受这两项运行时限制。

## 决策

### 一、嵌入交换与普通 API 密钥共用同一套有效性语义

`POST /api/v1/auth/sessions:from-api-key` 接受任何当前可用的用户 API
密钥，包括 `expires_at=NULL` 的永久密钥。“可用”仍指：

- 密钥存在且明文校验通过；
- 未吊销；
- 设置了到期时间时尚未到期；
- 所属账号存在且已启用。

嵌入交换不再另建一条“必须有到期日”的密钥判定。边缘与端点内部
仍使用同一枚 API 密钥各校验一次，直连 auth-server 不会绕过认证。

### 二、嵌入协议不做运行时门禁

HTTP/WS 与 HTTPS/WSS 都是受支持的部署形态。前端按当前页面协议选择
`ws://` 或 `wss://`；换票请求继续走同源 HTTP，不因 `window.location.protocol`
拒绝嵌入。边缘保留现有 HTTP 监听，是否在前面终结 TLS 由部署方决定。

### 三、短期会话与泄漏缩减措施保持不变

放开的是根密钥有效期和传输协议，不是嵌入会话权限：

- API 密钥仍只用来换取 300 秒 access token，业务 HTTP 与 WebSocket 不直接使用它；
- API 密钥、access token 与用户信息仍只存在 iframe 内存，不写持久化存储；
- 首航仍立即从地址栏删除 `token`，边缘日志仍不记 query；
- `no-store`、`no-referrer`、换票限流、管理面禁入和账号权限校验仍保留。

### 四、风险作为显式告警，不作为阻断条件

永久密钥经 HTTP URL 进入浏览器时，网络路径上的任何被动观察者都能获得
一枚不会自动到期的 Bearer 凭据。访问日志、浏览器历史、截图、扩展与父页
中的 XSS 也可能复制它。本决策有意进一步放宽
[`config-and-secrets.md`](../agents/config-and-secrets.md) 中“密钥不进 URL”与安全传输原则。

界面与文档必须明示该风险，但不阻止用户选择永久密钥或 HTTP。建议为
每个嵌入方使用独立的最小权限账号，定期查看 `last_used_at`，并在疑似泄漏时
立即吊销。永久密钥的回收只能依赖这条人工吊销路径。

## 否决的替代方案

### 一、继续拒绝永久密钥

能限制忘记轮换的最坏暴露期，但会让现场调用方必须追踪根密钥到期时间并
修改 iframe URL；不符合本次对固定凭据的要求。

### 二、在前端或边缘强制 HTTPS

能避免被动窃听根密钥，但会让没有 TLS 终结能力的现场内网无法使用嵌入；
不符合本次 HTTP 直接运行的要求。

### 三、一次性嵌入票据

这仍是密钥不进浏览器时的更安全方案，但嵌入方需要额外开发后端换票与配置面，
与“直接使用 `url?token=api_key&theme=xx`”的接入目标冲突。

## 必须验证的契约

- 有限期与永久 API 密钥都能换取 300 秒嵌入 access token。
- 伪造、已吊销、已过期密钥与停用账号仍不能换票。
- HTTP 和 HTTPS 页面均不被应用层拒绝；实时通道分别使用 WS 和 WSS。
- 密钥不持久化、URL 立即清理、边缘日志脱敏、换票限流与管理面禁入不变。
