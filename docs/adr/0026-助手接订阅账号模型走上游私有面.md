# ADR 0026：助手接订阅账号模型，走上游的私有接入面

- 状态：已接受
- 日期：2026-08-26

## 背景

助手一期只认一个 OpenAI 兼容端点（`ASSISTANT_MODEL_BASE_URL` + API Key，
默认百炼）。用户要的是**用手上那份 ChatGPT / Codex 订阅**跑助手，而不是再按
token 付一份钱；登录动作要在应用里完成，不要求部署机上装 codex CLI。

订阅账号那一路走的是 `chatgpt.com/backend-api/codex`——一个未公开接口，
认证是 OAuth 而不是 API Key。供应商自己的口径是：**自动化应该用 API Key**，
账号态认证只在「你自己的可信机器上跑官方客户端」时才推荐。

## 决策

**一、订阅账号是一路可选的模型，默认关着，与按量那一路并存。**

`ASSISTANT_CODEX_ENABLED` 为假时，这一路的凭据、登录、模型一件都不装。
两路都配好时由**会话**自己选（`chat_sessions.model_profile`），不是全局二选一——
同一个人可能想用便宜那一路闲聊、用订阅那一路做重活。

**二、协议与模型客户端**从 `langchain-openai` 借，不自己实现。

它自带 `chatgpt_oauth`（端点常量、令牌形状）与 `_ChatOpenAICodex`
（把后端那几条硬约束焊死：只走 Responses 面、`store=false`、必须流式、
`SystemMessage` 提升进顶层 `instructions`）。自己重写一遍等于把那几条 400
再踩一次，且每次上游改动我们都要重新踩。

代价是**踩了两个私有名**（前导下划线）。本服务已有一处同类先例
（`llm/reasoning.py`）。做法照旧：一条契约用例钉住导入路径与它强制的那几格——
上游升级时**红的是测试**，不是生产。

**三、登录走设备码，凭据加密落库，续期在我们这一层做。**

- 设备码：页面显示验证链接与用户码，人在任何设备上确认，浏览器轮询。
  ⚠ **这两跳的线形是实测的，不是从上游库里抄的**——它那份 `login_chatgpt_device`
  对不上现在的端点（发表单而端点要 JSON、用 `device_code` 而端点叫 `device_auth_id`、
  本地造 PKCE 而 verifier 由服务端给、指望响应里有 `verification_uri` 而它没有）。
  照它写的第一版四处全错，表现是一句「上游没给出可用的用户码」。
  差异逐条记在 `oauth_client.py` 的文件头，线形由一组用例钉住。
  轮询由浏览器驱动**不起后台任务**——api 角色无状态，下一次轮询可能落到另一个
  副本上，而后台任务会在关停时被 drain 掉，用户看到的是「一直转圈」。
- `device_code` 与 PKCE verifier 是密钥态，一个字都不下发；交给浏览器的是句柄。
- 令牌整包加密进 `assistant.model_credentials`（一路一行），
  上游那个文件版提供者用不了：多副本各有各的文件系统，而凭据是整套部署共用的。
- 续期单飞：拿到 Redis 锁的那个去换，其余的等一小会儿重读库。锁里确实有一次
  网络往返——它有 10 秒硬超时、锁的 TTL 比它长，且**等锁的人不排队**，
  最坏是一次多余的 401 而不是一串挂住的请求。
- 续期被拒（refresh_token 作废）**不删行**：删了界面上是「从来没登录过」，
  而真实情况是「登录过、需要重新来一次」——后者要告诉人。

**四、每一路各有一份断路器。**

共用一份的话，订阅那一路挂掉会把按量那一路一起短路，而后者本来好好的。

## 后果

- 换回按量那一路是**改一格配置**，不是一次回滚。
- 这条路**随时可能被上游改坏**：端点未公开、client_id 未公开。表现会是登录打不开
  头或对话直接 401；那时把 `ASSISTANT_CODEX_ENABLED` 关掉即可，会话历史不受影响。
- **合规责任在部署方**：是否允许用订阅账号喂一个后端服务，取决于账号、工作区、
  订阅与适用条款。`.env.example` 与上游库自己都把这一点写在明面上。
- 截图那条链路眼下**不走这一路**（`supports_vision=false`）：它只在按量那一路
  验过，带图的那一轮照旧落到按量端点上。

## 备选方案

- **只接 API Key**：风险最低，但不满足「用订阅」这条需求本身。
- **把官方 codex CLI 当 sidecar 驱动**：留在官方客户端里，但它自带一整套 agent
  循环与自己的工具，与本服务的工具/计划/客户端工具三条线全都对不上——
  等于把助手换成另一个产品。
- **自己实现 Responses 协议与 OAuth**：多出约 700 行需要长期跟着上游改的代码，
  而收益只是少两个私有名。
