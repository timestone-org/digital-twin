# ADR 0045：拟合参数表达不成 JSON 的模型走对象存储，加载前过四道护栏

- 状态：已接受
- 日期：2026-09-03

## 背景

建模模块最初只上了一条通道：**拟合参数必须能用纯 JSON 表达**，发布时整份写进
`modeling_model_versions.serving_json`，推理时从那一列读回来重建。线性回归、岭
回归、标准化、独热——这些的拟合结果就是几个数与几张映射表，纯 JSON 完全够用。

够不上的是另一半，而它恰恰是用户点名要的那一半：随机森林、梯度提升、PCA 之后的
主成分矩阵。一片 100 棵树的森林是几万个节点对象，写成 JSON 有几十 MB，而且
**重建出来的东西与 sklearn 自己的对象不是一回事**——预测路径要重写一遍。

当时的处理是发布时直接拒：「这个算法的拟合参数没法用纯数据表达，暂不可上线」。
诚实，但它把「树模型」这一整类挡在了平台之外，而工业场景里非线性关系是常态
（负荷—能耗在低负荷段几乎是台阶）。

## 决策

**一、开第二条通道：模型本体序列化成字节，存进对象存储，库里只留一个键。**

算子用 `SERVING_CHANNEL` 声明自己走哪条：`"json"` 是通道 A（拟合参数进
`serving_json`），`"binary"` 是通道 B。

否掉的两种：

- **字节进数据库（`bytea` 或 base64 进 JSONB）**——版本列表页要全量读版本表，
  一行几十 MB 会连着把备份与 WAL 一起撑大；而对象存储本来就在，素材库已经在用。
- **模型转 ONNX / PMML 之类的中立格式**——多一个转换环节、多一套运行时，而两边
  的数值实现不完全一致：同一个模型转换前后算出来的数会差一点点，而那一点点在
  台账上会被当成数据问题查很久。

**二、字节的键由服务端拼，全模块没有任何上传端点。**

`modeling/runs/{run_id}/{node_id}.pkl`（运行期）与
`modeling/models/{version_id}/model.pkl`（版本）。请求里的任何字符串都不进键。

**三、发布时把运行期那份**搬**到版本自己的键下，不是让版本指着运行期那份。**

运行记录有保留期，到期整片删掉。不搬的话，指着它的那些模型版本会在某个夜里
一起变成算不出数的版本，而那时候没有任何一条日志说得清是什么时候开始的。

**四、反序列化前必须过四道护栏，任何一道不过一律拒载并给人话原因。**

1. **只加载本服务自己写的字节**——见决策二；
2. **摘要校验先于反序列化**——对象存储被旁路写入就等于任意代码执行；
3. **受限反序列化**——只放行 `numpy` / `scipy` / `sklearn` / `joblib` 四棵模块
   树，加上点名的十四个内建。这是纵深防御：护栏 1、2 都被绕过时还剩这一层；
4. **训练时与加载时的库版本必须一致**（只比大小版本号）——跨版本反序列化行为
   未定义，放过去的表现是同一个模型换个环境算出不同的数，而两边都不报错。

⚠ 护栏 4 的版本记在**训练那一侧**（节点运行行的 `artifact_json`），不是发布时
现算：发布跑在 api 进程里，那里的 numpy / sklearn 版本未必与工进程一致，现算
会把 api 的版本当成训练时的版本记下来，于是这道闸永远不会响。

**五、发布那一步要真把字节取回来、真算一行。**

一份产物元信息证明不了那些字节还在、还读得回来。取不回来时版本**照样发**，只是
`servable=false` 且理由写在版本上——那比上线后每一格都空着强得多。

**六、通道 B 的「拟合参数」在库里只有一份列序。**

产物自己不记列名，投影按位置取。列序对不上时预测照样算得出来，只是每一列都
错位了——没有异常、没有告警、数看着也正常。所以列序必须与产物一起存。

⚠ 由此带来的一条闸门改动：发布时「该带参数的一步空着就不许上线」那道闸的判据
**不能是「`fitted` 空不空」**——通道 B 的 `fitted` 本来就只有一份列序。判据是
`SERVING_CHANNEL` 加「产物在不在」。

## 影响

- 新表 `modeling_model_artifacts`（一个版本至多一份，随版本 CASCADE）；
  `modeling_node_runs` 加一列 `artifact_json`。两者都是纯扩展步。
- 没配对象存储的部署照样跑得起来：纯 JSON 那些算子一个字节都不产。树模型在那种
  部署上训得出来、发不出去，理由写清楚。
- 反序列化是一次**同步的** CPU 活，在事件循环上跑。线程池不能让它让出 GIL，
  进程池又要把结果再序列化一次送回来。所以：限死产物体积（32 MB）把这一次停顿
  框住，并靠进程内按摘要建键的缓存，让每个进程每份模型只付一次。
