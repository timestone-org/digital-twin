# ADR 0039：模型供应商目录由 platform-server 持有，助手与知识库按用途从目录取端点

- 状态：已接受
- 日期：2026-09-02

## 背景

两个消费方各自从环境变量读模型端点：助手读 `ASSISTANT_MODEL_*`（对话、看图、
摘要、嵌入四档）、知识库读 `KNOWLEDGE_EMBEDDING_*` 与 `KNOWLEDGE_MODEL_*`。同一家
供应商的同一把密钥要在两份 `.env` 里各抄一遍，换供应商要改环境变量再重启两个
服务；界面上的「助手模型」页只能看，不能配。

用户要的是一页**模型管理**：在里面配各供应商的端点与密钥，助手与知识库统一使用。

三条硬约束把落点收窄了：

- 服务之间不许互相 import（CLAUDE.md），跨服务只走 HTTP / 消息 / 只读 SQL；
- 知识库**不许回调助手**，助手也不代理知识库（ADR-0032 决策四，双向同步 RPC
  明令禁止）——所以目录不能放在助手里让知识库来拉；
- `domain/*` 不许含 ORM / CRUD / 依赖注入件（ADR-0004）——所以目录的表不能
  下沉进 `llmcore`。

## 决策

**一、目录由 `platform-server` 持有：`platform.llm_providers` + `platform.llm_assignments`。**

供应商 = 一个 OpenAI 兼容端点（地址 + 密钥）+ 它上面登记的几个模型（代号、
种类 `chat|embedding`、接不接图、嵌入维数）。分配 = 一个**用途**指到一路供应商
上的一个模型。用途是闭合集合（`assistant.chat` / `.vision` / `.summary` /
`.embedding`、`knowledge.chat` / `.embedding`），由平台登记并带 CHECK 约束。

选平台而不是助手，与素材、台账同一个理由：它是**跨消费方的公共资源**，而平台
本来就是数据属主兼配置面。这正是采集计划那条既有先例的形状——平台持有配置、
collector 经内部面拉全量（ADR-0001）。

**二、消费方经内部面拉全量目录，服务级密钥认证，按 TTL 缓存、拉不到沿用旧的。**

`GET /internal/v1/platform/llm-catalog`，带明文密钥，只在集群网内走一跳。
`llmcore` 提供目录的形状、解析、按用途解端点，以及带 TTL 的缓存
（`CatalogCache`）——两个消费方共用同一份，改一处两边一起变。

只有全量、没有增量：增量消息丢一条就永久错位。刷新失败**不清空**手上那一份
（清空等于让平台抖一下把所有会话打回环境变量那一档），并在日志里标明它是陈旧的。

**三、环境变量是永久默认值，目录是运行期覆盖（config-and-secrets §7.1）。**

目录里没给某个用途分配时，那一档照旧走环境变量；分配了就走目录，且只在**那一个
用途**上生效——助手的折叠摘要没分配时仍走环境变量的对话档。这样存量部署一行
配置都不用改：目录整个缺席（平台没配 `PLATFORM_LLM_PROVIDER_SECRET`）时，两边
与今天完全一样。

**四、能力面按「此刻真解得出端点」报，不按配置里的开关报。**

按量那一路的适配器在有目录时**总是**装得出来（断路器按装配了的那几路建），
`profiles()` / `can_answer` / `can_embed` 问的是此刻的目录快照。每个异步入口
（能力探测、回合推进、嵌入调用）先让目录按 TTL 刷新一次，启动时预拉一次。

**五、权限码自成一族：`llm:view` / `llm:manage`。**

目录同时喂两个产品，挂在 `assistant:*` 或 `knowledge:*` 下都不对。订阅账号那一路
仍归 `assistant:manage`——它是助手一家的事。

## 后果

- 全仓多一张「跨三个服务的字面量契约」：用途码在平台、助手、知识库各复述一份。
  三边逐字一致由前端的 `llm-shapes.contract.spec.ts` 对着三份源码比；迁移里
  写死的 CHECK 集合也在那里比。
- 改分配之后两侧在一个 TTL（默认 10 s）内生效，不重启。页面上「当前生效」那一栏
  读的是两个消费方自己的能力面——目录里分配了、那一侧没跟上时只有它看得出来。
- 换加密密钥会让存量密文解不开：那一路整路不下发并响亮记日志，界面上重填即恢复。
- 平台多一枚可选密钥（`LLM_PROVIDER_SECRET`）、一次迁移、一个功能模块；两个消费方
  各多两项配置（刷新周期与超时）。旧地址 `/system/assistant` 重定向到 `/system/models`。

## 备选与为什么不选

| 备选 | 不选的理由 |
|---|---|
| 目录放助手，知识库经助手的 HTTP 面拉 | 知识库回调助手是双向同步 RPC（ADR-0032 决策四），且助手的定位是纯消费方 |
| 目录放助手，知识库跨 schema 只读它的表 | 密钥密文要在知识库再解一遍，加密密钥就得三处共享；解析逻辑还要复制一份，复制品一定会漂 |
| 两个消费方各自一张表、各自一页 | 正是今天「同一把密钥抄两份」的形状换了个地方 |
| 改分配走 Redis 广播即时生效 | 多一条跨服务的键名契约与一个订阅循环；按 TTL 重拉的代价是最多晚十秒，而分配不是秒级操作 |
