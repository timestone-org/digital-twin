# 知识库 — 上下文

## 1. 通用语言

| 词 | 指什么 | 不指什么 |
|---|---|---|
| **知识库** base | 一组共享同一嵌入档与检索策略的知识 | 不是一个文件夹，也不是一个权限域 |
| **来源** source | 知识从哪来的一路实例（一次上传通道、一个外部系统） | 不是一份文档 |
| **文档** document | 来源里的一个条目：一个上传的文件，或外部系统的一条记录 | 不一定是文件 |
| **块** chunk | 检索与引用的最小单位 | 不是一段、也不是一页——切法由 `Chunker` 定 |
| **原件** raw item | 字节 + media type + 文件名，解析层的入参 | 不含「它从哪来」 |
| **定位** locator | 一个块在原件里的位置（页码 / 工作表与行号 / 幻灯片序号 / 标题路径） | 不是块的 id |
| **策略** strategy | 一次检索怎么走（单次召回 / 混合 / 带补检的循环） | 不是一个模型 |
| **转写** transcript | 语音输入到目前为止识别出的**整段**文字（已定稿各句 + 当前句的在线增量） | 不是一帧增量，也不是最终答案 |

⚠ 「**节点**」在本仓指三样东西（画布节点 / 采集点位 / OPC UA 地址空间节点），
本服务一个都不涉及，所以提示词与响应里**不许出现这个词**。

⚠ 「**知识块**」在助手那边另有所指（`assistant.knowledge_chunks`，助手记住的
长期口径，ADR-0030）。两者不共用一张表、也不互相同步：那边是助手自己的记忆，
这边是用户建的知识库。说到本服务的块，一律说「块」不说「知识块」。

## 2. 边界

本服务是本仓第二个**数据属主兼消费方**：

- 只写自己的 `knowledge` schema（库、来源、文档、块、块向量五张表）。
- 外部系统来源的数据经对方的 **HTTP 面**拿，**不读别人的库**。
- 代表用户调 platform 时**原样转发边缘注入的签名身份头**，由 platform 自己判权限。
  知识库绝不用服务级密钥去替用户读它本来读不到的数据。
- **不被 ai-assistant 之外的服务调用，也不回调任何人**（禁双向同步 RPC，
  ARCHITECTURE §6）。
- 与 ai-assistant 共用 `server/domain/llm/`，但两者互不 import。
- 嵌入档与对话档的端点**先问模型目录、再退环境变量**（ADR-0039）：目录由 platform
  持有，经内部面拉、按 TTL 缓存；`KNOWLEDGE_EMBEDDING_*` / `KNOWLEDGE_MODEL_*` 是
  目录的永久默认值。用途码在 `llm_purposes.py` 复述一份，与平台逐字一致由前端契约
  用例守。

## 3. 不变式

1. **摄取状态落库，不留内存。** worker 是多副本、可重启的；留内存的话一次重启就把
   「它卡在哪一步」全丢了，而界面上表现为「一直在处理中」。
2. **认不出的格式当场报错，不许静默给空。** 状态 ready 却检索不到，
   与「这份文档里确实没这句话」长得一模一样——那是最难查的一类故障。
3. **解析跑在进程池里。** docx/xlsx/pptx 的解析是纯 CPU 且阻塞的，放进 async 会把
   整条消费循环连同健康探针一起冻住，而现象是「服务好好的，队列不动了」。
4. **`locator` 不是可选项。** 解析时丢掉它，后面任何一层都补不回来，
   而表现是答得头头是道却指不出出处——用户没法核对，这份答案就等于没有。
5. **`embedding_model` 与 `dimensions` 钉在库上。** 一个库里混两种维数算不出有意义
   的余弦，而表现只是「召回忽然变差了」，没有任何一处会报错。
6. **bytea 是持久真相，pgvector 是加速物化。** 加速结构不进迁移——目标库装不上时
   迁移会当场失败，而迁移是 compose 的前置作业，那意味着整栈起不来。
7. **回退是明说的。** 走在 `BruteForceIndex` 或 `LikeKeywordIndex` 上时，
   `/capabilities` 与管理页都要写着为什么。悄悄退化的表现是「有点慢」「有点不准」，
   没有人会去查。
8. **能力缺席就如实缺席。** 没配嵌入时检索答「这个库还没建索引」，不是返回空表——
   空表与「确实没有相关内容」长得一模一样。
9. **不自动重试。** 一条链路只有一层负责重试，而这条链上那一层是人按的那一下。

## 4. 六层

`apps/knowledge/services/` 下六个子包，每个一副 `ports.py` + `registry.py` +
实现目录（ADR-0029 的三件套）：
`sources/` → `parsing/` → `chunking/` → `embedding/` → `indexing/` → `retrieval/`。

⚠ 六层是**能力分层，不是执行流水线**。摄取那条链确实顺序穿过前五层，但检索只穿过
后两层，而 `agentic` 策略会**反复重入** `indexing/`。

⚠ 注册一律是**显式元组**，不靠 import 副作用：隐式注册让「装了哪些实现」取决于
import 顺序，而顺序在测试里与生产里可以不同。

## 5. 一期不做

- **PDF 与 OCR**。加 PDF = 加一个 `parsing/pdf.py` + 注册元组一行 + 一条契约测试。
  在此之前，传 PDF 的用户拿到的是一句点得出名字的错。
- 权限下沉到文档：一期的粒度是「这个库」。
- 增量重嵌：换嵌入档只能整库重嵌。
- 图片与图表的理解、知识图谱与实体抽取。
