# 建模归档保留身份，部署换版使用修订号与历史记录

模型实例与模型版本增加可恢复的管理归档状态，保留唯一编码、版本号、训练记录与计算本体。
归档不是删除，不释放身份，不级联变更部署或公式绑定；仍有在途训练或资源引用时拒绝归档。
这保留了历史反查与恢复能力，代价是归档对象继续占用原有编码与存储。
它不改变数据库规范中默认真删的约定，明确的模型恢复需求只在建模上下文使用此管理状态。

部署的稳定编码与固定版本保持分离。受控换版与回滚必须提交当前修订号，校验同一建模对象、
任务类型、可服务状态及完整输入输出签名；签名改变需要调用方明确确认。
版本切换、前后版本引用、认证主体与审计在同一业务事务中保存；回滚是一次新的显式切换，
不自动重试。旧 PATCH 继续兼容，未提交修订号的请求不能获得覆盖冲突保护。

迁移仅增加可空字段与新表，不回填、不删除已有资源。旧业务代码忽略归档与修订号，
所以发布时须先暂停建模写入口并停止全部旧 API/worker，再完成扩展迁移与兼容代码升级，
确认全部写者已升级后恢复入口。只有扩展结构与旧代码兼容，不代表归档状态可由旧代码正确执行；
回滚必须保留理解归档状态的兼容版本，不能直接恢复不识别归档的旧业务代码。
