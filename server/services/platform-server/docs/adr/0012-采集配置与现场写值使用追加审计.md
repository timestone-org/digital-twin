# 采集配置与现场写值使用追加审计

平台持有 `collect_audit_events`。事件包括授权账号、UTC 时刻、来源 IP、trace ID、
稳定动作、目标和数据源 ID。配置新增、修改和删除的事件与配置变更在同一事务提交，
批量操作逐目标记录。对审计有用的非敏感字段保留前后状态，设备连接参数、凭据、写值
内容及请求体不保留。目标删掉后仍保留审计，正常 DML 不得改写、删除或清空审计表。

设备动作无法参与数据库事务。写请求须通过鉴权、现有幂等占位和目标校验，在接触
命令总线前提交意图。真实设备回执收到后以另一短事务追加确认、明确拒绝或未确认
事件，一条意图最多有一条结算。请求取消时保留意图，并记录关联 ID；没有结算
只能说明结果未知。审计落库不确定时保留
已有的写值保护窗口，不通过重试审计触发设备重写。设备原值不可知，不追加现场读值。

先部署只新增表和约束的扩展迁移，再部署写入方。旧版本可继续使用已有表，已有历史
无需改写。应用回滚保留审计表，审计事件不跟随配置、时序数据或普通日志清理。
