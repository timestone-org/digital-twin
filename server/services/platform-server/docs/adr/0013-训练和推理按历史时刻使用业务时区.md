# ADR-0013：训练和推理按历史时刻使用业务时区

业务时区由部署的台账聚合时区配置决定。新训练随节点任务传递 IANA 时区名，时间特征按每行时刻在该时区的历史规则取值，重采样按业务时区的实际桶边界对齐。春季跳时和秋季重复时间仍按 UTC 时刻区分。原 UTC 运算的取值和切分规则继续有效。

新发布版本只有在时间特征步骤冻结了 IANA 时区名时才采用可服务格式 2.2。步骤的 `fitted.timezone` 与训练使用的名称一致，推理根据每个输入时刻查询该时区的偏移。2.2 继承 2.1 的冻结缺省语义。存量缺少时区信息的工件照旧按 UTC，存量冻结分钟偏移的工件照旧用同一个固定偏移，不更改存量工件和部署。

先发布能读取 2.2 的 Platform API 和 worker。此时训练仍冻结原有分钟偏移，发布继续生成 2.1。全部读取角色升级后再启用按历史时刻计算的训练。滚动期间发布端根据已冻结步骤选格式，读取新 worker 生成的命名时区拟合时也必须选择 2.2。旧读取者对 2.2 明确拒绝，生成 2.2 后的回滚版本必须能读取它。无法解析的时区不能退回 UTC。对外签名形状和训练图配置均无需迁移。
