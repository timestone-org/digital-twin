# 规则计算模型共用发布资源，计算结果使用结构化接口

归集、流向追溯和单位能耗核算必须保持业务公式与计量守恒，不能用回归近似代替。
它们以 `rule_calculation` 任务复用流水线、不可变模型版本、部署密钥和配额，
不要求目标列或虚构训练标签；`energy_rules` 保存有界、可验证的规则与计量拓扑。
第三方通过独立的 `:calculate` 接口取得核算值、分类明细、路径和命中规则，
不将结构化结果压成既有 `:predict` 的单个预测值。

规则版本冻结计算参数、签名、结果精度与来源；数据源与阈值仍由使用者按现场口径配置。
供应诊断只陈述测量越界及对应规则，流向平衡只陈述计量差额，均不推断未观测的根因。
空调当前状态达标判定属于规则计算，开机达标时长继续遵守根 ADR-0010。

模型版本的计算表示保持不可变，名称与说明允许单独修改；改名不修改训练结果、
模型签名、版本号或部署及公式绑定。该约定收窄旧文档“发布后只读”的范围至计算行为。
共享数据库允许本地新版与现场旧版并存。规则版本独立存于
`modeling_rule_versions`，既有训练版本表的任务约束保持原值域；部署扩展独立的
规则版本引用，两类引用恰好一项有值。新版管理接口合并两类版本，旧版既有内联查询
只看见训练模型及其部署，不会因不认识规则任务而使整个列表失败。
代码回滚后规则资源仍保留在库中，新版恢复后可继续使用。
规则运行投递到既有建模队列派生的独立规则流，由新版 worker 消费，避免共享 Redis
中的旧 worker 领取不认识的算子。新版保留期清理同时保护两种版本的来源运行；
混合部署期间，旧 worker 的过期清理可能被规则来源运行的外键保护阻止，需随部署更新。
混合部署期间每类规则使用独立流水线，不将已经发布规则版本的流水线改回旧训练
队列；旧 worker 的按次数清理不认识规则版本，可能删除规则来源的节点明细。
跨任务复用同一流水线前须升级全部 worker；规则模型计算本体始终由版本表保留。
