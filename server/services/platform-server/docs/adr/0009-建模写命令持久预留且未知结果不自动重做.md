# 建模写命令持久预留，未知结果不自动重做

创建、配置、训练、发布与部署命令需要跨浏览器恢复提交结果。建模命令由 platform 持有，
按认证账号、操作范围与幂等键摘要唯一，保存参数指纹和安全结果，不保存原始密钥或请求体。
同键不同参数是冲突；命令详情与按键查找只允许认证账号自身访问，并校验对应操作权限。
共享模型资源域不等于共享命令结果，模型调用与管理仍遵守根 ADR-0062 的账号权限。

先用独立短事务预留命令，随后将业务变更与成功结果放在同一事务提交，
避免 Redis 成功缓存先于业务事务提交，也避免在发布产物等外部 IO 期间持有幂等锁。
代价是预留后进程中断可能留下一条不能证明是否执行的命令。
处理中或结果未知的命令只能查询与人工核查，不因超时自动接管或重新执行；
数据库已提交但 HTTP 响应丢失时，同键请求可以回放已保存结果。
这提供持久恢复与不盲目重复提交的保证，不承诺跨数据库和对象存储的 exactly-once。

认证账号始终是审计主体。外部能管操作人是另一项声明，只接受配置授权的专用网关账号提交，
与平台账号分别保存，不能把未经验证的请求头变成平台用户身份。
命令、归档、部署切换与模型调用审计不记录完整输入数据和凭据。
