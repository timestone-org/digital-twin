# ADR-0001：点位候选读取先兼容 HTTP

助手只消费平台点位语义检索，不创建数据源、连接现场或更改权限。`PointMatch`
读取模型固定接受 `http` / `modbus_tcp` / `opcua`，其它值及错误类型仍失败关闭。
协议类型保持严格闭合字面量，不改为任意字符串。

平台滚动升级之前，助手读取者先行发布。契约要求平台协议值域是这三个已知值的
子集，并保留两种既有协议；读取者允许值域固定等于这三个值。旧平台的两值与新
平台的三值分别验证。字段集合、必填、类型、可空性、单值 `const` 和其它枚举仍
逐字段严格相等。常量缺键与显式 `null` 不同；常量和枚举按
[JSON 实例相等规则](https://json-schema.org/draft/2020-12/json-schema-core#section-4.2.2)
区分布尔与数字，数字按数学值比较，数组顺序及对象成员值递归比较。
未知协议、移除既有协议及其它字段漂移必须使测试失败。

该约定将读取者的兼容能力与生产者当前输出区分开，使助手先行版本及随后平台
兼容版本都可单独构建验证。跨服务仍通过原用户签名身份头读取，不使用服务密钥
代替用户授权。新协议不会改变点位身份、排序、检索降级状态和工具调用权限。

完整 HTTP 写面必须等全部旧读取者退出后发布。存在 HTTP 行时，助手不得回滚到
仅接受旧两种协议的版本；可回滚到本读取兼容版本，平台下限另见平台 ADR-0002。
兼容版本提交 SHA 应由真实交付记录填写，本决策不宣称已部署。
