# 批量绑点

把大屏（或 3D / 2D 孪生子编辑器）上模块的**数据槽位**接到**采集点位**上。
这是助手最省人力的一件事：一屏几十个槽位，人工要在挑点弹窗里搜几十次。

**用户要的不是「绑完了」这三个字，是连点的过程中就看得见数出来。**
所以这件事的节奏是「绑一个 → 保存 → 看那一行有没有数」，不是「闷头绑完一屏
再一起交差」。

## 先认清三个「节点」不是一回事

这套系统里 node 指三样东西，**回话时一律用全称，不许简称**：

- **画布节点**：大屏上的一个模块实例，id 是 uuid。
- **点位**：采集来的一个测点，身份是 `node_key`，形如 `{数据源id}:{点位编码}`，
  **按第一个冒号切分**。
- **地址空间节点**：OPC UA 服务器里的节点，与本技能无关。

## 工作顺序

1. `dashboard.read_canvas` 看清这一屏有哪些画布节点、各是什么模块。
2. **动手之前先读绑定**：`dashboard.read_bindings` 读目标节点的槽位声明，
   以及**每一行此刻喂的是谁**（`entity`）。槽位是模块清单定死的，
   不能凭空造一个槽键。
3. 已经绑着东西的行，把那些 `node_key` 收一批交给 `points.resolve` 换成名字，
   跟 `entity` 对一遍。**光看 `node_key` 那串身份认不出绑没绑对。**
   进了 `unknown` 的那几个是库里真的没有的点位，如实报给用户。
4. 弄清用户要什么：
   - 说了「把 1 号机组的温度绑上」→ 直接进第 5 步。
   - 上传了点表 → 表的内容已经摊平在用户那句话里，把表里的行与槽位对上。
   - 什么都没说 → **问一句**，不要自己猜整屏该绑什么。
5. `points.list_sources` 看有哪些数据源；`points.search` 按关键词找候选。
6. 进「绑—存—看」的循环（见下一节），一次一个槽。
7. 全部写完后 `dashboard.validate` 自检，把悬空的报给用户。

## 绑—存—看：这件事的主循环

对每一个（或每一小批）槽位：

1. `dashboard.write_binding` 写进去。
2. `dashboard.save` 保存。**不保存就一个数都不会出来**——实时推送按**已落库**
   的绑定组装推送计划，编辑器草稿里的绑定它看不见。
3. `dashboard.read_values` 读那个画布节点此刻的读数，看刚绑的那一行是不是
   真有数了。

⚠ **第一次 `dashboard.save` 之前先跟用户说一句**：保存的是**整份草稿**，
连他自己刚改还没保存的那些一起落库。说完再存，别先斩后奏。

⚠ **`waiting` 不等于这个点位坏了**。`read_values` 回的 `status` 有四档：

| status | 意思 | 你该做什么 |
|---|---|---|
| `has_value` | 有数 | 这一行成了，接着下一个 |
| `waiting` | 订上了，还没来第一帧 | **等一下再读一次**，别动绑定 |
| `unavailable` | 订不上，或这个点位不推 | 报给用户；怀疑绑错了就 `points.resolve` 核一遍 |
| `unbound` | 这一行还空着 | 还没绑，去绑 |

刚保存完就读，多半整屏都是 `waiting`。**看见 waiting 就去改绑定，是这件事
最容易做错的一步**——改完还是 waiting，然后你会以为点位全是坏的。

⚠ `dashboard.save` 失败就**停下来**，尤其是 409（别人动过这张屏）：
那之后你再绑多少条都存不进去，接着往下做等于白做。把失败如实报给用户。

## 怎么找对点位

**能用的信号只有三样**，按可靠度排：

| 信号 | 说明 |
|---|---|
| `name` | 中文全称，如「1号机组出口温度」。**最可靠**，优先用它 |
| `code` | 工业缩写编码，如 `K1_TMT_HOT_T_PI`。需要按缩写词表解读 |
| `unit` | 单位，用来交叉验证。℃ 配温度槽，kPa 配压力槽 |

⚠ **`address` 基本没有语义**：真实现场里大部分节点是 `i=2253` 这样的裸数字标识，
那是 OPC UA 的标准诊断节点，与业务毫无关系。**不要拿 address 猜业务含义。**

⚠ **点位表没有描述、没有分组、没有设备归属**。想按设备收窄只能靠 `code` 的前缀
（`K1_` = 1 号机组）或数据源本身。

### 检索结果怎么读

`points.search` 回来的每一条带 `score` 与 `why`。**`why` 说的是「它为什么排在
这」**——「名字里含这个词」比「编码解读出温度」可靠得多。分数只用于排序，
不构成取舍：选哪一个由你定，因为只有你知道用户这句话的上下文。

⚠ **空表就是真的没找到**，不是「再换个词就有了」。换一两个说法可以，但连着
换三次还是空，就该把这个槽留空并告诉用户，而不是从别的槽的候选里挑一个凑上。

### 常见工业缩写

`TT`/`TMT` 温度 · `PT` 压力 · `DP` 压差 · `FT` 流量 · `LT` 液位 ·
`AT` 分析 · `PI` 过程量后缀 · `SP` 设定值 · `PV` 测量值 · `MV` 输出值 ·
`RUN`/`ST` 运行状态 · `ALM` 报警 · `FREQ` 频率 · `KW`/`POW` 功率

编码常见形状：`<机组>_<测点类型><序号>_<介质或位置>_<后缀>`，
例 `K1_TMT_COOL_T_PI` = 1 号机组冷侧温度过程量。

## 用户选中了东西的时候

快照里的 `selected` / `selected_ids` 说的就是用户此刻选中的那几个。
他说「把**这几个**接上」「这些都绑一下」时，指的**只有那几个**。

- **只动名单上的那几个**，一个都不许多。旁边那个看着也该绑的、
  上一轮你自己挑中的那个，都不算。
- 名单被截断了（快照会明说还有几个没列出来）就**问一句**，
  别按列出来的那一截当成全部。
- 他没选任何东西又说「这几个」，问清是哪几个，不要自己圈一批。

## 照着另一处接一遍

「1 号机组接好了，2 号机组照着接」用 `dashboard.copy_bindings`，不要手抄。

1. 先 `dry_run: true` 跑一次，把 `copied` 与 `skipped` 拿给用户过目。
2. `copied` 里覆盖掉目标原有绑定的那几条要**点出来**。
3. `skipped` 里的**如实报**：按名字对不上就是对不上。
4. 用户确认后再 `dry_run: false` 落一次，然后照常 `dashboard.save` +
   `dashboard.read_values`。

⚠ **匹配不上不要改用 `by_index` 硬抄。** 按行号对齐是这套数组绑定最容易出
「每一条都有值、但全接错对象」的地方，而那种错在画面上完全看不出来。

⚠ 它抄的**只是取数来源**。标题、单位、阈值这些配置归 `dashboard.set_config`，
不要指望它一起过去——真一起过去了，2 号机组的标题会变成「1 号机组…」。

## 不许做的四件事

1. **不许瞎绑**。一个槽位找不到有把握的点位，就把它留空并在最后列出来，
   由用户定夺。绑一个看着像的点位，会画出一条一直有数、但数错了的曲线——
   那比空着难发现得多。
2. **不许改槽键**。改槽等于换一条绑定，而绑定 id 是实时推送的关联键。
   要换槽就先解绑再绑。
3. **不许扩大范围**。用户点了三个模块，就只动那三个；顺手把第四个也接上，
   下次他就不敢让你动这一屏了。
4. **不许一次绑完不核对**。写完必须 `dashboard.validate`，
   并用 `dashboard.read_values` 看过数。

## 收尾要说清的三件事

1. 哪几行接上了、各接的是哪个点位（用名字说，不要念 `node_key`）。
2. 哪几行**没**接上、为什么（找不到候选 / `unknown` / `skipped`）。
3. 读数此刻是什么状态：还在 `waiting` 的那几行说清「订上了还没来第一帧，
   过一会儿就有」，别让用户以为是坏的。

## 不接点位的那几种槽

不是每一格都来自现场。用户说「这一格就写 380」「额定值填死」时，
用 `dashboard.write_binding` 的 `source_kind: "static"` 加 `value`：

```
dashboard.write_binding(node_id=…, field_key="itemValues[2].value",
                        source_kind="static", value=380)
```

- `value` 可以是数字、文本、真假。
- ⚠ **不能给 `null`**：那一层把 null 读成「没配过」，画面上是「取不到」
  而不是空值，而你会以为自己配好了。
- 常量槽没有历史、也不推送，所以趋势图那类时序槽绑常量是没有意义的。

⚠ 常量与点位**是同一条绑定的两种取数方式**。要把一个已经绑了常量的槽改接
点位，直接再写一次 `write_binding`（换成 `opcua` 加 `node_key`）——
不要先 `remove_binding` 再绑：绑定 id 是实时推送的关联键，解了再绑会断一次。

## 数组槽位

多数数据模块的槽位是**数组槽**（一个槽对应 N 行），槽键形如 `itemValues[0].value`。

- 行号**必须从 0 起、连续**。跳号的绑定服务端会拒收。
- 有的数组槽是**钉在实体上**的（孪生的锚点、信息牌）：第 i 行喂配置里第 i 个实体，
  行数由配置决定。这种槽 `dashboard.read_bindings` 会给出每行对应的实体名字
  （`entity`），**按名字对，不要按行号猜**。
- 还没绑的行也会出现在 `rows` 里、`node_key` 为 null。那不是这一行不存在，
  是它还空着——正好是你要接的那些。
