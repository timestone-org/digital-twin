# 组态大屏

在大屏画布上摆模块、改它们的配置与外观、做对齐排版。

## 先看地图再动手

`modules.catalog` 是**唯一的模块真源**，分两步给：

1. 先按 `category` 或 `keyword` 筛选 → 一页模块的**名片**（类型、中文名、分类、别名、默认尺寸、
   绑定槽、有几个配置字段）。需要更多时用 `next_page` 继续，认出目标即停止。
2. 带 `module_type` 再调一次 → 那一个模块的**配置字段全表**（类型、默认值、
   可选值、条件显示）、绑定槽详情、出厂配置、现成观感预设的目录，外加两张
   **图例**。**动配置之前必须走这一步。**
3. 想套某一套现成观感时，带 `module_type` + `preset=<id>` 第三次调它 →
   那一套预设的完整配置。

⚠ 整份清单一次给不得，所以名片里没有配置字段。凭名片猜键名等于凭印象填。

### 展开结果里那两张图例

`field_types` 说的是每一档 `type` 该写**什么形状的值**，`binding_data_types`
说的是每一档绑定槽收什么。你没有属性面板可看——`type: "enum"` 那一格该写
`options[].value` 里的哪一个、`type: "boolean"` 认不认 `"true"` 这个串、
`type: "image"` 接不接 CSS 渐变，只有图例说得出来。**写之前先看它。**

⚠ `default` 是**不落库**的渲染兜底：配置里没有这个键就是没配过。要恢复缺省是
把键删掉（值给 `null`），不是写一个你以为的默认值进去。

⚠ 带 `when` 的字段只在条件满足时才生效，而且条件是**链式**的：控制它的那个
字段自己不生效时，它也不生效（页头的「扫光宽度 ← 开了扫光 ← 选了带花纹的风格」
就是这个形状）。

⚠ 展开结果里有 `sub_editor` 的那个配置键由**整页子编辑器**接管，它的内部形状
不在清单里（孪生场景、2D 画面就是）。不要往那个键里写——写进去既不报错也不渲染。

### 预设：别逐个字段去凑一套观感

有些观感是十几个字段的组合（切角按钮、储罐仪表、告警列表）。展开结果里的
`presets` 是目录页，只有 `id` / `label` / `hint`；带 `preset=<id>` 再调一次拿到
`config`，再**逐键**写进节点配置。

⚠ 预设是**浅合并**：没列出的键原样保留，不要先清空再写。
⚠ 预设里可能带 `__cardStyle` 那一段，它的写入路径是 `["__cardStyle","<键>"]`，
与顶层字段不一样。

⚠ **不要凭印象填配置键**。清单里没有的键写进去不会报错，也不会生效——
画面上表现为「配了没反应」，而配置确实存下去了。

⚠ 用户说的模块名是中文（「数值卡」「按钮」），清单里每个模块带 `keywords`
（含拼音），按它对上模块类型，**不要自己音译**。

## 改配置的四步

配置是一只**自由袋子**：写一个清单里没有的键既不报错也不渲染，画面上表现为
「配了没反应」，而配置确实存下去了。所以每次改配置都走这四步：

1. `modules.catalog` 带 `module_type` —— 这个模块**能配什么**（键、类型、
   默认值、可选值、条件显示、数组字段的 itemSchema），以及每一档类型该写
   什么形状的值（`field_types` 图例）。
2. `dashboard.read_config` —— 这个画布节点**此刻配成什么样**。
   ⚠ 不读就写，等于把用户已经调好的那几格一起冲掉。
3. `dashboard.set_config` 改单个键，或 `dashboard.add_config_item` /
   `dashboard.remove_config_item` 增删数组字段里的一项。
4. 把改了什么用一句话说给用户听。

`dashboard.set_config` 的 `path` 是**路径数组**：

| 要改的东西            | path                             |
| --------------------- | -------------------------------- |
| 顶层字段              | `["title"]`                      |
| 数组里第 2 项的某一格 | `["items", 1, "unit"]`           |
| 卡片外观              | `["__cardStyle", "borderStyle"]` |

⚠ 往数组字段里**加一项**不要用 `set_config` 整份重写——用
`dashboard.add_config_item`，它按 itemSchema 填好默认值再盖上你给的那几格。
整份重写会把没提到的字段全变成 `undefined`。

## 动手的边界

- 每一步都立刻显示在用户的画布上，用户能 Ctrl+Z 撤单步。
- **删除节点会连子树一起删**。删之前先说清要删什么、有几个子节点。
- 不要替用户保存。
- 一次只做用户要的那件事。用户说「加一个数值卡」，就加一个，
  不要顺手把整屏重新排版一遍。

## 多步任务与截图验收

- 要动 3 个以上对象（摆一片模块、整屏排版、批量改外观）时，先用
  `plan.write` 把步骤列出来再动手，每完成一项立刻更新状态。
- 布局与外观是**看效果**的活：计划的收尾项固定是「截图自检」——用
  `dashboard.capture` 看一眼成品，位置错了、挤在一起、颜色不对就把修正项
  补进计划接着改。没看过图不许把收尾项勾掉。
- 看图时把结论**当场写成文字**（哪几块要动、动成什么样）：图只在这一轮
  看得见，下一轮只剩一句占位。
