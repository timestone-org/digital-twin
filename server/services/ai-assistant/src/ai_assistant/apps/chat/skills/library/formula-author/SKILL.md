# 写公式

为台账的公式列写表达式。**写完必须自己验过再交给用户。**

## 唯一的函数真源

`formula.catalog` 默认给出一页函数和求值口径。`table_id` 从工作面快照里取。
需要引用本表列、跨表或公式库时，分别指定 `section=columns`、`tables`、`library`。
按 `category` 或 `keyword` 缩小范围；需要更多时保持筛选和 `limit` 不变，
使用 `next_page` 自行继续，找到目标就停止。

不给 `keyword` 时函数只有名字、签名与一句话；想看样例与参数名，就带上
`keyword` 再要一次（「同比」「PREV」都行），它只回匹配的那几个并展开。

⚠ **不许凭记忆写函数名**。目录里没有的函数写出来是「未知函数」，
而用户看到的是一条报错，不知道是你编的。按词查不到时就直说没有这个函数，
不要挑一个名字像的顶上。

## 按需参考

编写或校验公式前，先用 `skills.read_resource` 读取 [formula-semantics.md](references/formula-semantics.md)。

## 工作顺序

1. `dataset.read_columns` 看清这张表有哪些列、各是什么类型与单位，
   以及已有的公式列现在是怎么写的。
2. `formula.catalog` 拿函数目录（要样例就带 `keyword` 再要一次）。
3. 写出表达式。
4. `formula.validate` 验语法、依赖与环。
5. `formula.preview` 带一组**你自己编的样例值**试算 —— 它不读台账里的真数据，
   所以空表也能验。看返回的 `value` 是不是你预期的那个数。
6. 把表达式、它的读法、以及试算结果一起给用户。

⚠ 试算返回的 `history_refs` 列出了**按空处理**的那些引用（`PREV`、时间窗、
整列、跨表）。有这一项时要明说「这几项试算时按空算，实际取数后才准」。

## ⚠ 台账页没有撤销

大屏编辑器改的是草稿，台账页**每一次写入都是真实落库、没有撤销栈**。
所以：

**你只提议，不落库。** 用 `dataset.propose_formula` 把写好并验过的表达式交给
用户：界面上会出现一张卡，他点「填进编辑器」才带进弹窗，**保存还是他自己按**。

⚠ 提议里的 `column_key` 对新列**建后不可改**——它是数据行里的字段名，也是别的
公式里的 `{列key}`。给一个将来会后悔的 key，用户改不回来。所以新列的 key
要先跟用户对一句。

改一条**公式库**条目影响更大——它属于全库，会同时改掉所有引用它的台账列。
碰它之前必须先说清有多少列在用。
