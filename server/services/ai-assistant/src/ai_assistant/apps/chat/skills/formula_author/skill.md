# 写公式

为台账的公式列写表达式。**写完必须自己验过再交给用户。**

## 唯一的函数真源

`formula.catalog` 给出这张表能用的全部函数、运算符、可引用的列与跨表、
公式库条目，以及九条求值口径。

⚠ **不许凭记忆写函数名**。目录里没有的函数写出来是「未知函数」，
而用户看到的是一条报错，不知道是你编的。

## 记法

- 引用本表的列：`{列key}`
- 引用别的台账：`{表code.列key}`（按**第一个**点号切分）
- 调公式库：`@标识(实参)`
- 列 key 允许中文；公式库的 code 也常常是中文（`@同比增长率(...)`）

## 必须记住的求值口径

这几条最容易写错，且错了不报错、只是算出来的数不对：

- **四则运算里任一值为空 → 整条为空**。要兜底就显式用 `IFS` + `ISBLANK`。
- **`SUM`/`AVG`/`MIN`/`MAX` 与所有 `*_OVER`/`*_ALL` 跳过缺失值**，不当 0。
- **除零得空**，不报错。
- **`PREV` 不含当前行，而 `*_OVER` 含当前行**。这一条几乎每个人第一次都写反。
- **判空只能用 `ISBLANK`**，不能用 `== 0` 也不能用 `== ''`。
- **公式列可以引用公式列，但不能成环**。

## 工作顺序

1. `dataset.read_columns` 看清这张表有哪些列、各是什么类型与单位。
2. `formula.catalog` 拿函数目录。
3. 写出表达式。
4. `formula.validate` 验语法、依赖与环。
5. `formula.preview` 带一组**你自己编的样例值**试算 —— 它不读台账里的真数据，
   所以空表也能验。看返回的 `value` 是不是你预期的那个数。
6. 把表达式、它的读法、以及试算结果一起给用户。

⚠ 试算返回的 `history_refs` 列出了**按空处理**的那些引用（`PREV`、时间窗、
整列、跨表）。有这一项时要明说「这几项试算时按空算，实际取数后才准」。

## ⚠ 台账页没有撤销

大屏编辑器改的是草稿，台账页**每一次写入都是真实落库、没有撤销栈**。
所以：

**你只提议，不落库。** 用 `dataset.propose_formula` 把写好并验过的表达式交给
用户，由他点确认。绝不要在用户没明确同意之前改任何一列。

改一条**公式库**条目影响更大——它属于全库，会同时改掉所有引用它的台账列。
碰它之前必须先说清有多少列在用。

## 几个真实例子（这套系统里在用的）

```
同比增长率    ({本期} - PREV({本期}, {周期数})) / PREV({本期}, {周期数}) * 100
增量          {累计值} - PREV({累计值}, 1)
占全表比例    {值} / SUM_ALL({值}) * 100
滑动均值      AVG_OVER({值}, {窗口})
安全除        IFS(ISBLANK({分母}), {兜底}, {分母} == 0, {兜底}, {分子} / {分母})
达标判定      IF({实测} <= {限值}, 1, 0)
```

时间窗写法：`30s` `15m`（**分钟不是月**）`1h` `1d` `1w` `3mo` `1y`。
