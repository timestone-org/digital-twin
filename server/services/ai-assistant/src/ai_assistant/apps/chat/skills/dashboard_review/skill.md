# 看图提建议

截图看画面，给布局与信息层级上的改进建议。

## 先截图，再配合读画布

`dashboard.capture` 给一张当前画布的图；`dashboard.read_canvas` 给结构。
**两样都要**：图上看得出「挤」「空」「不齐」，但看不出节点 id——
而给建议要能指名道姓说是哪一个。

三维模块（孪生视图）截得到：截图前会给每个 WebGL 画布重画一帧、
用 2D 替身顶上。⚠ 若某个三维区域仍是空白，那是**这一次截取失败**
（场景还没渲染出来、或画布被污染），不是「这里漏配了」——先按
`dashboard.read_canvas` 确认那一格是什么再下结论，不要建议往那儿加东西。

⚠ **图只活在这一轮。** 下一轮你只看得见一句「[截图]」——所以看完必须当场把
结论写成文字。想着「等下再回头看那张图」的话，回头时它已经不在了。
要再看就再截一次。

## 看什么

按这个顺序，先结构后细节：

1. **信息层级**：一眼看过去，最重要的数字是不是最显眼。大屏是给人在几米外
   扫一眼的，不是给人凑近读的。
2. **对齐与间距**：边缘是否对齐、间距是否一致。歪一两个像素比歪二十个更难看，
   因为它像是没对齐而不是有意错开。
3. **密度**：有没有大片空白，或者挤到看不清。
4. **配色**：状态色（红/黄/绿）有没有被装饰色抢掉。装饰用色越多，
   真正表示告警的那个红就越不像告警。
5. **文字**：字号是否够大、标题与正文是否分得开。

## 怎么给建议

- **具体到节点**。说「左上角那个数值卡（id 前八位 `a1b2c3d4`）比右边三个矮 12 像素」，
  不说「布局可以再优化一下」。
- **给出可执行的下一步**，并用 `user.ask` 问要不要现在就改。
  可以改就切到组态技能去做。
- **最多给五条**，按影响从大到小。一口气列二十条等于没给建议。
- **不评价数据本身**。屏上的数值对不对不是布局问题。

## 不要做的事

- 不要因为「看起来空」就自作主张加模块。
- 不要重排整屏。整屏重排的结果几乎一定不是用户想要的，
  而它把用户此前所有的手工调整一次抹掉。
