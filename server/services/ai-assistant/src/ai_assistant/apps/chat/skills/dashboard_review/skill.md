# 看图提建议

截图看画面，给布局与信息层级上的改进建议。

## 先截图，再配合读画布

`dashboard.capture` 给一张当前画布的图；`dashboard.read_canvas` 给结构。
**两样都要**：图上看得出「挤」「空」「不齐」，但看不出节点 id——
而给建议要能指名道姓说是哪一个。

⚠ 三维模块（孪生视图）在截图里**多半是一块空白**：它用 WebGL 画，
截图库抓不到画布内容。看到大片空白时先确认那一格是不是三维模块，
**不要把它当成「这里漏配了」**。

## 看什么

按这个顺序，先结构后细节：

1. **信息层级**：一眼看过去，最重要的数字是不是最显眼。大屏是给人在几米外
   扫一眼的，不是给人凑近读的。
2. **对齐与间距**：边缘是否对齐、间距是否一致。歪一两个像素比歪二十个更难看，
   因为它像是没对齐而不是有意错开。
3. **密度**：有没有大片空白，或者挤到看不清。
4. **配色**：状态色（红/黄/绿）有没有被装饰色抢掉。装饰用色越多，
   真正表示告警的那个红就越不像告警。
5. **文字**：字号是否够大、标题与正文是否分得开。

## 怎么给建议

- **具体到节点**。说「左上角那个数值卡（id 前八位 `a1b2c3d4`）比右边三个矮 12 像素」，
  不说「布局可以再优化一下」。
- **给出可执行的下一步**，并问用户要不要现在就改。可以改就切到组态技能去做。
- **最多给五条**，按影响从大到小。一口气列二十条等于没给建议。
- **不评价数据本身**。屏上的数值对不对不是布局问题。

## 不要做的事

- 不要因为「看起来空」就自作主张加模块。
- 不要重排整屏。整屏重排的结果几乎一定不是用户想要的，
  而它把用户此前所有的手工调整一次抹掉。
