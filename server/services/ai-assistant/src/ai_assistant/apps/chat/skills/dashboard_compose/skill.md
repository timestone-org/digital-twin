# 组态大屏

在大屏画布上摆模块、改它们的配置与外观、做对齐排版。

## 先看地图再动手

`modules.catalog` 是**唯一的模块真源**，分两步给：

1. 不带参数调它 → 全部模块的**名片**（类型、中文名、分类、别名、默认尺寸、
   绑定槽、有几个配置字段）。认模块用这一步。
2. 带 `module_type` 再调一次 → 那一个模块的**配置字段全表**（类型、默认值、
   可选值、条件显示）、绑定槽详情、出厂配置、现成观感预设的目录，外加两张
   **图例**。**动配置之前必须走这一步。**
3. 想套某一套现成观感时，带 `module_type` + `preset=<id>` 第三次调它 →
   那一套预设的完整配置。

⚠ 整份清单一次给不得，所以名片里没有配置字段。凭名片猜键名等于凭印象填。

### 展开结果里那两张图例

`field_types` 说的是每一档 `type` 该写**什么形状的值**，`binding_data_types`
说的是每一档绑定槽收什么。你没有属性面板可看——`type: "enum"` 那一格该写
`options[].value` 里的哪一个、`type: "boolean"` 认不认 `"true"` 这个串、
`type: "image"` 接不接 CSS 渐变，只有图例说得出来。**写之前先看它。**

⚠ `default` 是**不落库**的渲染兜底：配置里没有这个键就是没配过。要恢复缺省是
把键删掉（值给 `null`），不是写一个你以为的默认值进去。

⚠ 带 `when` 的字段只在条件满足时才生效，而且条件是**链式**的：控制它的那个
字段自己不生效时，它也不生效（页头的「扫光宽度 ← 开了扫光 ← 选了带花纹的风格」
就是这个形状）。

⚠ 展开结果里有 `sub_editor` 的那个配置键由**整页子编辑器**接管，它的内部形状
不在清单里（孪生场景、2D 画面就是）。不要往那个键里写——写进去既不报错也不渲染。

### 预设：别逐个字段去凑一套观感

有些观感是十几个字段的组合（切角按钮、储罐仪表、告警列表）。展开结果里的
`presets` 是目录页，只有 `id` / `label` / `hint`；带 `preset=<id>` 再调一次拿到
`config`，再**逐键**写进节点配置。

⚠ 预设是**浅合并**：没列出的键原样保留，不要先清空再写。
⚠ 预设里可能带 `__cardStyle` 那一段，它的写入路径是 `["__cardStyle","<键>"]`，
与顶层字段不一样。

⚠ **不要凭印象填配置键**。清单里没有的键写进去不会报错，也不会生效——
画面上表现为「配了没反应」，而配置确实存下去了。

⚠ 用户说的模块名是中文（「数值卡」「按钮」），清单里每个模块带 `keywords`
（含拼音），按它对上模块类型，**不要自己音译**。

## 改配置的四步

配置是一只**自由袋子**：写一个清单里没有的键既不报错也不渲染，画面上表现为
「配了没反应」，而配置确实存下去了。所以每次改配置都走这四步：

1. `modules.catalog` 带 `module_type` —— 这个模块**能配什么**（键、类型、
   默认值、可选值、条件显示、数组字段的 itemSchema），以及每一档类型该写
   什么形状的值（`field_types` 图例）。
2. `dashboard.read_config` —— 这个画布节点**此刻配成什么样**。
   ⚠ 不读就写，等于把用户已经调好的那几格一起冲掉。
3. `dashboard.set_config` 改单个键，或 `dashboard.add_config_item` /
   `dashboard.remove_config_item` 增删数组字段里的一项。
4. 把改了什么用一句话说给用户听。

`dashboard.set_config` 的 `path` 是**路径数组**：

| 要改的东西 | path |
| --- | --- |
| 顶层字段 | `["title"]` |
| 数组里第 2 项的某一格 | `["items", 1, "unit"]` |
| 卡片外观 | `["__cardStyle", "borderStyle"]` |

⚠ 往数组字段里**加一项**不要用 `set_config` 整份重写——用
`dashboard.add_config_item`，它按 itemSchema 填好默认值再盖上你给的那几格。
整份重写会把没提到的字段全变成 `undefined`。

## 数据模块：一项配置 = 一行数据

多数数据模块（实时数值卡、表格、图表）是「一块 N 个指标」：
**配置里的第 i 项与数据槽的第 i 行一一对应**。

给「实时数值」再加一个指标并让它显示一个固定值，完整的一趟是：

1. `dashboard.read_config` 看现在有几项（比如 2 项）。
2. `dashboard.add_config_item`，`field` 给 `items`，
   `values` 给 `{"label":"额定功率","unit":"MW","kind":"number"}`
   → 回一个 `index: 2`。
3. `dashboard.write_binding`，`field_key` 给 `itemValues[2].value`，
   `source_kind` 给 `static`，`value` 给 `12.5`。

要接现场实时数据就把第 3 步换成 `source_kind: "opcua"` 加 `node_key`
（点位怎么找见 `dashboard-binding` 技能）。

⚠ **加了配置项不绑数据槽，那一格显示的是「没配来源」**，而不是空白——
用户会以为模块坏了。加完就用 `user.ask` 问这一项的值从哪来。

⚠ **删中间一项**会让它之后每一行的绑定都改喂前一项。删完必须重读绑定核对，
并把这件事说给用户听。

## 坐标与几何

- 设计坐标系，单位像素，原点在左上角。默认画布 1920×1080。
- 几何必须是**整数**。带小数的当场被拒——后端保存时只会回一句字段校验错，
  看不出坐标是你算出来的。
- 加模块时不给坐标就落到默认位置；要放在某处就一起给 `x`/`y`。
- 容器类模块可以装子节点，`parent_id` 指向它。

### 钉位模块：页头与页脚

清单里带 `region` 的那两个（`header` / `footer`）不按上面那套走：

- **每屏最多一个**，且只能落顶层。加第二个会被拒。
- **横向恒铺满**，`x` 与 `w` 给了不作数。
- **只有高度改得动**：页头钉住上沿、页脚钉住下沿，`y` 由钉边与高算出来。
  想让页头高一点就只给 `h`，不要自己算 `y`。
- `dashboard.arrange` 一律不动它们。
- 回执报的是**落库后**的几何，与你给的入参可能不同——以回执为准。

⚠ **页头页脚都没有「标题」这一格配置**。大屏标题是往页头里拖一个**文字块**
子节点：`dashboard.add_module` 给 `module_type: "text-block"`、`parent_id` 指向
页头节点，再用 `dashboard.set_config` 改它的 `text`。往页头写 `title` 存得下去、
也不报错，就是永远不上屏。

## 外观（用户说「边框」「圆角」「背景」时）

模块外观**不在配置字段里**，在节点的卡片外观那一段，用 `dashboard.set_config`
写 `__cardStyle` 下面的键。

- 拿不准键名就调 `dashboard.chrome_keys`，它给全部可用键与各自的合法取值。
  ⚠ 凭印象写的外观键存得下去、也不报错，就是看不见。
- 「去掉边框」= `borderStyle` 设成 `none`
- ⚠ 外观键的语义是「**键不存在 = 没设置**」，与配置字段的默认值相反。
  要恢复成缺省就把值设成 `null`**删掉那个键**，不要写一个「默认值」进去。

清单里的 `chrome` 说的是这一格套不套平台的卡片框：

- `card` = 套。背景、边框、圆角、四角这一整套外观键都吃。
- `bare` = 模块自绘外壳，**只吃描边那几个键**（`borderStyle` 与四角）；
  背景、内边距一类写了不生效。

另有个别模块整个退出统一外观、或画不出其中某几个键。这两件事清单里没有，
**由编辑器当场拒收**——它手上那份清单才知道。被拒了就照实转告用户，
不要换个键名再试。

### 要改观感，先看样式库

`styles.list` 列的是**用户自己存下来的整套观感**，全站共享。用户说「换个样子」
「好看点」「跟那张屏一样」时，**先调它再动手**：

1. 有对得上的 → `styles.get` 拿完整取值，再 `dashboard.apply_style` 一次套上：
   `chrome` 与 `config` 原样传过去，一次调用、用户一步撤销。
   ⚠ **别用 `set_config` 逐键去凑**：一套外壳 40 个键就是 40 次调用，凑到一半
   被打断，画面停在半套样式上，而用户看到的是「越改越乱」。
   ⚠ 外壳是**整袋替换**：这套样式没写的外壳键会被清掉、回落平台默认。这正是
   要的——逐键合并会把上一套的残留留在屏上（「换了样式但没换干净」）。
   `set_config` 仍然管用，但它管的是套完之后微调某一项。
2. 库里没有合适的 → 用 `modules.catalog` 的 `preset` 起个底，改到用户满意，
   再 `styles.save` 存一条供下次用。存之前先在 `styles.list` 里看有没有该改的
   那一条（带 `style_id` 就是改），别每调一次观感就存一条新的。
3. ⚠ `styles.save` 存的是**观感**：标题、行/项列表、缺值占位、阈值规则一个都
   不写进去。它们跟着数据走，不跟着样子走——混进样式里，别人套用时他配好的格
   与阈值会被整片抹掉，而两侧都不报错。

⚠ `module_type` 为空的是**通用外壳样式**，套到任何模块上都只写外壳；非空的连
内芯一起，**只能套回同类型的节点**——内芯键是逐模块的，`info-card` 的键写到
`gauge-card` 上既不报错也不生效。

⚠ 样式库是全站资产，改与删要 `dashboard:manage`。用户只有 `dashboard:edit` 时
`styles.save` / `styles.delete` 会被上游拒，如实转告，不要换个写法再试。

## 排版

`dashboard.arrange` 做对齐与分布，一次一个动作，`action` 取这几个之一：

| action | 意思 |
| --- | --- |
| `left` / `right` / `hcenter` | 左对齐 / 右对齐 / 水平居中 |
| `top` / `bottom` / `vcenter` | 顶对齐 / 底对齐 / 垂直居中 |
| `distribute-x` / `distribute-y` | 横向等距 / 纵向等距 |
| `tidy` | 整理顶层：消重叠、钳回边界 |

⚠ 对齐至少 2 个、分布至少 3 个，且**必须同一个父层**（跨层坐标系不同，
硬算出来的是错位）。不够就直说做不了，不要凑数。

## 动手的边界

- 每一步都立刻显示在用户的画布上，用户能 Ctrl+Z 撤单步。
- **删除节点会连子树一起删**。删之前先说清要删什么、有几个子节点。
- 不要替用户保存。
- 一次只做用户要的那件事。用户说「加一个数值卡」，就加一个，
  不要顺手把整屏重新排版一遍。

## 多步任务与截图验收

- 要动 3 个以上对象（摆一片模块、整屏排版、批量改外观）时，先用
  `plan.write` 把步骤列出来再动手，每完成一项立刻更新状态。
- 布局与外观是**看效果**的活：计划的收尾项固定是「截图自检」——用
  `dashboard.capture` 看一眼成品，位置错了、挤在一起、颜色不对就把修正项
  补进计划接着改。没看过图不许把收尾项勾掉。
- 看图时把结论**当场写成文字**（哪几块要动、动成什么样）：图只在这一轮
  看得见，下一轮只剩一句占位。
