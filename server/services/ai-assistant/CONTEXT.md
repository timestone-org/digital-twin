# AI 助手 — 上下文

## 1. 通用语言

| 词 | 指什么 | 不指什么 |
|---|---|---|
| **会话** session | 一次对话，属于一个用户，钉在一个工作面上 | 不是浏览器标签页，也不是登录会话 |
| **回合** turn | 用户一次输入 → 助手给出最终答复之间的全部动作 | 不是一次模型调用 |
| **步骤** step | 回合内的一次模型调用或一次工具执行 | 不是一个 token |
| **工作面** surface | 助手当前所处的页面及其可读上下文 | 不是路由：一个路由可以有多个工作面 |
| **技能** skill | 一组指令 + 一组工具 + 适用的工作面 | 不是一个模型，也不是一个提示词模板 |
| **服务端工具** | 在本进程里执行的工具 | —— |
| **客户端工具** | 下发到浏览器、由编辑器执行的工具 | —— |

⚠ **「节点」在本仓指三样东西**：画布节点 / 采集点位 / OPC UA 地址空间节点。
本服务的提示词与响应里一律用全称，不许简称成「节点」。

## 2. 边界

本服务是**纯消费方**（ARCHITECTURE §3.7）：

- 只写自己的 `assistant` schema（会话、消息、步骤三张表）。
- 业务数据一律经 platform 的 HTTP 面拿，**不读别人的库**。
- 代表用户调 platform 时**原样转发边缘注入的签名身份头**，由 platform 自己判权限。
  助手绝不用服务级密钥去替用户读它本来读不到的数据。
- 不被任何服务回调（禁双向同步 RPC，ARCHITECTURE §6）。

## 3. 不变式

1. **改画布的工具在浏览器里执行，不在这里执行。** 编辑器持有本地草稿，
   后端碰不到它；后端直接改库的话用户屏幕上什么都不会变，保存时还会撞 409。
2. **待续状态落库，不留内存。** api 角色无状态且 HPA，续跑可能落到另一个副本。
   状态在 `chat_steps.state = 'awaiting_client'` 上。
3. **模型端点不进就绪探针。** 它是外部依赖，抖一下不该让整组副本被摘掉；
   助手在模型不可达时仍要能列历史会话。可用与否由 `/capabilities` 如实回答。
4. **模型不可用时 fail-open**：返回明确的不可用提示，不是 5xx，也不是静默降级
   （runtime-resilience §9 的降级表已经点名这一条）。
5. **开关开着却没配密钥 → 启动即失败。** 不打 WARN 继续，也不留到第一次对话
   才发现——那时服务已经接了流量。
6. **指令正文读不到就抛。** 空指令的技能仍会被模型选中，然后不带任何约束地
   乱做一气，比「这个技能不存在」难查得多。

## 4. 技能

一个技能 = 一个目录：`apps/chat/skills/<name>/`，含 `manifest.py`（清单）与
`skill.md`（指令正文）。

**渐进披露**：提示词里常驻的只有每个技能的名字与一句话简介；正文只在这个技能
被选中之后才注入。工作面一换，可用技能集跟着变，不适用的技能连名字都不出现。

注册是**显式的一步**——`skills/__init__.py` 里的 `SKILLS` 元组。不靠 import
副作用，因为那会让「装了哪些技能」取决于 import 顺序，而顺序在测试里与生产里
可以不同。

## 5. 一期不做

- 向量检索与知识库（架构里规划的「知识块」表**不建**：空着的表比不存在的表
  更容易被误用）。
- 助手自己保存大屏。
- 公开大屏上的助手（ADR-0014，那是全站唯一的匿名面）。
- 自主长任务：一期每个回合都由用户起头。
