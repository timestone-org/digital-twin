# AI 助手 — 上下文

## 1. 通用语言

| 词 | 指什么 | 不指什么 |
|---|---|---|
| **会话** session | 一次对话，属于一个用户，钉在一个工作面上 | 不是浏览器标签页，也不是登录会话 |
| **回合** turn | 用户一次输入 → 助手给出最终答复之间的全部动作 | 不是一次模型调用 |
| **步骤** step | 回合内的一次模型调用或一次工具执行 | 不是一个 token |
| **工作面** surface | 助手当前所处的页面及其可读上下文 | 不是路由：一个路由可以有多个工作面 |
| **技能** skill | 一组指令 + 一组工具 + 适用的工作面 | 不是一个模型，也不是一个提示词模板 |
| **服务端工具** | 在本进程里执行的工具 | —— |
| **客户端工具** | 下发到浏览器、由编辑器执行的工具 | —— |

⚠ **「节点」在本仓指三样东西**：画布节点 / 采集点位 / OPC UA 地址空间节点。
本服务的提示词与响应里一律用全称，不许简称成「节点」。

## 2. 边界

本服务是**纯消费方**（ARCHITECTURE §3.7）：

- 只写自己的 `assistant` schema（会话、消息、步骤、知识块四张表）。
- 业务数据一律经 platform 的 HTTP 面拿，**不读别人的库**。
- 代表用户调 platform 时**原样转发边缘注入的签名身份头**，由 platform 自己判权限。
  助手绝不用服务级密钥去替用户读它本来读不到的数据。
- 不被任何服务回调（禁双向同步 RPC，ARCHITECTURE §6）。
- **档位就是目录里的一路供应商**（ADR-0041）：目录由 platform 持有，经内部面拉、
  按 TTL 缓存；开着的每一路各装一个适配器，装配口子按**接入形态**查一张显式的表
  （`llm/adapters`）。认不出的形态如实缺席，不猜着接。
- `ASSISTANT_MODEL_*` 是端点那一形态的永久默认值：目录里有了同一形态的供应商就
  让位，一路都没有时才轮到它。订阅账号那一形态**没有环境变量档**——登录态挂在目录里
  那一路供应商的行上，目录之外的那一路无处存登录态。用途码与形态码在 `llm/ports.py`
  复述，与平台、`llmcore` 逐字一致由前端契约用例守。
- 要登录的那几路（订阅账号）的凭据**归 platform 持有**（ADR-0041）：本服务经内部面
  `POST /internal/v1/platform/llm-credentials/{id}:token` 领一份短时令牌，**只领不刷**
  ——刷新是写操作，属主只有平台一个。本地 `model_credentials` 表这一期只留声明、
  没有任何读写路径，删表在下一次发布。

## 3. 不变式

1. **改画布的工具在浏览器里执行，不在这里执行。** 编辑器持有本地草稿，
   后端碰不到它；后端直接改库的话用户屏幕上什么都不会变，保存时还会撞 409。
2. **待续状态落库，不留内存。** api 角色无状态且 HPA，续跑可能落到另一个副本。
   状态在 `chat_steps.state = 'awaiting_client'` 上。
3. **模型端点不进就绪探针。** 它是外部依赖，抖一下不该让整组副本被摘掉；
   助手在模型不可达时仍要能列历史会话。可用与否由 `/capabilities` 如实回答。
4. **模型不可用时 fail-open**：返回明确的不可用提示，不是 5xx，也不是静默降级
   （runtime-resilience §9 的降级表已经点名这一条）。
5. **开关开着却没配密钥 → 启动即失败。** 不打 WARN 继续，也不留到第一次对话
   才发现——那时服务已经接了流量。
6. **指令正文读不到就抛。** 空指令的技能仍会被模型选中，然后不带任何约束地
   乱做一气，比「这个技能不存在」难查得多。
7. **每轮会变的东西只许待在对话末尾**（ADR-0023）。常驻提示词与工具声明排在整个
   请求最前面，是端点前缀缓存唯一能命中的那一段，且**跨会话共享**。往里塞一格易变
   的东西——快照、计划、当前时间、用户名——等于把它后面十几 k 字符连同整段历史
   一起作废，而从外面完全看不出来：只有账单和延迟会慢慢变难看。

## 4. 技能

一个技能 = 一个目录：`apps/chat/skills/<name>/`，含 `manifest.py`（清单）与
`skill.md`（指令正文）。

**渐进披露**：提示词里常驻的只有每个技能的名字与一句话简介；正文只在这个技能
被选中之后才注入。工作面一换，可用技能集跟着变，不适用的技能连名字都不出现。

注册是**显式的一步**——`skills/__init__.py` 里的 `SKILLS` 元组。不靠 import
副作用，因为那会让「装了哪些技能」取决于 import 顺序，而顺序在测试里与生产里
可以不同。

## 5. 一期不做

- 助手通常不保存大屏；实时绑定是唯一例外。它可在先告知用户“会保存整份草稿”后
  调用浏览器侧 `dashboard.save`，因为 publisher 只读取已落库绑定（ADR-0023）。
- 公开大屏上的助手（ADR-0014，那是全站唯一的匿名面）。
- 自主长任务：一期每个回合都由用户起头。

⚠ 「向量检索与知识库」曾在这一节里，理由是「空着的表比不存在的表更容易被误用」。
[ADR-0030](../../../docs/adr/0030-助手建长期记忆的知识块表.md) 推翻了它——写入
来源被钉成两个显式工具（`memory.remember` / `memory.search`），表因此一定不空，
当初那条理由随之消失。检索不依赖 pgvector：向量存 `bytea`，余弦在应用层算。

### 客户端实际回执（停止回合仍记录）

`POST /sessions/{id}:receipts` 复用 `assistant:use` 与会话归属，只接收已有客户端调用的实际结果，按 `call_id` 原子结算，绝不推进模型或执行工具。同值重试幂等；未知、重复或冲突回执整批拒绝。待办每个调用单独 `ChatStep`，入参信封 `{call_id,arguments}`，结果有界且图片只存占位；未返回项保持 `awaiting_client`。旧版 `{calls:[...]}` 批次兼容拆分，不做迁移或生产回填。普通 advance 在模型调用前记录回执，新前端则先经独立接口保存，取消每次 dispatch 守卫继续有效。回执保存失败如实提示且不重试已执行操作；历史不能被当作设备执行审计凭据，客户端回执表达的是浏览器报告的实际结果。

数据库消息保留真实追加顺序；模型输入将回执放在所属助手调用后，未收回执补执行状态未知的临时占位，绝不据此结算步骤或重试动作。窗口外调用的孤立回执不进入模型；截图仍只随当前推进输入。步骤结果只存有界摘要与完整结果、错误的规范 JSON SHA-256 指纹，JSON 键顺序不影响幂等。旧版已结算步骤没有指纹时明确拒绝重填，提示查看历史且不要重新执行；不以摘要或图片占位假称相同。

### MCP 写操作授权与确认

管理员共享模型配置不授予业务权限。MCP 写工具必须同时属于部署白名单及明确的
`ASSISTANT_MCP_WRITE_POLICIES` 业务政策；请求中的权限来自已验证用户，不能从模型
或载荷声明。政策只支持大屏、台账、报告的查看与写权限对，并使用该用户身份从平台
核验 UUID 目标。没有对应资源校验器的设备或未知动作拒绝，不猜测权限映射。

新客户端声明 `mcp.confirm_write` 协议后，写调用作为独占待续调用落库，浏览器只做
可信确认，实际执行仍在服务端。准备接口从已存调用读取工具及参数，返回目标、参数、
影响和短期票据；决定接口只接票据及用户决定。票据散列存于本服务步骤，绑定实际
用户、会话、调用、工具、规范参数和政策。服务端执行前重新签发并校验用户身份、
业务权及目标，短事务原子领取后才做外部 IO。票据取消、过期、篡改、重放和并发
重复不得执行。MCP 服务端实际回执落库，浏览器不能把待确认调用伪造为成功。
已领取调用及结果未知的写操作不能自动重发，读取工具沿用原执行路径。

确认记录及会话回执不是业务审计。部署方启用涉及 observability §7 操作的 MCP 写
适配器前，必须验证实际业务服务使用真实操作者记录时间、类型、对象、前后值、
来源 IP 和 trace_id，在业务事务内持久化、不可篡改且独立保留；没有验证不得启用。
本协议的资源权限检查不替代下游业务约束或业务审计，也不使会话历史成为设备审计。
还必须验证可信操作者及链路上下文如何传到适配器；共享 MCP Bearer 及模型参数里的
操作者字段均不代表真实用户身份。本期未启用或验证实际业务写适配器。
