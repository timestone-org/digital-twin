# GYZky 空调 view 接入

`create_views.sql` 根据《空调开机字段说明.xls》为 K01–K17、K20、K21、K22、K25
共 21 台空调创建 `dbo.KTStartData_<序号>`。在 SQL Server 的 SSMS 中打开并整体执行。
目标数据库为附件给出的 `EMS5.2.2`，源表假定为 `dbo.GYZky`；实际 schema 不同时需修改脚本。
这是外部 EMS 库的独立建视图脚本，不是项目 PostgreSQL 迁移。脚本不包含连接凭据。

每个 view 输出 `CT` 和 `apps/hvac/datasets.py` 定义的全部 19 个指标，测点转换成
`float`，原始 NULL 保持 NULL，不过滤停机记录、不聚合、不补零。源表的数据不会被复制。
项目接入约定见 `docs/AC_DATA_DESIGN.md`、ADR-0009 和 ADR-0010。

## 执行前确认

- 附件没有给出时间列。脚本假定为非空 `Ct`，支持 datetime/smalldatetime/datetime2，
  不符时直接报错。请用现场表结构确认名称、当地时间口径及分钟采样周期。
- `CT` 必须唯一；重复时间会导致项目游标漏行。应确认源表在 Ct 上存在单列唯一索引，
  并检查近期相邻记录间隔是否为 60 秒。无索引时需由现场 DBA 评估查询性能与索引方案。
- 附件压力没有注明单位。`F2` 暂按项目要求的 kPa 原值映射，必须现场确认；
  若为 MPa，应将 `chilled_water_supply_pressure` 的表达式乘以 1000。
- 脚本先检查所有所需字段的存在性和数值类型。发现任一同名对象即停止，
  不覆盖旧视图。成功创建后的再次执行也会停止；修改已有定义需另行评审后使用 ALTER VIEW。
- 21 个 view 在同一事务内创建，失败整体回滚；锁等待上限 5 秒。
  使用具备建视图权限的现场部署账号执行，项目连接账号仅授予读取所需对象的权限。

## 字段差异

附件不是旧文档中的 KTkgj 布局，不能使用每台连续 19 列的旧偏移公式。
K01 从 F5 开始，K21/K22 各只有 11 个本机测点，其余各 13 个。

停用的新风测点按附件备注引用启用测点，例如 K01 的 F9/F10 改读 F35/F36，
K21 的 F243/F244 改读 F230/F231；所有变比均为 1。
全部空调共享 F1 冷冻水供水温度、F2 冷冻水供水压力。

以下列用 `CAST(NULL AS float)` 补齐：

- 全部空调的 `heat_steam_temp`、`humidify_steam_temp`：附件未提供。
- 全部空调的 `heat_steam_pressure`、`humidify_steam_pressure`：附件 F3 是高压分气缸压力，
  F4 是空调分气缸压力，无法据此认定加热/加湿归属，因此不猜测映射。
- K21、K22 的 `mixed_air_temp`、`mixed_air_humidity`：附件未提供。

当前开机判定依赖风机频率、车间温度和湿度；当前模型特征不消费上述蒸汽列或混风列。
补齐列名只保证契约形状，模型效果仍需通过真实历史事件、达标范围与训练结果验证。

## 项目中使用

1. 将平台空调外库连接指向 `EMS5.2.2`，源时区按现场设置（中国当地时间为 Asia/Shanghai）。
2. 在空调台账建立对应序号并配置真实所属房间；不要根据编号推断房间。
3. 在每台空调的“数据与达标”中，把 `raw_minute` 绑定到 `KTStartData_K01` 等对象名，
   只填对象名，不带 `dbo.`；设置车间温湿度达标范围。
4. 检查原始数据页：温湿度、设定值、风机频率与现场同一时刻一致，再生成开机事件并训练。

平台可绑定对象下拉框还会查询 `KTInfo(device_id, Caption)`。
附件没有说明该表是否存在，需现场确认项目账号能读取它；缺失时下拉框可能报错。
本脚本不虚构设备名称或新建 KTInfo。运行账号应以 dbo 为默认 schema，且没有遮蔽这些
对象的同名对象，因为项目读数 SQL 使用不带 schema 的对象名。

脚本末尾会返回 21 个 view 的列数（应全部为 20），并展示 K01 最新 10 条关键读数。
当前仅完成本地字段和 SELECT 投影验证，尚未连接现场 SQL Server 执行。
